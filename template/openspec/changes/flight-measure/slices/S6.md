# S6 · versions.ts：插件副本核对与判定器事件表核对（纯函数）

## 做什么（新文件 `template/plugins/flight/hooks/versions.ts`，经 `Io` 读文件与跑命令，不碰 `$`）

```ts
import type { Io } from './core'
export type VersionCheck = { ok: true; line: string } | { ok: false; reason: string }
export async function checkPluginCopy(io: Io, x: { pluginRoot: string; configDir: string; mainTree: string }): Promise<VersionCheck>
export async function checkJudges(io: Io, x: { hooksDir: string; required: readonly string[] }): Promise<VersionCheck>
```

### `checkPluginCopy`
1. **加载版本**：`io.read(`${pluginRoot}/.claude-plugin/plugin.json`)`，取 JSON 的 `version`。读不到或解析失败时为 `未知`。
2. **已安装记录**：`io.read(`${configDir}/plugins/installed_plugins.json`)`。结构为 `{ "version": 2, "plugins": { "<name>@<marketplace>": [ { "scope", "projectPath"?, "installPath", "version", ... } ] } }`，这是本机实测的格式（2.1.295），没有文档。
   - **选条目**：在键以 `flight@` 开头的全部条目里，先选 `scope === 'project'` 且 `projectPath` 规范化后等于 `mainTree` 的；没有就选 `scope === 'user'` 的。
3. **路径比较**：一律先规范化（去掉末尾 `/`、`.`、`..`），可以复用 `envelope.ts` 的 `normalizePath`。
4. **判定**：
   - `pluginRoot` 与条目的 `installPath` 都在 `${configDir}/plugins/cache/` 之下且两者不同 → `{ ok: false, reason }`，`reason` 为：
     `flight：已安装 flight <条目 version>（<installPath>），本会话加载的是 <加载版本>（<pluginRoot>）：先运行 /reload-plugins 再起飞`
   - 两者相同 → `{ ok: true, line: '插件 <加载版本>' }`。
   - 其余情形一律 `{ ok: true, line: '插件 <加载版本>（已安装版本未核对：<原因>）' }`，原因分别为：
     - 文件不存在：`无 installed_plugins.json`
     - JSON 损坏：`installed_plugins.json 无法解析`
     - 找不到条目：`没有 flight 的安装记录`
     - 加载目录不在缓存下：`本会话加载的不是安装副本（<pluginRoot>）`
     - 条目的 `installPath` 不在缓存下：`安装记录不在缓存下`

### `checkJudges`
- 运行 `io.run(['python3', `${hooksDir}/ledger.py`, 'events'])`。
- 退出码非 0 → `{ ok: false, reason: 'flight：判定器过旧（<hooksDir>/ledger.py 没有 events 子命令）：先把主检出更新到与插件同一版本' }`。
- 输出按行得到集合；`required` 中有不在集合里的 → `{ ok: false, reason: 'flight：判定器（<hooksDir>）不认识事件 <逗号分隔>：先把主检出更新到与插件同一版本' }`。
- 都在 → `{ ok: true, line: '' }`。
