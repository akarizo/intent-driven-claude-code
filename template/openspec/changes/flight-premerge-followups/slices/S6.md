# S6 · 测试卫生：插件 TS 测试零失败纳入全量 pytest，修掉 orchestrator.test.tsx 收尾的未处理拒绝

## 先读
- `tests/test_flight_plugin.py`：`plugin_run()`（lru_cache，跑一次 validate 与 test）、`assert_ts_passed`。
- `claude plugin test` 的输出格式：每个文件一行 `tests/<file>:`，用例行 `(pass) <名字> [<耗时>]` / `(fail) <名字> [<耗时>]`，文件级失败为 `(fail) the file ran to its end [0.00ms]`，其后缩进行是原因（如 `a rejection nothing handled: no implementation for turn.step`），末尾 ` N pass` / ` N fail`。
- 规划时的定位结果（design Context）：main `ff19ecd` 上该失败只在 `orchestrator.test.tsx`；二分到文件末尾 33 个用例（自 `ticker-not-duplicated` 起）后，拆成两半单独跑都不复现——取决于用例组合。推测是某用例留下的后台任务（定时器、drive、唤醒）在它的测试世界拆掉后才请求 `turn.step`，未核实。
- `template/plugins/flight/hooks/orchestrator.tsx` 的 `on('turn.step', { agentId: /./ }, …)`（第 1538 行附近）与测试世界的 `turn.step` 应答。
- 设计：design D7。
