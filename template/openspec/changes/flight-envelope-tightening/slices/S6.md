# S6 · agent 定义、命令、skill 与新 ADR 写明收紧后的包络

## 做什么
1. **agent 定义**：`template/plugins/flight/agents/executor.md`、`fixer.md` 的正文各加一条（措辞一致）：
   > git 一律作用于你自己的 worktree（派发提示词首行给出；插件会把你的 Bash 固定在那里运行）。禁止 heredoc（`<<`）和读标准输入的解释器（`python3 -`、`bash -s`、`/dev/stdin`）：要写文件就用 Write 工具，要跑脚本就先写成脚本文件再运行。

   `reviewer.md` 只加后半句（禁止 heredoc 与读标准输入的解释器）。
2. **命令与 skill**：`template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md` 的「执行引擎（先读）」里，「飞行中的权限」那一条各更新为同一措辞（插件 0.3.1 起），在现有内容上补充：
   - 飞行 agent 的 Bash 由插件固定在它自己的 worktree 里运行；改动类 git 只能作用于自己的 worktree；
   - 读取（Read / Grep / Glob）只在主仓库内免询问；
   - heredoc 与读标准输入的解释器一律被拒。
3. **新 ADR** `template/openspec/adr/DRAFT-flight-envelope-tightening.md`，格式参照同目录的 `DRAFT-flight-capability-envelope.md`：
   - 头部：
     - `- Status: accepted, supersedes DRAFT-flight-capability-envelope`
     - `- Date: 2026-10-10`
     - `- Supersedes: DRAFT-flight-capability-envelope`
     - `- 关联：DRAFT-flight-orchestrator-state-machine`
   - **Context**：写 spawn 的 cwd 未生效的实测证据，以及 #41 评审的安全缺口。
   - **Decision**：全文重述包络，即旧 ADR 的 6 条加上本 change design 的 D1–D6，并标出哪些是修订。
   - **否决的方案**：至少写「只靠提示词要求 git -C」「要求每条改动类 git 必须带 -C」。
   - **旧 ADR 原文一个字都不改。**
4. **测试**：`tests/test_opsx_apply_engine.py` 去掉末尾骨架的 xfail，按 scenario 断言。它要读三份 agent 定义，路径为 `template/plugins/flight/agents/*.md`，取 frontmatter 之后的正文。
