# S5 · 批准带：进行中显示、基线进度、按键起飞提交工件、去重提示

依赖 S2：类型 `FlightItem.busy`，以及从 `./orchestrator` 导出的 `scenarioFiles`。与 S4 并行；本片不改 `orchestrator.tsx`。接口见 `slices/_interfaces.md`。

## 先读
- **按键处理**在 `register.tsx` 的 `ui.press`，以及 `startTakeoff` / `startResume`（约第 330–400 行）；续飞依赖在 `depsOf`；渲染在 `ui.render { component: 'AbovePrompt' }`。
- **`$` 不出文件**：只 import `takeoffNow` 与 `scenarioFiles`，不把 `$` 传给别的文件。
- **`Button` 没有禁用属性**：进行中时不渲染按钮，只渲染 `<Text>`。
- **测试与插件是隔离实例**：进行中表、计时只能经按键与重绘的效果观察。

## 省轮次（包络与工具的已知限制）
- 改文件一律用 Edit / Write，路径写字面绝对路径；不要用 `sed -i`、`python3 -c` 改文件，不要用 heredoc，不要把输出重定向到 worktree 之外。
- 命令里带 `$` 或反引号时，包络可能判为「无法判定」；查找用 `grep -n -e … <字面路径>`。没有 Grep 工具，用 Bash 的 grep。
- `claude plugin test template/plugins/flight` 跑全量约 4 秒，接 `2>&1 | grep -E "^\(fail\)| pass| fail"` 过滤。

## 测试世界的已知事实
- **`flight.test.tsx` 的世界**：
  - 已记录 `fills`、`notes`、`baselines`、`gates`、`git` 调用；
  - 让判定器「卡住」：给 python3 的应答返回一个之后才 resolve 的 promise。

- **重绘**：`ui.mount` 之后重新 `find` 即可看到最新的批准带。

## 做什么（design D6、D7）

### `template/plugins/flight/hooks/register.tsx`
1. **进行中表**：模块级 `Map<string, { phase: 'takeoff' | 'baseline'; since: number }>`。
   - `startTakeoff`：按下时登记 `takeoff`，`takeoffNow` 返回后（含异常）删除；
   - `startResume`：登记 `baseline`，基线结束、进入起飞时改为 `takeoff`，返回后删除。基线阶段可以在 `depsOf.baseline` 前后改相位，或由 `resumeFlight` 的回调改，取最少改动的写法。
   - 每次改动后调 `refresh($)`。
2. **显示**：`refresh` / `evaluate` 给有进行中记录的项填 `busy`：
   - `takeoff` → 「起飞中…」；
   - `baseline` → 「基线运行中（已 N 分钟）」。

   渲染时 `busy` 非空就只显示 `<Text>{busy}</Text>`，不渲染 Button。进行中的项即使按规则本该「不显示」，也要显示。
3. **基线进度**：进入 `baseline` 相位时：
   - 立即写状态行，并用 `$.clock.after(60000, tick)` 续表，每次更新状态行与批准带，相位离开 `baseline` 就不再续；
   - 状态行为「flight · 续飞准备中 <change> · 基线已跑 N 分钟（上次全量约 M 分钟）」，M 由该 change 的 `slices.json` 的 `gate.full_suite_sec` 换算成分钟（四舍五入，至少 1）。
4. **去重提示**（spec `band-dedupe-toast-says-takeoff`）：toast 改为「flight：<change> 已批准（指纹相同），直接起飞」。
5. **`scenarioFiles` 去重**：删掉本文件的 `scenarioFilesOf`，改为 import `./orchestrator` 的 `scenarioFiles`，调用处的参数按它的签名调整。
6. **按键起飞带「授权提交」**：现行实现应已如此，只需加强现有用例的断言（见测量协议第 5 条）。
