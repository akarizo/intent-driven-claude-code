# S1 · install.sh 对 openspec/ 只下发种子，并列出疑似旧版误拷的开发工件

**目标**：`install.sh` 对目标项目的 `openspec/` 只按清单下发种子，不再拷本仓自己的 change 与 DRAFT ADR。安装或升级结束时，列出目标里与本仓开发工件同名的条目，提示用户手动清理；安装器不代删。spec 见 `install-openspec-seeds` 的两条要求。

## 事实基线（main `7fd26b0`）

- `install.sh:214-241` `copy_tree src dst overwrite preserve`：逐项复制，日志 `[add]` / `[update]` / `[skip]`，计数 `ADD_COUNT` / `UPD_COUNT` / `SKIP_COUNT`。`.claude/` 也走它，**不要改这个函数**。
- `install.sh:466` 复制 `.claude/`；`:467-468` 注释与 `copy_tree "$TEMPLATE_SRC/openspec" "$TARGET/openspec" 0`（整目录只增不改，**本片要替换的就是这两行**）。
- `install.sh:469-477` 往 `openspec/.gitignore` 追加 `changes/*/.flight`，前提是 `.gitignore` 已经下发，所以种子复制必须在它之前。
- `install.sh:478-482` 升级模式 `copy_tree "$TEMPLATE_SRC/openspec/schemas" "$TARGET/openspec/schemas" 1` 与 `migrate_root_adr`，保持不动。
- `install.sh:586-611` 退役文件与迁入插件文件两段提示：先收集到数组，`${#arr[@]} -gt 0` 时打印 `echo` 空行 + `log_info` 标题 + 每条 `log_info "  $rel"`。新提示段照抄这个写法，放在文件末尾这两段之后。
- `template/openspec/` 种子：`.gitignore`、`config.yaml`、`changes/.gitkeep`、`adr/.gitkeep`、`superpower/.gitkeep`、`schemas/intent-driven/**`。其余（`changes/<name>/`、`adr/DRAFT-*.md`）都是本仓开发工件。

## 取舍（design 跳过，记在这里）

- **按清单下发而不是排除 changes/ 与 adr/**：本仓以后可能在 `template/openspec/` 下长出新的开发目录，例如归档产生的 `specs/`、`changes/archive/`，或者 `superpower/` 里的设计稿。排除法会让它们再次漏进用户项目；清单法只有显式加进清单才会下发。代价是以后新增种子要记得改清单，漏了的后果只是少一个空目录占位。
- **提示按名字匹配，不比内容**：本仓的 change 工件在 v2.0 之后还在改，按内容比对会漏。已核实 `stable-v2.0` 带进去的 17 个条目在 main 的模板里都还有同名项，按名字匹配能全部覆盖。代价是用户自己的 change 若恰好同名会被误列，但这里只是提示，不会删除。

## 坑

- ⚠ macOS 自带 bash 3.2：`set -u` 下展开空数组会报 unbound variable。照抄 `:586-611` 的写法，`${#arr[@]} -gt 0` 判断之后才展开 `"${arr[@]}"`。
- ⚠ `set -e`：判断写成 `if [[ -e … ]]; then …; fi`，不要用 `[[ … ]] && …`。
- ⚠ glob 没有匹配时会保留字面 `*`。不要改全局 `shopt`，靠 `-e` 判断自然跳过即可。
- ⚠ `copy_tree` 函数本身和 `.claude/` 的复制一行都不要改；`:469-482` 也不要改。
- ⚠ 测试名与 scenario 的对应以 `slices.json.scenario_tests` 为准，不要改骨架的断言，解锁时只删 `@pytest.mark.xfail(strict=True, reason="骨架")` 那一行。
- ⚠ `test_upgrade_keeps_user_seed_edits` 是护栏，没有 xfail，base 上已经通过，改完必须仍然通过。
- ⚠ 既有 `tests/test_install.py` 的其他测试（`.gitignore` 追加、settings 合并、插件安装、pipe 模式、退役提示）必须继续通过。
