## 做什么

### 1. `core.ts`
- `ev.measure(b, { attempt, slice, agent, base, commit, outcomes, changed, source })`。
- `ev.dispatch` 的入参增加可选 `base?: string`，写入事件。
- `agentOf` 的返回值增加 `base?: string`，取该 dispatch 事件的 `base`。

### 2. 新文件 `measure.ts`（与 `landing.tsx` 的 `FINDINGS_TOOL` / `onFindings` 同一模式，不碰 `$`）
- **工具定义**：`MEASURE_TOOL = { name: 'measure', description: '…', inputSchema: { type: 'object', properties: {} } }`。描述写明：
  - 只有本次飞行的执行体可用；
  - 由控制面运行本片 scenario 测试并记账；
  - 先在改生产代码前调用一次看它红。
- **`onMeasure(ctx, found, agentId)`**：
  - **校验调用者**：调用者须是当前 attempt、role 为 executor 的 agent，否则返回 `{ deny: '只有本次飞行的执行体可以请求测量' }`。
  - **运行测量**：用 `judge(io, f, 'slice-gate', ['measure', S, '--change-dir', f.changeDir, ...(base ? ['--base', base] : [])], worktree, 600000)`。
  - **记账**：解析 JSON 后追加 `ev.measure`，`agent` 为调用者。
  - **结果文本**：
    - 每个目标一行 `- <目标>：<状态>`；
    - 一行结论：有 FAILED / ERROR 的写「本次见红：…」，没有就写「本次未见红」；
    - 见红且 `source` 非空时，加一句「注意：测量时已改动生产代码 <文件>，这次红不能作为先红证据」；
    - 不可测的目标列一行；
    - 末尾附 `tail`。
  - **测量没完成**：退出码非 0、输出不是 JSON、写账本失败 → `{ result: '测量没有完成：<原因>' }`，不记事件。

### 3. `orchestrator.tsx`
- **注册工具**：`session.start` 里 `submit_findings` 旁边再注册 `MEASURE_TOOL`（`isDeferred: false`），同样 try / catch。
- **工具调用**：新增 `on('tool.call', { tool: 'mcp__flight__measure' }, …)`，交给 `onMeasure`，`.catch` 时拒绝。
- **免询问**：`inEnvelope`：`who.role === 'executor' && tool === 'mcp__flight__measure'` → true。
- **起跑**：`perform` 派发执行体时，`slice-gate start` 的参数加 `--evidence ledger`，并从 start 的 stdout JSON 解析 `base`。解析不出 base 时，本片记 blocked（infra）。
- **起点测量**：spawn 之前，读账本，看有没有本片、本 base、`changed` 为空的 measure 事件。
  - 没有 → 先跑一次 measure，以 `agent: 'dispatch'` 记账；
  - 跑不起来或写账本失败 → 本片 blocked（infra），理由 `起点测量失败：<原因>`，不派发。
  - 解冲突 agent 不做起点测量。
- **记 base**：执行体与解冲突 agent 的 dispatch 事件都带 `base`。
- **门禁参数**：`runGate` 一律带 `--evidence ledger`，三条路径都要覆盖：
  - **执行体**（SubagentStop 收口、`gate` 动作补跑）：`--base <该 agent dispatch 的 base>`；
  - **regate**：`--base a.base`；
  - **解冲突 agent**：`--base <它的 dispatch base> --measure-base <本片最后一个执行体 dispatch 的 base>`；
  - dispatch 没有 base（旧账本）时不带 `--base` / `--measure-base`，只带 `--evidence ledger`。
- **起飞核对**：`takeoff` 在 git 版本检查之后、写任何账本事件或 timeline 之前：
  - `checkPluginCopy(io, { pluginRoot: $.plugin.root, configDir, mainTree: main.path })`。`configDir` = `await $.env.get("CLAUDE_CONFIG_DIR")`；没有就是 `${await $.env.get("HOME")}/.claude`，两者都没有时传空串，由 S6 判为未核对。
  - `checkJudges(io, { hooksDir, required: EVENT_TYPES })`。
  - 任一 `ok: false` → 回复其 `reason` 并返回。
  - 成功时，起飞回复改为 `✈ 起飞 <name>：<n> 片 / <k> 个 wave · 主模型 <model> · <checkPluginCopy 的 line> · attempt <a>`。
- **判不出拒写**：`flyingWho` 遇到 `ownership` 返回 `unknown` 且该 change 在 `active` 里 → 返回 `{ unknown: true, error }`。
  - `tool.call`（Write / Edit / NotebookEdit / Bash）→ `{ deny: 'flight：归属判定失败（<error>），稍后重试' }`；
  - `tool.check` → 原样返回引擎判定；
  - `agent.spawn` 守卫 → 按在飞处理。
