## 做什么（`template/.claude/hooks/slice-gate.py`）

### 1. G5 逐目标（design D1）
`g5_ledger_verdict(events, slice_id, base, pairs, guards=())`：`guards` 是本片护栏的 scenario id 集合，对应的目标是护栏目标。

**取测量**：
- `ms`：本片、本 base 的测量；
- `starts`：`ms` 里 `changed == []` 的；
- `clean`：`ms` 里 `source == []` 的。

**判定**：
1. **没有 `starts`** → 失败「缺少本片起点测量」（不变）。
2. **护栏目标**：
   - 在某个 `starts` 里为 PASSED → 警告 `G5 measure: <t> 为护栏（计划已批准），起点测量已通过，免于先红`；
   - 否则 → 失败 `G5 measure: 护栏 <sid> → <t> 在起点测量里未通过（护栏测试须在规划时写好、base 上已通过）`。
3. **非护栏目标**：满足条件是「某个 `clean` 测量里它为 FAILED 或 ERROR」。不满足时失败，按下面顺序取第一条命中的：
   - 某个 `clean` 测量里它为 PASSED → `G5 measure: <sid> → <t> 在改生产代码之前就已通过：若它描述的行为在 base 上本已成立，应在计划里标为护栏（slices.json guards）并预写测试；不要改坏生产代码造红`；
   - 只在 `source` 非空的测量里红过 → `G5 measure: <sid> → <t> 只在改了生产代码之后测到红（改源码后的红不算先红证据）`；
   - 都不是 → `G5 measure: <sid> → <t> 从未在控制面测量中红过（写好测试后调用 measure 看它红，再写实现）`（原措辞）。
4. **删除两条旧规则**：
   - 整片失败项「每次见红时都已改动生产代码（RED 须先于实现）」；
   - 警告「在本片起点已通过，免于先红」的隐式豁免。
5. 非 pytest 目标照旧只记警告「非 pytest 目标无法测量」。

`cmd_gate` 调用时传入 `set(sl.get("guards") or [])`。

### 2. guards 的 lint（design D2）
**`lint_plan` 加两条错误**，以 `guards:` 开头：
- `guards: <S> 的护栏 <sid> 不在本片 scenarios 里`
- `guards: <S> 的护栏 <sid> 没有 scenario_tests 映射`

**`cmd_lint`**：在 `lint_plan` 之后、打印 waves 之前，查每个护栏映射到 `.py` 的目标。测试函数仍带 xfail 标记时，加错误 `guards: <S> 的护栏 <sid> 的测试 <target> 仍带 xfail（护栏须在规划时写好、base 上已通过）`。
- 识别方式与 G7 / `scenario_status` 判「仍带骨架标记」的方式相同，含别名装饰器。复用现有函数，不另写一套。
- 文件按 git toplevel 解析。
- 有错误时与 `lint_plan` 的错误一样以非 0 退出。

### 3. measure 输出（design D3）
`cmd_measure` 输出的 JSON 增加 `"guards"`：本片护栏映射的目标列表，按 `scenarios` 的顺序排列，无护栏时为 `[]`。

### 4. 现有测试同步（同在 `tests/test_slice_gate.py`）
