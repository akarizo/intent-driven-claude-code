# DRAFT. memory 是第五记忆载体，按「索引常驻 + 正文按需」纳入分流体系

- Status: accepted
- Date: 2026-08-29

## Context

`claudemd-standard §12b` 把「这条事实该写哪」规约成四个载体，按加载条件排序：`CLAUDE.md`（全量常驻）、`.claude/rules/*.md` + `paths:`（命中 glob 才加载）、Skill（description 匹配才加载）、测试/lint/hook（不占上下文）。

这张表漏了一个正在被大量使用的载体：`~/.claude/projects/<slug>/memory/`。本机实测 21 个项目有 memory 目录，其中 `amc-afa` 累积到 **221 个实体文件 / 1.1 MB 正文 / 24 KB 索引**。

漏掉它有两个后果，都已经实际发生：

**其一，「这条写哪」这个问题在 spec 层面无法回答。** 实测发现同一条事实（subagent 模型 env 优先级）在全局 `CLAUDE.md` 与某项目 memory 里各写了一遍，措辞几乎逐字相同。LCA 铁律本该判它只留一处，但 memory 不在载体表里，规则就够不着它。

**其二，memory 的常驻成本被系统性低估。** memory 的加载条件不是「全常驻」也不是「全按需」，而是混合体——`MEMORY.md` 索引每会话必付，正文按需 recall。这意味着**写一条 memory 不是零成本**：每条都给所有会话永久加一行索引。`amc-afa` 的 106 条索引 = 7.8k tokens 常驻。把 memory 当成免费仓库使用，代价会以最不易察觉的方式（索引缓慢膨胀）积累。

同时，memory 层此前**完全没有机械门禁**，而 `CLAUDE.md` 有 `claudemd-lint`。实测在 `amc-afa` 抓到一次文件重命名引发的三重失效：悬空指针（索引指向已不存在的文件）、孤儿文件（新文件未被登记）、状态失真（索引行仍宣称「已 propose 未 apply」，实际已 apply 完毕待开 MR，且展示的是一批 propose 期已作废的警告）。**第三项最危险——常驻层主动提供错误信息，比不提供更坏。**

## Decision

**把 memory 作为第五载体正式纳入 `§12b` 分流体系**，并按其混合加载条件规约成本与守护方式。四条原则：

1. **加载条件决定分界，不靠直觉**。唯一的第一性问题是「这条事实需要在每一次会话开头就生效吗」。是 → `CLAUDE.md`；只在碰到特定任务时才需要 → memory。落成可判定的判据：**不知道它会「做错事」→ CLAUDE.md（它是约束）；不知道它只是「多花时间」→ memory（它是发现）**。

2. **索引即常驻税，memory 准入门槛不为零**。每条 memory 永久占用一行常驻索引，其价值必须能被「命中时省下的重新查证」摊平。粗判据：**未来 10 次会话用不到 1 次的，不该进 memory**——它的归宿是文档或 issue。

3. **二级索引下沉是正当且受支持的机制**。已完结、低命中率的条目移入 `index-*.md` 二级索引，从常驻层退出、仍可 recall。命名以 `index-` 前缀为约定，使机械工具能零歧义识别。超预算的第一处置是下沉，不是删知识。

4. **索引完整性由机械门禁守，准入判断由人守**。这是 `§13b`「硬约束 vs 软判断」分工在 memory 层的落地：双向映射闭合、字节预算、行长是可判定的 → `memory-lint` 机械拦截；「这条值不值得记」是软判断 → 交给人与 `/claudemd-commit`，**lint 不得裁决**。状态漂移居中——依赖自然语言比对、不可能完全可判定，故只提醒、不阻断。

配套的兜底原则：**任何内部异常一律放行**。坏门禁不能锁死编辑，这一条优先于任何检查。

本决策规约的是「memory 在载体体系中的位置、成本与守护边界」，**不触及**「哪条具体知识值得记」——那是每次写入时的个案判断。

## Consequences

- **更易**：「这条事实写哪」首次有了覆盖全部五个载体的完整判据，跨 `CLAUDE.md` 与 memory 的重复有了可判定的裁决规则（常驻层级更高者赢，另一侧连指针都不留）。
- **更易**：memory 索引的失真（悬空 / 孤儿 / 状态漂移）可被机械发现。这类缺陷跨越几十个会话、由 agent 自动写入产生，人眼无法守住。
- **更难**：写 memory 从「随手记」变成有成本意识的动作——要先过准入门槛，还要同步索引。这是刻意增加的摩擦，换取常驻层不再无声膨胀。
- **更难**：新建二级索引必须遵守 `index-` 命名约定，否则被下沉的条目会被误报为孤儿。约定优于配置，代价是失去命名自由。
- **约束后续变更**：memory 不在任何 git 仓库下，**没有版本基线**。因此 `claudemd-lint` 的净增量闸（`--diff-gate` 比对 `git show`）在 memory 层无法实现，预算只能是绝对阈值。若未来要做增量闸，需先解决基线来源问题，届时重新评估本 ADR。
- **不影响**：无 memory 目录的项目（实测 139 个 projects 目录中 118 个无 memory、5 个为空）零输出零影响；`claudemd-lint` 的既有判据与阈值一行不改；两个 lint 脚本互不 import。
