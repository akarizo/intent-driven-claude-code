## 做什么（design D6、D9）

### `template/plugins/flight/hooks/orchestrator.tsx`
1. **诊断员只读操作升 allow**（spec `diagnostician-reads-auto-allowed`）：
   - `inEnvelope`（约第 246 行）现在对诊断员直接 `return false`；改为与评审员同规则：Read / Grep / Glob 用 `readUpgradable`，Bash 用 `bashUpgradable`；
   - 诊断员的 `commands` 额外加上 `triagePrompt` 里那两条查看命令：`python3 <hooksDir>/ledger.py show --change-dir <D>` 与 `python3 <hooksDir>/timeline.py report --change-dir <D>`，D 为 `absChangeDir(f)` 或提示词里实际写的路径，以 `prompts.ts` 的 `triagePrompt` 为准；
   - 写入照旧不升级。
2. **诊断员纳入看门狗**（spec `watchdog-stops-stalled-diagnostician`）：`inFlight`（约第 859 行）也认 `diagnosing.has(change)`，仅对 role 为 diagnostician 的 agent。`watchOne` 对诊断员已是「只停不记」（约第 839 行），保持。
3. **看门狗停飞补停**（spec `watchdog-halt-drains-queue`）：
   - `watchOne` 停飞那支（约第 851–855 行）现在是：写 halt → 停 `liveAgents` → 刷新 → triage；
   - 改为与 `abortCommand`（约第 725 行，策略在 `abort.ts` 的 `abortFlight`）同法：先停在跑的，再 `queue.then(() => undefined)` 等手上这轮 drive 做完，然后补停其间派出的；
   - 可以直接复用 `abortFlight`（halt 回调里传 `haltKind: 'watchdog'` 与看门狗的原因），也可以照它的顺序写。
4. **计时器去重**（spec `ticker-not-duplicated`）：
   - `ensureTicker`（约第 777 行）每起一个计时器就递增一个模块级代号；`watchTick` 只在自己的代号是最新时处理，旧计时器的 tick 直接返回；
   - `watchTick` 对每个超时 agent 先 `forget` 认领再处理，避免两次 tick 并发拿到同一快照（现在已是先 forget，确认在任何 await 之前完成）；
   - 去掉第 776 行那条已不成立的 ceiling 注释，改写为如实描述。
5. **起飞闭包**（无专属 scenario，由 S5 的 `band-approve-takes-off` 覆盖）：
   - 模块级 `let entry: ((args: string[], opts?: { resume?: boolean }) => Promise<string>) | undefined`；
   - 在 `{ cwd: /^/ }` 的 `session.start` hook 里设 `entry = (args, opts) => takeoff($, args, opts ?? {})`；
   - 导出 `takeoffNow(args, opts)`：`entry` 未设时返回 `flight：插件尚未就绪，稍后再按`。
   - 测试与插件是隔离实例，不能在测试里 import `takeoffNow` 直接调用来验证。
