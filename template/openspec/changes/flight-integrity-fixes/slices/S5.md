# S5 · flight 插件：可批准项优先、读不到版本给提示、路径规范化、守卫覆盖门禁结论 ref

**目标**（design D6）：批准带优先显示可批准项、分开计数；读不到版本时 toast；文件写入守卫先规范化路径；命令守卫也拦 `refs/flight/<change>/gate-<S>`；版本升到 0.1.1、描述同步。

## 契约

```text
topItem：先在 problem === '' 的项里取 mtime 最新；没有才在全部项里取
批准带底部：待批准数 = 可批准项数 - 1（显示项本身不计），无法批准数 = problem 非空且不是显示项的项数
  文案「另有 N 个待批准」「另有 M 个无法批准」，为 0 的那段不显示
session.start：$.session.version() 放进 try；catch → $.ui.toast('flight：无法确认 Claude Code 版本，批准带已停用')，保持停用，next(e)
文件路径规范化：String(path).replace(/\\/g, '/')，再循环把 '//' 与 '/./' 折叠为 '/'，然后测 LEDGER_FILE
LEDGER_REF 扩为 /refs\/flight\/[^\s'"]+\/(ledger|gate-[^\s'"\/]+)/（拒绝文案仍含 ledger.py show）
plugin.json version → 0.1.1；plugin.json 与 marketplace.json 的描述：「…拦截模型对账本 / 门禁结论 ref 的写入（Bash / Monitor / 文件写入工具）」
```

新增 TS 测试，名字与 scenario id 一致：
- `band-prefers-approvable-item`：主 worktree 的 demo 可批准，mtime 1000；另一 worktree（分支 `worktree-zeta`）的 zeta，mtime 2000，该 worktree 下无 plan_fp.py。断言出现 key `approve:demo:<F>` 的按钮，以及含「另有 1 个无法批准」的文字。
- `version-unreadable-shows-notice`：`versionFails`；断言 toasts 里有含「无法确认 Claude Code 版本」的一条，且没有任何 Button。
- `guard-normalizes-ledger-paths`：Write `C:\repo\.git\refs\flight\demo\ledger`、`/repo/.git/refs//flight/demo/ledger`、`/repo/.git/refs/./flight/demo/ledger`。断言三次都被拒（结果含 `ledger.py show`），且没有到达执行端。
- `guard-denies-gate-record-writes`：Bash `git update-ref refs/flight/demo/gate-S1 abc` 被拒、没有到达执行端；Bash `python3 .claude/hooks/slice-gate.py gate S1 --change-dir openspec/changes/demo` 原样到达。
