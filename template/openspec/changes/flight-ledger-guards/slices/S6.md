## 做什么（design D3、D8、D11）

### `template/plugins/flight/hooks/land.ts`
- **`afterMerge`**：删掉 `slice-gate record` 调用，只刷新接口摘要、取 HEAD。
- **`mergeFix`**：
  - 删掉 `timeline record fix` 调用；
  - 第三个形参改名 `_note`、保留不用：并行的 S7 仍按原位置传参，见 `slices/_interfaces.md`；
  - 注释同步。
- **`closeout`**：
  - 跑 ship → 写 `review-findings.json` → 勾选 `tasks.md` → 返回 `{verdict, reasons}`；
  - 删掉 `timeline record apply-done` 与末尾的收口提交，它们挪到 landing（design D3）。
- **新增 `renderRecords(io, f): Promise<string | undefined>`**：
  - 先在 change worktree 运行 `timeline.py render --change-dir <D>`（经 `judge`，cwd 为 `f.changeTree`）；
  - 再 `commitRecords(io, f, 'chore(flight): 收口', ['review-findings.json', 'tasks.md'])`；
  - 失败返回原因（首行），成功返回 undefined。
  - `RECORD_FILES` 里须含 `timeline.md` 与 `gate-report.md`，没有就补上。

### `template/plugins/flight/hooks/landing.tsx`
- **land 分支**（design D3 的 5 步）：
  1. `closeout`；
  2. 追加 land；
  3. `renderRecords`。失败时 `ctx.log` 写「落地记录生成失败：<原因>」，`ctx.toast` 写含「落地记录生成失败」的提示，继续；
  4. 打印飞行记录。verdict 为 draft 且 reasons 非空时，飞行记录里加一行 `draft 原因：<reasons>`。可以给 `flightRecord` 增加一个可选参数，也可以在调用处拼接，但飞行记录仍须是一次 `ctx.log`；
  5. 交接 pr-ship，不变。
- **final 分支**：final 事件写入 `warnings: g.warnings`（`ev.final` 已接受可选 warnings，S5）。
- **`reviewPlan` 的 followup 分支**：base 为空、或等于 commit 时返回 error「复核范围缺 base：…」，由现有路径记 `blocked review:<slice>`（infra），与 whole 分支的阻断写法一致。
- **派发前查停飞**：派发评审员与修复体时，`ctx.spawn` 之前调用 `stoppedNow(io, f)`；结果非 undefined 就直接 return，不追加事件。

### `template/plugins/flight/hooks/io.ts`
- 新增 `stoppedNow`，签名与语义见 `slices/_interfaces.md`、design D8。用本文件现有的账本读取函数。

### 测试
- `landing.test.tsx` 的世界要应答 `python3 …/timeline.py render`：默认退出 0，输出 render 的 JSON。可配置为失败。
- 现有用例里断言 closeout 记 apply-done、或收口提交发生在 land 之前的，改为新顺序。
- change 1 留下的 `advance()` 辅助函数（遇到全量评审派发就模拟评审员返回空列表）保留。
- `land.test.ts` 里断言 `record` / `timeline record` 调用的用例，改为断言不调用。
