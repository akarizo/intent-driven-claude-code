## 做什么（design D1 插件侧、D7、D10、D13）

### `template/plugins/flight/hooks/orchestrator.tsx`
- **派发改调 `base`**：
  - `startSlice` 改名 `sliceBase`，运行 `slice-gate.py base <S> --change-dir <D> [...extra]`，不再带 `--evidence ledger`；
  - 从 stdout 取 base 的逻辑不变，失败原因的前缀改为「slice-gate base 失败：」；
  - 两个调用点的参数照旧：全新执行体 `--expect-branch <f.branch>`，续接 `--base <a.base>`，解冲突不带。
- **起飞不写 timeline**：
  - 删掉 attempt 1 时 `timeline record approve` → `git add` → `git commit -m 'chore(flight): approve'` 那一段；
  - 只为它准备的变量（takeoff-gate 的输出若仅用于 note）随之清理，但 takeoff-gate 的核对本身保留。
- **判主模型**（design D10）：
  - 删掉 `session-model.py` 调用；
  - 未给 `--model=` 时 `await $.session.model()`，按 `['opus', 'sonnet', 'haiku', 'fable']` 子串匹配取别名，不区分大小写；
  - 取不出或抛错时，回复「flight：判不出主模型（<原值或错误首行>），用 --model= 指定」。
- **abort**：`abortCommand` 的 `live()` 去掉 `await queue`，新增 `drain: () => queue`。

### `template/plugins/flight/hooks/abort.ts`
- 按 design D7 改写 `abortFlight`：依赖增加 `drain`；处理「本 attempt 已 halt 且有残留 agent」；在飞时两段停。
- 回复文案：
  - 在飞：首行沿用「已中止 <change> attempt <n>（已在账本记停飞）」；
  - 残留：首行为「<change> attempt <n> 已停飞（<halt 原因首行>）；停掉残留 agent：」；
  - 每个 agent 一行 `- <id>：已停` 或 `- <id>：未停（<原因>）`；
  - 末行沿用 `/flight resume <change>` 的提示。

### `template/plugins/flight/hooks/versions.ts`
- `REQUIRED_FEATURES` 增加 `ledger-records`。

### 测试
- `orchestrator.test.tsx` 的世界：
  - 对 `slice-gate.py start` 的假应答（约第 258 行）换成 `base`；
  - 删掉 `session-model.py` 的应答，改为在插件之下 `on('session.model', () => 'claude-opus-5-5')`，写法同现有的 `session.cwd` / `session.id`；
  - `slice-gate.py features` 的应答加上 `ledger-records`；
  - 不再应答 `timeline.py record approve`，世界见到它就报错，用来守住「起飞不写 timeline」。
- `versions.test.ts`：`ALL_FEATURES` 加 `ledger-records`。
- `abort.test.ts`：`abort-halts-then-stops-live-agents` 的调用顺序改为两段停的新顺序；`abort-refuses-without-own-flight` 里「已 halt」那一格按 D7 第 3 条调整：halt 且 `live()` 为空时回答不变。
