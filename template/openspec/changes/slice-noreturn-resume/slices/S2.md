## 契约

```js
// startCmd 加第三参：(s, base, resume) => … + (base ? ` --base ${base}` : '') + (resume ? ' --resume-checkpoint' : '') + (branch ? ` --expect-branch ${branch}` : '')
// const NO_RETURN = { noReturn: true }
// executorPrompt(s, retryOf)：
//   retryOf.noReturn → 不出现第零步 cherry-pick；第一步 startCmd(s, null, true)；
//                      任务行：上一轮执行体未返回（多为撞 maxTurns 轮次上限），没有门禁结论；start 会把上一轮半成品恢复为未提交改动（看 start 输出的 checkpoint.restored），先 git status / git diff 看清已完成部分，在其上继续、不要重做；收尾仍按切片包 TDD、每切片一个 commit
//   其余分支原样不动
// 派发：.then((r) => (!r || !r.ok) ? agent(executorPrompt(s, r || NO_RETURN), {同既有 retry opts}) : r)
// 结果仍 null：blocked {slice: s, kind: 'infra', reason: 'agent 未返回（已重派一次）'}
```

- `opsx-apply.md` / `SKILL.md` 回退路径在「门禁红则…重派同一切片一次」之后补同一句：执行体未返回门禁 JSON（Agent 工具回报 partial 或无 JSON）也重派一次——prompt 说明上一轮未返回，`slice-gate.py start <S> --resume-checkpoint` 从快照恢复半成品后继续；重派仍无 JSON 记 blocked（infra）。两份同句同改。
- `slice-executor.md` 开工段第 2 条补：prompt 让 `start` 带 `--resume-checkpoint`（上一轮未返回）时，start 已把半成品恢复为未提交改动，输出的 `checkpoint.restored` 列出文件；先看清再继续，不重做。预算条补半句：撞上限时 hook 已快照 owns 内改动，重派会接续，但仍应在上限前收尾。
- `hooks.json`：`PostToolUse` 新增 `{"matcher": "Write|Edit|Bash", "hooks": [{"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/slice-gate.py\" checkpoint"}]}`；`PostToolUseFailure` 新增 matcher `Bash` 的同一命令。
- 根 `.claude/settings.json`：同两条，按该文件既有 `sh -c '[ -f … ] && exec … || exit 0'` 写法指向 `template/.claude/hooks/slice-gate.py`。

## 坑

- ⚠ `test_workflow_routes_models_explicitly` 要求 `agent(` 出现次数 = `model: models.` 次数：不新增 `agent(` 调用，注释里也别写裸 `agent(` 字样（用 `agent()` 也会被正则 `\bagent\(` 计数）。
- ⚠ `test_workflow_start_carries_expect_branch`：S1 首轮 G0 拒绝（`commit` 空串、非 null）→ 重派**不** cherry-pick、走「按切片包 TDD 实现」——这是红灯分支，不能被 `noReturn` 分支吞掉。
- ⚠ `test_apply_docs_mirror_retry_and_preflight` 要求命令与 skill 提到的 hook 脚本集合一致，两边都只写 `slice-gate.py`。
- ⚠ `test_apply_command_zero_prompts`：opsx-apply.md 的 lint 到 `/pr-ship` 区间不能出现 `AskUserQuestion`。
- ⚠ 每条新测试解锁时去掉 `@pytest.mark.xfail(strict=True, ...)` 那一行。
