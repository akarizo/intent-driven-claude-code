## 省轮次（包络与工具的已知限制）
- 改文件一律用 Edit / Write，路径写字面绝对路径；不要用 `sed -i`、`python3 -c` 改文件，不要用 heredoc，不要把输出重定向到 worktree 之外。

## 测试世界的已知事实（`orchestrator.test.tsx`）
- `demoWorld({ dirty: [...] })` 把每个路径渲染成一行 porcelain（`?? <path>`）；改名行需要原样的 porcelain 行。若世界还没有这个开关，加一个可选的 `porcelain?: string`：给出时 `git status --porcelain` 原样返回它，写法照现有 `dirty`。
- `ARTIFACTS` 恰为 3 个：`<CD>/proposal.md`、`template/openspec/adr/DRAFT-x.md`、`tests/test_s1.py`。

## 做什么

### `land.ts`
1. `classifyDirty` 循环开头：`if (p.includes(' -> ')) { out.others.push(p); continue }`，注释写明「porcelain 改名行（X 位 `R  `、Y 位 ` R` 去掉 XY 两列后同形）：不代为提交，归为工件之外（#44 评审 MEDIUM）」。
2. 函数 docstring（若有）补一句改名行的口径。不改 `commitArtifacts`。

### `orchestrator.tsx` 的 `takeoff()`
3. 「未提交的只有本 change 的工件」那条拒绝：改为
   `flight：工作区不干净，不起飞：未提交的只有本 change 的工件（N 个）：\n<逐行路径>\n确认无误后发 \`/opsx-apply <name> 授权提交\`，插件只提交这些文件后起飞`。
   ⚠ 首行仍须以「工作区不干净，不起飞：未提交的只有本 change 的工件」开头：`armed.ts` 的 `classifyRefusal` 靠这句归类为 `human-key`，`transient` 的判据是「不起飞：」后紧跟换行，不能误入。
4. 起飞回复：`committed` 改为 `\n已提交工件 N 个文件：\n<逐行路径>`。
5. 有工件之外改动时的拒绝不变（只列工件之外）。
