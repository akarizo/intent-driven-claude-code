## 做什么（design D1–D5、D6 的包络部分；签名见 `slices/_interfaces.md`）

### `template/plugins/flight/hooks/core.ts`
- **类型与常量**：`Role` 加 `diagnostician`，新增 `HealKind`、`HaltKind`、`HEAL_BUDGET = 3`、`INTEG = 'integ'`；`Action` 按接口约定增改；`Ctx` 加可选 `notify?`。
- **事件**：`ev.heal`、`ev.triage`；`ev.halt` 接受可选 `kind`。
- **`healVerdict(state, kind, slice)`**：只数本 attempt 的 heal。
- **A1**（design D1）：
  - `afterMergeFailed`：非冲突且未派解冲突 agent 时 → `heal` / 全新派发 / blocked（预算原因）。
  - `sliceActions`：只看最后一次执行体派发之后的 merge。
  - `executorOutcome`：已派次数只数最后一条 merge-retry heal 之后的派发。
- **A2**（design D2，只管被停之后）：
  - `reviewActions`：评审员结束而没有 review，且有 `heal {kind: 'watchdog', agent: <它>}` → 重派同 slice 的评审员（同 commit）。
  - `wholeReview`：评审员结束而没有 review，且有指向它的 heal → 重派同 slice、同 mode、同范围（复核要带同一 base / prior）。
  - `fixerOutcome`：没有收口门禁、且有指向它的 heal → 重派同 slice 的修复体（同 findings / failed）。
  - 没有 heal 的情形一律维持原行为。
- **A4**（design D4）：final 红时按 design D4 第 1–5 步走 `heal integ` → `dispatch fixer {slice: 'integ', findings: [], failed}` → 收口绿 → `dispatch reviewer {slice: 'integ', mode: 'integ', base: <integ dispatch 的 base>, commit: <收口 commit>}` → review 无阻断 → `merge integ via fix` → `final`。
  - `reviewFindings(state, true)` 排除 slice `integ`。
  - integ 合回后，若最新 final 早于这次合回，返回 `final`（参照 `wholeReview` 对 `fix-r<k>` 的写法）。
- **halt 分类**：`next` 返回的每个 halt 都带 `haltKind`：
  - blocked 停飞 → `blocked`；
  - 指纹 → `fingerprint`；
  - final 红且不派 integ，或 integ 后仍红 → `final`；
  - integ 复核阻断、或 `blocked integ` → `integ`。

  预算不允许时的原因追加 `healVerdict` 的 reason。
- **`summarize` / `summaryLines`**：
  - 多一行「自愈 k/3：<kind> <slice> · …」（k 为本 attempt heal 数）；
  - 有 triage 时多一行「诊断：<首行>」；
  - 修复列对 slice `integ` 显示「整合 进行中 / 已合回 / 阻断（…）」。
