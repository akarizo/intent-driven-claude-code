## 做什么（design D5、D4）

### `template/.claude/hooks/intent-gate.py`
- **抽出纯判定** `judge(target_abs, cwd) -> (allow, reason)`。原有规则全部保留，顺序不变：
  - 根下无 `openspec/` 放行；
  - 目标在根外放行；
  - 命中豁免放行；
  - apply 上下文放行；
  - mini 声明覆盖放行；
  - 其余拒绝。
- **删掉切片标记逻辑**：读 `.openspec-slice`、owns 检查、「标记在而无 apply 上下文」那几步。
- **apply 上下文收窄**（design D5）：
  - 取目标最近的已存在祖先目录；
  - 在其中求 toplevel 与当前分支（`git symbolic-ref --short -q HEAD`，失败视为无分支）；
  - 分支形如 `worktree-<name>` 或 `flight/<name>/<…>`：只看 `<root>/openspec/changes/<name>/tasks.md` 有无未勾项；
  - 否则：原判法（任一 change 有未勾项）。
  - 拒绝原因按 design D5 的文案，须含「change <name>」。
- **classic 模式**（无参数，读 stdin）：
  - 只用 `judge`；
  - 输出形状不变；
  - 异常放行（fail open）不变。
- **check 模式**：形状见 `slices/_interfaces.md`。
  - 每个路径各判一次，汇总后打印一行 JSON；
  - 判定中的任何异常：stderr 写原因，退出 2。
- 文件头注释同步：判定步骤、两种模式、收窄规则。

### `tests/test_intent_gate.py`
- 现有 4 个用例里依赖标记 owns 的（不在 owns 内拒绝、陈旧标记、owns 内放行）：按新语义改写，或被新 scenario 覆盖后删掉。
- 「worktree 定根」的用例保留；它的仓库若在 `worktree-<name>` 分支上，须补上同名 change 与未勾任务，保持原意。
- 末尾 2 个骨架写实。
- 测试里的 git 仓库与 worktree 用 `git init`、`git worktree add -b <分支>` 在 tmp_path 下现造。
