# S2 · 落地交接 /pr-ship 失败不停飞；飞行记录拼装有兜底

## 做什么
`template/plugins/flight/hooks/landing.tsx`：

1. **land 分支**：现在的顺序是 closeout → land 事件 → 清状态行 → `ctx.log(record)` → `ctx.runCommand('pr-ship', f.change)`。把 `runCommand` 包进 try/catch。出错时：
   - `await ctx.log(\`落地完成，但接 /pr-ship 失败：${首行}\`)`；
   - `await ctx.toast(\`flight：${f.change} 已落地，但接 /pr-ship 失败：${首行}；请手动运行 /pr-ship\`)`；
   - 不再向上抛，所以 drive 的「动作异常」分支不会补记 halt。
2. **`flightRecord`（约 58 行）**：`judge(... 'timeline', ['report', ...])` 包进 try/catch，抛错与非 0 退出走同一个分支，正文写 `（timeline report 失败：<原因首行>）`。原因取 stderr 首行；为空时写 `exit <退出码>`；是抛错时取异常消息首行。
3. **测试补漏（PR #40 评审 LOW）**：在 `landing.test.tsx` 补一个路由对账「N 条不符」的用例：一条 ended 事件的 model 与起飞主模型不符，断言 log 含「路由对账：1 条不符」和对应的 summary。这一条不是 scenario。
4. **过时注释**：`tests/test_flight_landing.py` 约 56 行的「骨架：S2 实现后去掉 xfail 标记。」改成「flight-hardening S2 的 scenario 测试。」

## scenario → 同名 TS 测试（写在 `landing.test.tsx`，沿用文件里的假 Ctx）
- `flight-landing-handoff#land-handoff-failure-keeps-landing`：假 Ctx 的 `runCommand` 抛 `new Error('no command named /pr-ship in this session')`。
- `flight-landing-handoff#flight-record-survives-report-throw`：假 io 在 `timeline report` 时抛 `new Error('spawn ENOENT')`。断言 log 文本，以及调用顺序为 `['log', 'command']`。
- `flight-landing-handoff#flight-record-shows-exit-code`：timeline report 以 2 退出、stderr 为空，执行停飞动作。
