# S1 · land.ts：导出提交飞行记录的函数；准备解冲突现场不吞非冲突的合并失败

## 做什么
`template/plugins/flight/hooks/land.ts`（3a S6 写的，先读一遍）里有两处要改：

1. **导出 `commitRecords`**：它现在是模块内函数 `async function commitRecords(io, f, message, extra = [])`，返回 `string | undefined`（错误或无）。改成 `export async function commitRecords(...)`，签名与行为不变：
   - 只 add `RECORD_FILES`（加 extra）里有未提交改动的、change 目录内的文件；
   - 有才 commit；
   - change 目录外的改动不碰。
   
   S4 的落地逻辑会在跑 final 前调用它。
2. **`prepareResolve` 检查合并的退出码**：在解冲突 worktree 里重做 `git merge --no-ff flight/<change>/<S>` 之后：
   - 退出非 0 且 `git diff --name-only --diff-filter=U` 为空 → 返回 `{ error: 'git merge 失败：<stderr 首行>' }`；
   - 有未合并文件才返回 `{ path, conflicts }`；
   - 退出 0（意外地无冲突）→ 返回 `{ error: '解冲突现场合并意外成功：无需解冲突' }`。
