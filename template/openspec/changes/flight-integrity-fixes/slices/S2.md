## 契约

```text
scenario_status：
  先按原有逻辑做文本检查；文本检查通过、且目标文件以 .py 结尾的，收集到 py_targets（nodeid = rel::func）
  py_targets 非空 → 跑一次：
    [sys.executable, "-m", "pytest", "-v", "-p", "no:cacheprovider", *nodeids]，cwd=root
  逐行匹配 ^(?P<id>\S+::\S+?)\s+(?P<out>PASSED|FAILED|ERROR|SKIPPED|XFAIL|XPASS)\b
  对每个目标，取 id == target 或以 target + "[" 开头的行：
    无行          → violations += "G7 scenario: <sid> → <target> 未被收集运行"
    有非 PASSED   → violations += "G7 scenario: <sid> → <target> 实际结果 <OUT>（未真正通过）"
    全 PASSED     → passed += 1
  非 .py 目标：保持只做文本检查（文本通过即 passed += 1）
```

## 坑

- ⚠ **不要用 `-rA` 解析**：它的汇总里 SKIPPED 行是 `SKIPPED [1] path:line: reason`，不带 nodeid。用 `-v` 的逐条行。
- ⚠ pytest 子进程 cwd 必须是 `root`（git toplevel），nodeid 是相对它的路径。
- ⚠ 既有用例要继续通过：
  - `test_final_gate_reports_scenarios`：实际 PASSED，passed 为 1；
  - `test_final_detects_multiline_xfail`：文本检查已报「仍标记 xfail/skip」，不再重复跑；该目标不进 py_targets 也可以。
- ⚠ G7 文案必须同时含 scenario id、`G7` 前缀与实际结果单词（XFAIL / SKIPPED 等），骨架按这三样断言。
- ⚠ 本仓库自己的 final 会因此多跑一遍映射测试（含 `claude plugin test`），属预期代价。
- ⚠ 逐条去掉 3 条 S2 骨架的 `@pytest.mark.xfail`；不要动 S1 的测试。
