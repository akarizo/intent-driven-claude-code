## 做什么

### `template/plugins/flight/commands/pr-ship.md`（design D10）
- **保持骨架**：步骤编号 1–11 与各步标题的开头保持不变，其他测试按「4. **预合并冲突检查」「7. **创建 PR/MR**」「8. **」「9. **」「10. **」「11. **」「**Output Summary」「**Guardrails**」切段。
- **description 与开头段**：写明两种模式。
  - 飞行模式（有 `slices.json`）：评审与修复已在飞行内由控制面完成，本命令只负责送出，由 `ship` 工具按账本裁决；
  - 飞行外：维持「干净评审员 + 至多一次问询」。
- **第 6 步（标题与正文）**：
  - 飞行模式：正文写背景、设计、测试计划三段，不再贴 `ship --markdown` 段落与切片评审清单，因为裁决和评审结论由 `ship` 工具贴成评论；
  - 飞行外：正文须写一行「非账本裁决（飞行外）」。
- **第 7 步（创建 PR/MR）**：
  - 飞行模式一律带 `--draft` 建 PR，建好后调用 `ship` 工具（`mcp__flight__ship`），参数为 `change` = `<change-dir>` 的最后一段、`pr` = PR 号；
  - 写明插件会核对 PR 头、按账本裁决、贴评论、切换 draft / ready、记 ship 事件；主会话据工具结果打印，不自行判断；
  - 写明工具拒绝时的处理：
    - 「先推送」→ 推送后再调一次；
    - 「只支持 GitHub」→ PR 保持 draft，交人；
    - 其他 → 停下报告。
  - 本步不得出现 `gh pr ready`。
  - 飞行外：照旧不加 `--draft`。
- **第 8、9、10 步**：
  - 标题行都写明「飞行外」，内容维持原样。原样的范围包括：worktree 钉住、`model: "<main>"`、取 diff 回退、AskUserQuestion 与「默认只贴评论」。
  - 删除第 10 步末尾「收尾复裁（飞行模式必做，双向转换）」整段，这一段改由 `ship` 工具完成。
  - 删除「只更新 `review-findings.json` 的 `blocking`」这类要模型改写裁决依据的指示。
- **第 11 步与 Output Summary**：PR 状态在飞行模式取自 `ship` 工具的结果。
- **Guardrails**：
  - 飞行模式全程零问询；
  - 飞行外至多一次（第 10 步）；
  - 新增一条：飞行模式不派评审员、不改 `review-findings.json`、不执行 `gh pr ready`。

### `/opsx-apply` 命令与 skill（同改：`template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md`）
- **「评审、修复与 final」段**：补上全量评审与修复轮。final 绿后控制面派全量评审，审整条 change 分支；有 CRITICAL/HIGH 自动修，至多 2 轮，每轮修复后重跑 final 并复核；仍未闭环就落地为 draft。
- **「落地交 /flight:pr-ship」段**：改为写明三点：
  - 落地时按 ship（只读账本）的输出写 `review-findings.json`；
  - `/flight:pr-ship` 以 draft 建 PR 后，调 `ship` 工具由插件按账本裁决；
  - 删掉「它会自己再跑一次 ship」之类的旧说法。
- **角色表**：增加「全量评审 / 复核：`flight:reviewer`，会话主模型，只读」。
- **来源规则**：每份文档只保留一处完整表述，即带 `/flight abort`、`/flight resume` 的那条。另一处删掉，或改成指向它的半句，但不得再出现「**来源规则**」字样。
