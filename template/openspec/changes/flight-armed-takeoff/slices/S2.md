## 做什么（design D9；spec `flight-takeoff-commit`）

### `template/plugins/flight/hooks/land.ts`
- **`commitArtifacts(io, f, paths)`（约第 56 行）**：现在对全部路径 `git add --`，再 `git commit -m … --`。改为：
  1. 先用 `git -C <changeTree> status --porcelain -- <paths>` 找出 XY 为 `D `（暂存区已删、工作区也没有）的路径；
  2. 这些路径不交给 `git add`，其余照旧 add；
  3. `git commit` 仍带全部路径。
- **实测依据**（真实 git）：照原写法，`git add` 报 `pathspec … did not match any files`；跳过后 `git commit -- <全部路径>` 正确记下删除，工作区干净。
- **其它情形**：status 失败时照旧走原逻辑（交给后面的 add 报错）。全部路径都是已暂存删除时，不调用 `git add`。
- **顺带修一处注释（LOW，无 scenario）**：`freshResolve` 的注释（约第 179 行）还写着「按 io.freshWorktree 的规则命名」，但 freshWorktree 现在有 `-r2…-r4` 候选，freshResolve 没有。改成如实描述 freshResolve 自己的命名规则，行为不改。
