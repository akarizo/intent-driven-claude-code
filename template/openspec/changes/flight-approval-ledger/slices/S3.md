## 行为契约（逐条对应 scenario）

1. **刷新**：`session.start`、主会话 `turn.complete`（`e.agentId` 缺省即主会话）、每次批准后。`git -C <$.session.cwd()> worktree list --porcelain` → 第一块是主 worktree；每块取 `worktree <path>` 与 `branch refs/heads/<b>`。
2. **候选**：每个 worktree 的 `openspec/changes/*` 与 `template/openspec/changes/*`（跳过 `archive`），需同时满足：有 `spec.html`、`tasks.md` 含 `- [ ]`。同名去重：分支为 `worktree-<name>` 的 worktree 优先，其次主 worktree，否则丢弃。
3. **待批准** = 当前指纹 ≠ `approved` 输出；`approved` 退出 4 → 该项显示「账本损坏」且无按钮（不在 scenario 内，按此实现）。结果写 `$.state`（`types/index.d.ts` 声明），绘制只读状态。
4. **批准带**（`ui.render` · `AbovePrompt`）：无待批准 → `next(e)`；有 → 最近修改（`spec.html` 的 `$.fs.stat().mtimeMs` 最大）的一项：change 名、指纹前 8 位、`spec.html` 绝对路径、`<Button key="approve" label="批准起飞">`，另有 N 个时注明。`e.props.hasSurvey` 为真时 `next(e)`。
5. **按压**：用 `on('ui.press', { plugin: 'flight', element: 'approve' }, …)` 处理（拿得到 `e.surface`）。先重算该项指纹；≠ 显示值 → `$.ui.toast('…计划已变化…')`、刷新、不写。= 显示值 → 账本追加（下条）→ 成功后 `$.prompt.fill({ text: '/opsx-apply <name>' })`；`isFilled` 为假时 toast 提示手动输入。
6. **账本追加**（模块内单一 Promise 队列串行；`cwd` = 该 change 所在 worktree）：
   `git hash-object -w --stdin`（stdin = 事件 JSON）→ `git mktree`（stdin = `100644 blob <sha>\tevent.json\n`）→ `git rev-parse -q --verify refs/flight/<name>/ledger`（失败 = 无父）→ `git commit-tree <tree> [-p <父>] -m "flight: approve <name> <fp8>"` → `git update-ref refs/flight/<name>/ledger <新> <父|40 个 0>`。`update-ref` 非 0 → 从 rev-parse 起重试，共 3 次；仍失败 → toast 错误、不预填。
   事件：`{"v":1,"ev":"approve","change":<name>,"fp":<64位>,"at":new Date(await $.clock.now()).toISOString(),"by":{"plugin":"flight","surface":e.surface,"session":await $.session.id()}}`
7. **守卫**：`on('tool.call', { tool: 'Bash' }, …)`：`e.command` 匹配 `/refs\/flight\/[^\s'"]+\/ledger/` → `{ deny: '…账本只能由 flight 控制面写入；读取请用 python3 .claude/hooks/ledger.py show …' }`，否则 `next(e)`；`.catch(($, e, next) => next.called ? next(e) : (匹配 ? { deny } : next(e)))`。
8. **无模型入口**：不调用 `$.tool.register`；不调用 `$.command.register`。
9. **版本下限**：`session.start` 读 `$.session.version().version`，按数字逐段比较 < `2.1.295` → 状态置为停用、`$.ui.toast` 含 `2.1.295`；批准带 `next(e)`、按压不写；守卫照常。

## 坑

- ⚠ **TS 测试名必须与 scenario id 完全相同**（`band-shows-pending-plan` 等 8 个），pytest 包装按 `(pass) <名>` 逐条核对；`plugin-manifest-validates` 只由 pytest 跑 validate，不需要 TS 测试。
- ⚠ 插件工具返回值须为字符串（实测）；本插件不注册工具，此条只为提醒不要顺手加。
- ⚠ 写账本的代码只能出现在按压处理路径里；不得暴露成命令、工具或可被 `prompt.submit` 触发的入口（ADR：无模型可调批准入口）。
- ⚠ 引擎在热加载时会往插件目录写 `.claude-plugin/types/` 与 `tsconfig.json`：`.gitignore` 忽略生成物，不入库。
- ⚠ 不要 `import` S1 / S2 的 Python：只按上面的 CLI 契约用 `$.process.run` 调用。
- ⚠ 每条 pytest 骨架解锁时去掉 `@XF` 标记；本机 claude CLI ≥ 2.1.295 才能跑。
