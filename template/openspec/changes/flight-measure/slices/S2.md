# S2 · G5 账本判据；start 与 gate 的 --evidence ledger、--measure-base

## 前置
S1 已合回：`ledger.py` 认识 measure 事件；`slice-gate.py` 有 `measure` 子命令，以及与 `cmd_gate` 共用的 `source` 分类函数。先读 `slices/_interfaces.md` 与 S1 合回后的 `slice-gate.py`。

## 做什么（只改 `template/.claude/hooks/slice-gate.py`）

### 1. `start` 新增 `--evidence {log,ledger}`
- **缺省为 `log`**：行为完全不变。
- **为 `ledger` 时**：标记里多写 `"evidence": "ledger"`。打印的 JSON 照旧是标记本身，含 `base`。
- **重试同一切片时**（标记已存在且是本片）：保持原样打印。如果给了 `--evidence ledger` 而标记里没有这个字段，补上再写回。

### 2. `gate` 新增 `--evidence {log,ledger}` 与 `--measure-base B`
- **`log`（缺省）**：G5 沿用 `evidence_state`，一字不改。
- **`ledger`**：不读 evidence.log。`hooks_missing` 为 false，也不出任何含 evidence.log 的警告。G5 改为下面的判据。

### 3. G5 账本判据（`--evidence ledger`）
- **读账本**：`import ledger`，与 `takeoff-gate.py` 同样的做法（脚本目录在 `sys.path` 上）。读 `ledger.read_events(change_dir)`。抛任何异常 → 失败项 `G5 measure: 账本读取失败：<原因>`。
- **记号**：
  - `B_m` = `--measure-base`，没给就是门禁的 base；
  - `M` = `ev == "measure"`、`slice == S`、`base == B_m` 的全部事件，不分 attempt；
  - `T` = 本片 scenario 映射里以 `.py` 结尾的目标，非 `.py` 目标记警告 `G5 measure: 非 pytest 目标无法测量：…`；
  - `RED` = 状态为 `FAILED` 或 `ERROR`。
- **判据**，依次：
  1. M 里没有 `changed == []` 的事件（起点测量）→ 失败项 `G5 measure: 缺少本片起点测量（base <前 8 位>）`，不再看后面几条。
  2. 豁免：在任一起点测量里状态为 `PASSED` 的目标 → 警告 `G5 measure: <目标> 在本片起点已通过，免于先红`。
  3. `required` = T 减去豁免。对每个 t：M 里没有任何一次 t 为 RED → 失败项 `G5 measure: <scenario id> → <t> 从未在控制面测量中红过（写好测试后调用 measure 看它红，再写实现）`。
  4. `required` 非空，且 M 里没有任何一次「某个 required 目标为 RED 且 `source == []`」→ 失败项 `G5 measure: 每次见红时都已改动生产代码（RED 须先于实现）`。
- **测试友好**：把判据写成一个纯函数（输入 events、slice、base、T 与 scenario 映射，输出 failed 与 warnings），`cmd_gate` 只负责调用。
