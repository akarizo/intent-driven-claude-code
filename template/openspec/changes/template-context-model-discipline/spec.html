Why · 01为何而做

2026-07-10 对本机 24h token 用量的逐条聚合调查（103 个会话转录、8848 条计费消息）发现：PR #20 的 subagent 模型路由已生效，但仍有两处未被模板覆盖的浪费源。

(1) 主会话长上下文失控——44% 的 prompt 量发生在 >200k 上下文。主会话用 [1m] 变体是刻意保留的合理默认（1M 无加价、长任务不被 200k 硬切），但代价是失去 200k autocompact 的自动兜底——上下文闸门完全落到人工纪律上，而当前缺这套纪律：不主动 compact、挂机会话不重启（model 配置不热更新）、马拉松 subagent。

(2) Model 路由段的描述与官方优先级相反——它暗示可给 subagent 传 model: opus 升级，但官方 code.claude.com/docs sub-agents 已核实 CLAUDE_CODE_SUBAGENT_MODEL env var 优先级最高、压过 Task 显式 model 参数，锁 sonnet 后传参无效。这是一条会导致"以为升了 opus 实则 sonnet"返工的死条款。模板应把这些纪律与更正下发给所有使用者。

What · 02变更范围

  • 新增「上下文纪律」段到 template/CLAUDE.md.snippet：主会话用 [1m] 变体时无 200k autocompact 自动兜底，故人工纪律是唯一闸门——>150k 主动 /compact，切任务用 /clear 而非同会话续命；挂机长会话跨天必重启（model 不热更新，env 才热更新）；子 agent 单任务 scoped，预计超 ~100 轮或上下文 150k 先拆阶段、每阶段新开 agent 收束汇报，禁马拉松 subagent。
  • BREAKING（对模板语义）修正现有「Model 路由（省 token）」段：把"派发时给 subagent 传 model: opus 升级"更正为官方优先级——CLAUDE_CODE_SUBAGENT_MODEL env var > Task 显式 model 参数 > agent frontmatter > 继承主会话；env 锁 sonnet 后所有 subagent（含内置 general-purpose/Explore/Plan）一律 Sonnet，传 model: 无效；确需 Opus 级子任务 → 主会话直接做，或临时把 env 改 inherit 再派发。
影响文件：template/CLAUDE.md.snippet 纯文档契约 · 无代码/API/依赖 依据：24h 用量调查 + 官方文档核实

Specs · 04行为规范 (Gherkin)

ADDED context-lifecycle-discipline

上下文纪律随模板分发

模板的 CLAUDE.md.snippet MUST 包含一段「上下文纪律」，覆盖四类约束：[1m] 变体下失去 autocompact 自动兜底、故人工 compact/clear 成为唯一闸门、挂机长会话跨天重启、subagent 单任务上下文封顶。[1m] 是合理默认（1M 无加价、长任务不被 200k 硬切），本变更补上因此缺失的人工闸门纪律。

Scenario: 下游项目采用模板的 CLAUDE.md 片段并含上下文纪律段

  • GIVEN一个把 CLAUDE.md.snippet 并入自身 CLAUDE.md 的下游项目
  • WHEN该项目的主会话在这些指令约束下工作
  • THEN指令中包含一段「上下文纪律」
  • AND该段说明主会话用 [1m] 变体时无 200k autocompact 自动兜底，故人工 compact/clear 是唯一的上下文闸门

Scenario: 上下文纪律段规约 compact/clear 阈值

  • GIVENCLAUDE.md.snippet 已含上下文纪律段
  • WHEN主会话上下文增长
  • THEN该段要求上下文超 150k 时主动 /compact
  • AND切换到新任务时用 /clear 而非在同一会话续命

Scenario: 上下文纪律段规约挂机会话重启

  • GIVENCLAUDE.md.snippet 已含上下文纪律段
  • WHEN一个会话跨天挂机或长时间不重启
  • THEN该段要求跨天必重启会话
  • AND说明原因：model 配置不热更新（仅 env 热更新），旧会话会一直停在启动时的模型层级

Scenario: 上下文纪律段规约 subagent 上下文封顶

  • GIVENCLAUDE.md.snippet 已含上下文纪律段
  • WHEN派发或规划子 agent 工作
  • THEN该段要求子 agent 单任务 scoped
  • AND预计超 ~100 轮或上下文超 150k 的工作先拆阶段、每阶段新开 agent 收束汇报，禁止马拉松 subagent

MODIFIED model-routing-defaults

模型路由纪律随模板分发

路由纪律 MUST 如实反映官方 subagent 模型解析优先级——CLAUDE_CODE_SUBAGENT_MODEL env var > Task 显式 model 参数 > agent frontmatter > 继承主会话。MUST NOT 暗示"传 model: opus 可升级"。正确做法：主会话直接做，或临时把 env 改 inherit 再派发。

Scenario: 下游项目采用模板的 CLAUDE.md 片段

  • GIVEN一个把 CLAUDE.md.snippet 并入自身 CLAUDE.md 的下游项目
  • WHEN该项目的主会话在这些指令约束下工作
  • THEN指令中包含精简版 Model 路由段
  • AND该段说明：搜索/读文件/探索/渲染/机械同步默认 Sonnet；主会话对低推理命令需手动 /model sonnet

Scenario: 路由段如实反映 env var 优先级

  • GIVENCLAUDE.md.snippet 已含 Model 路由段
  • WHEN下游读者查阅如何给某个 subagent 使用 Opus
  • THEN该段声明 CLAUDE_CODE_SUBAGENT_MODEL env var 优先级最高，压过 Task 显式 model 参数与 agent frontmatter
  • AND该段说明在 env 锁 sonnet 时，给 subagent 传 model: opus/haiku 无效（含内置 general-purpose/Explore/Plan）

Scenario: 路由段给出获取 Opus 级子任务的正确做法

  • GIVEN一个确需 Opus 级推理的子任务
  • WHEN下游主会话依据路由段决定如何执行
  • THEN该段建议主会话直接做，或临时把 env 改 inherit 后再派发
  • AND该段不建议依赖"派发一个 opus subagent"的失效路径

Design · 05技术设计

Context

PR #20（ADR「模板分发的模型路由默认策略」）的 subagent Sonnet 兜底已生效，但两处未被覆盖：主会话长上下文（44% prompt 量 >200k）——主会话用 [1m] 变体是刻意保留的合理默认（1M 无加价、长任务不被 200k 硬切），代价是失去 200k autocompact 自动兜底，闸门落到人工纪律，而当前缺这套纪律（不主动 compact + 挂机不重启 + 马拉松 subagent）；以及 Model 路由段的 env 优先级描述错误。本变更是对唯一 in-force ADR 第 4 条「路由纪律下发」的描述精化 + 新增上下文纪律，未改其三层策略架构，故不需新 ADR supersede。

Goals / Non-Goals

Goals
  • 让路由纪律如实反映官方 env-var 优先级，消除"传 model:opus 升级"的误导
  • 新增上下文纪律段（[1m] 按需、compact/clear 阈值、挂机重启、subagent 封顶）
Non-Goals
  • 不改主会话默认用 [1m] 变体——刻意保留的合理选择（1M 无加价、长任务不被 200k 硬切），本变更只补上因此缺失的人工闸门纪律
  • 不改 settings.json 的 sonnet 兜底（它是对的，本变更只把文档写对）
  • 不引入运行期自动切换 / hook 强制——上下文纪律是主会话软约束
  • 不 supersede 现有 ADR

Decisions

决策 1 · Model 路由段改「优先级铁律 + 正确做法」而非「传参升级」

官方优先级 env var > Task 参数 > frontmatter > 继承。锁 sonnet 后传 model: 无效，原描述会让下游写出无效代码并返工。备选（已否）：保留原描述但加注"本机已锁 sonnet"——模板面向不特定下游（有的没锁），不如把优先级本身讲清。

决策 2 · 上下文纪律作为独立新段，而非塞进 Model 路由段

上下文管理与模型选择是两个正交关注点，混在一段会稀释各自的可执行性；独立成 context-lifecycle-discipline capability 让后续演进独立。

决策 3 · 上下文纪律是软约束，不加 hook 强制

与 ADR 第 3 条"主会话只引导不强制、保留选择权"一致；[1m] 与 compact 时机需人判断，硬闸门会误伤超长合法任务。补偿：subagent 封顶给出可执行的拆分判据（>100 轮 / >150k 先拆阶段）。

Risks / Trade-offs

[软约束不保证生效] → 与 ADR 既有取舍一致，提供明确阈值降低忽略概率。 [snippet 变长] → 净增约 6–8 行，仍在合理范围。 [下游已 fork 旧 snippet 不自动更新] → 模板变更固有特性，PR 合入后下游自行同步。

Migration Plan

纯文档变更，改 template/CLAUDE.md.snippet 一个文件。PR 合入 main 后新 install 项目自动获得；已有项目按各自节奏同步。回滚：单文件 git revert，无状态、无数据迁移。

Open Questions

无。现有 in-force ADR 无需 revisit——本变更在其架构内做描述精化。
