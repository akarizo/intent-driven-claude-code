Why · 01为何而做

2026-10-14 afa cparam-native-subhz-layout attempt 6 停飞，原因是插件缺陷，不是计划问题：

| 时间（UTC） | 事件 | 起点 base | |---|---|---| | 13:41 | S1 执行体甲派发，起点测量 3/16 通过（正常） | e015a343（change 分支尖端） | | 13:49 | 甲收口门禁红：只红 G4（既有测试缺 GWT 注释），实现已提交为 94a317c6 | — | | 13:50 | 同一 attempt 内续派执行体乙，复用甲的 worktree | 94a317c6（甲的提交） | | 13:56–13:58 | 乙三次收口都被 G5 判「在改生产代码之前就已通过」→ S1 blocked → 停飞 | — |

根因：同一 attempt 内的续派动作不带 base（core.ts:206 executorOutcome），编排层复用 worktree 时没有 --base 就以当前 HEAD 为起点（orchestrator.tsx:409）。HEAD 已是首个执行体写好的实现，起点测量全过，G5 必然误判。后果：任何切片只要首个执行体收口门禁红一次，这一片就救不回来。

0.13.0 的 planDefect 第 1 条判据还会把这个症状报成「计划缺陷，把该 scenario 标为护栏」，方向错误。修好起点后这个误报随之消失，判据本身不用改。

跨 attempt 的续接（firstDispatch）已经带上一次门禁的 base；但那条 base 也来自续派执行体的门禁，同样会被本缺陷污染。修在源头，两条路径一起修好。

What · 02变更范围

  • 续派带首个执行体的起点：同一 attempt 内、执行体收口门禁红或未正常收口后的续派动作，带上本片最后一次执行体派发记录的 base；编排层已有的「续接带原 base」分支随之生效：slice-gate base 带 --base <原起点>，起点测量按原起点去重、不再在实现之上重测，续派 dispatch 事件记原起点，收口门禁也以原起点判 G5。
  • 最后一次派发没有 base（旧账本）时行为不变。
  • 插件 0.13.1。
插件：template/plugins/flight/hooks/core.ts（executorOutcome 的续派动作）、.claude-plugin/plugin.json。编排层 hooks/orchestrator.tsx 不改：续接带 base 的分支（:409）已存在，只是此前收不到 base。测试：新增 tests/test_flight_redispatch_base.py；TS 用例追加在 core.test.ts、orchestrator.test.tsx。不在本 change：G1 失败全在 owns 外时不续派、所有停飞交主会话、preflight 查 G4（change flight-halt-continuity）。

Specs · 04行为规范 (Gherkin)

flight-redispatch-base ADDED

Requirement: 同一 attempt 内续派执行体沿用首个执行体的起点

执行体收口门禁红、或未正常收口后补跑门禁仍红，控制面在同一 attempt 内续派执行体时，续派动作 SHALL 带上本片最后一次执行体派发记录的 base；该派发没有 base 时 SHALL 不带（行为同旧版）。编排层复用原 worktree 续派时，SHALL 以该 base 调用 slice-gate base（--base <原起点>），续派的 dispatch 事件 SHALL 记原起点，且 SHALL NOT 在原起点之外再做一次起点测量。

Feature: 起点是「改生产代码之前」的快照；续派者接着前一个执行体的提交干活，G5 仍须以最初的起点判「先红后绿」。

Scenario: redispatch-carries-dispatch-base

  • GIVEN两份账本，waves 只有 [S1]：
  • WHEN对两份账本各求下一批动作
  • THEN甲为续派 S1 执行体，续接原因「执行体未正常收口」、失败项 G4 GWT、base 为 b0
  • AND乙为续派 S1 执行体，续接原因「执行体未正常收口」、失败项 G3 test、base 为 b0

Scenario: redispatch-without-dispatch-base-unchanged

  • GIVENwaves 只有 [S1]；S1 执行体 A 的派发没有 base 字段，A 收口门禁红（failed G4 GWT）后结束，结束后补跑门禁仍红（G4 GWT）
  • WHEN求下一批动作
  • THEN为续派 S1 执行体，续接原因「执行体未正常收口」、失败项 G4 GWT，动作不含 base

Scenario: redispatch-pins-original-base

  • GIVEN/opsx-apply demo 已起飞，waves 只有 [S1]；S1 的执行体 A 在 S1 worktree 派发，起点为 base-flight-demo-S1；A 收口门禁红（G4 GWT）
  • WHENA 结束，控制面续派 S1 的执行体
  • THEN第二次 slice-gate base S1 带 --base base-flight-demo-S1，在 S1 worktree 运行
  • AND续派的执行体在 S1 worktree 派发，其 dispatch 事件的 base 为 base-flight-demo-S1
  • AND账本里 agent 为 dispatch 的起点测量恰一次，base 为 base-flight-demo-S1

Requirement: 插件版本

插件清单 SHALL 声明不低于 0.13.1 的版本。

Scenario: plugin-version-0-13-1

  • GIVEN插件清单 template/plugins/flight/.claude-plugin/plugin.json
  • WHEN解析其 JSON
  • THENversion 按数字逐段比较不低于 0.13.1
