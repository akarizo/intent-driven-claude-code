## 契约

```python
# 标记形状（两段都必须非空，strip 后各 >= 4 字符）
#   <注释符> ceiling: <限制> -> <升级条件或路径>
# 分隔符 "->" 与 "→" 都接受

def ceiling_rows(root, base):
    """扫 base..HEAD 的新增行，返回 (failed, rows)。
    rows 每项 = (rel_path, lineno, limit, upgrade)，供汇总用。"""
```

`cmd_gate` 接线：`failed.extend(v8)`；`rows` 非空 → 追加进 `gate-report.md` 的「天花板」表（表头缺失时创建，形状：`| 时间 | 切片 | 位置 | 限制 | 升级路径 |`）。**只在 `gate` 子命令**，`cmd_final` 不动（design D7）。

判定细节：

1. **只扫新增行**：`git diff --unified=0 <base>..HEAD`，解析 `+++ b/<path>` 取当前文件、`@@ -a,b +c,d @@` 取新文件起始行号，随后每条 `+` 行 lineno 递增。
2. **范围**：排除 `is_doc_or_config(path)` 与 `path.startswith(NON_SOURCE_PREFIX)`。**测试文件不排除**——测试里的半吊子标记同样该被抓。
3. **只匹配行首注释紧跟标记**：`^\s*(?:#|//|--|\*)+\s*ceiling:`（大小写不敏感）。
4. 缺段 → `failed.append("G8 ceiling: %s:%d 缺<限制|升级路径>（期望 `限制 -> 升级条件/路径`）" % (rel, lineno))`。
5. 合规 → 进 `rows`，不进 `failed`。
6. **无标记 → 既不 failed 也不 warnings**（非目标守卫，SC4 锁死）。

## 坑（两条都会真实踩到）

1. ⚠ **自举自触发**：本切片提交的正是 `slice-gate.py`，而它内部会出现 `ceiling:` 字样。因此**判据必须按第 3 条只匹配行首注释紧跟标记**，并且**实现时不得写出 `# ceiling: …` 形状的说明注释**——要举例就写 `# G8 ceiling: …`（`ceiling:` 不紧跟注释符）或放进 docstring 的非行首位置。SC4 有一条 AND 专门锁这个。
2. ⚠ **diff 解析的 `+` 混淆**：`+++ b/<path>` 也以 `+` 开头。必须先判文件头（`+++ ` / `--- ` / `@@ `）再判内容行，否则文件头会被当成新增代码行。
