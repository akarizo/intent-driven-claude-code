# S5 · 命令 / skill / schema 改写

**目标**：命令与 skill 描述飞行流程，命令与同名 skill 同改不漂移；schema 的 tasks 产出切片格式。

## 产物（owns）

### `template/.claude/commands/opsx-apply.md` 与 `skills/openspec-apply-change/SKILL.md`（同改）

步骤：1 选 change（同今日）；2 `openspec-git-discipline`：CWD 在本 change worktree、工件已单独 commit、工作树干净；3 `python3 .claude/hooks/slice-gate.py lint --change-dir openspec/changes/<name>` 得 waves（红则停下报告规划问题，不进实现）；4 `timeline.py record approve`；写 `openspec/changes/<name>/.flight`（含启动时间）；5 启动命名工作流：`Workflow` 工具 `name: "opsx-apply"`，`args: {change, changeDir, hooksDir: ".claude/hooks", waves, useAgentTypes: true}`；若 Workflow 不可用（工具缺失 / `disableWorkflows`）→ 回退：按 waves 逐 wave 用 `Agent` 工具在同一条消息里并行派发 `subagent_type: slice-executor`（多切片 wave 各自 `isolation: worktree`），回报只收 JSON，wave 后派 `integrator`，评审用 `code-reviewer` 并行派发（`run_in_background` 语义：不等），最后一次批量修复与 final；6 收到工作流返回 JSON 后：`timeline.py record apply-done`；`session-decompose.py --session <当前会话 jsonl>`（路径从 `~/.claude/projects/<slug>/` 取最新）打印飞行记录；删除 `.flight`；勾选 tasks.md 中门禁绿的切片；7 **不问**，直接进入 `/pr-ship`（final 未绿或有 blocked 切片 → pr-ship 以 draft 建 PR 并列出）。`--gate=per-task` → 读 `.claude/skills/legacy/openspec-subagent-apply-change/SKILL.md` 并按它执行。暂停例外只有四种：spec 自相矛盾、需破坏性操作、测试环境坏、同一门禁项连续 2 次红。删除 step 6 模式问询与整合审问询、review-log 相关文字。

### `template/.claude/commands/opsx-propose.md` 与 `skills/openspec-propose/SKILL.md`（同改）

- 一次成稿：先并行 `openspec instructions <每个 artifact> --json` 全部读完，再一次性写出全部工件，最后一次 `openspec status`。
- 触发器表：行为变化 → specs（本模板要求必有）；跨模块 / 新依赖 / 数据模型 / 安全性能迁移 → design 写实质内容，否则 design.md 写「触发器未命中，跳过：<理由>」；长期架构承诺 → adr，否则不建；tasks 必需。
- tasks 阶段产出：`slices.json`（结构见 `openspec/changes/<name>/slices.json` 的字段说明 / schema template）、`slices/<S>.md` 切片包、每个 scenario 一个 `xfail(strict)` 骨架放在所属切片 owns 的测试文件、由 slices.json 生成的 `tasks.md`；随后 `slice-gate.py lint`。
- 基线：`slice-gate.py baseline --change-dir …`（跑一次全量测试记录耗时）。
- 渲染：`python3 .claude/hooks/spec_html.py --change-dir …`。
- 收尾：提示用户把工件单独 commit；说明「看 spec.html 飞行计划，运行 /opsx-apply 即批准」。

### `opsx-continue.md` / `openspec-continue-change`、`opsx-verify.md` / `openspec-verify-change`、`opsx-new.md` / `openspec-new-change`

- continue：渲染改调脚本；创建 tasks 时同样产出 slices.json / 切片包 / 骨架。
- verify：改为运行 `slice-gate.py final` + 打印 scenario 映射状态 + 简短 coherence 检查（design 决策被遵循）；不再要求让用户选 change（可推断则用）；删水位线分支。
- new：渲染相关文字对齐即可。

### `template/.claude/commands/pr-ship.md`

- 保留前置检查、变更梳理、预合并冲突检查、push、创建 PR。
- 删除：commit 方式问询（未提交改动直接以中文 conventional commit 提交，`git add` 只加相关文件）、文案 Accept、PR 正文 Accept、逐 finding 问询、是否复审问询。
- 评审：派一个 `code-reviewer`，模式 `full`，输入 = PR diff 命令 + `openspec/changes/<name>/gate-report.md` + `evidence.log` 摘要 + 「不重跑测试套件」；报告贴 PR 评论（保留签名与深度声明：改为「门禁：G1–G7 结果 / final ok」）。CRITICAL/HIGH：主会话直接修、commit、push、派 `follow-up` 复核，至多 2 轮；仍有阻断 → 停下交人。MEDIUM/LOW 只贴评论。收尾允许一次 AskUserQuestion（是否要人工再看）或直接结束。
- 删除水位线 / review-log / 三模式判定表。

### `skills/openspec-git-discipline/SKILL.md`

- Worktree Isolation 节增加 carve-out：wave 内并行切片的临时 worktree 由 Workflow / Agent 运行时创建（`worktree.baseRef: head`），其 commit 由 integrator 以 SHA 合回 change 分支，属本地实现 commit，不 push / 不 merge main；清理由运行时负责。

### `template/openspec/schemas/intent-driven/schema.yaml` 与 `templates/tasks.md`

- tasks.instruction 改写：产出 slices.json + 切片包 + 骨架 + 生成的 tasks.md；切片规则（1–9 片、深度 ≤ 3、同 wave 所有权不相交、owns ≤ 12 条、每片 verify）；`- [ ]` 仍必需。`templates/tasks.md` 改为切片格式示例（含 `deps:` / `verify:` 后缀）。`requires` 不改。
- design.instruction 加触发器与「跳过声明」写法。

### `tests/test_template_docs.py`（新）

静态断言上述文本要求（关键短语存在 / 不存在、AskUserQuestion 计数、schema yaml 可解析且 tasks instruction 含关键词）。
