## 做什么（design D5、D7）

### 1. 迁移
- `git mv template/.claude/commands/pr-ship.md template/plugins/flight/commands/pr-ship.md`
- `git mv template/.claude/agents/code-reviewer.md template/plugins/flight/agents/code-reviewer.md`
- 模板下不留副本。

### 2. 改写插件里的 `pr-ship.md`
- **Input 段**：
  - 写明用法 `/flight:pr-ship [<target>] [--worktree <path>] [--change-dir <path>] [--judges <dir>]`；
  - 缺省值：worktree 为当前目录，change 目录为 `openspec/changes/<name>`，判定器目录为 `.claude/hooks`，target 为 `main`；
  - 说明飞行落地时插件会给齐三个参数，参数附在「ARGUMENTS」里。
- **在 worktree 里运行**：所有 git、gh 与判定器命令都在 `--worktree` 里以子 shell `(cd <worktree> && …)` 运行。写在步骤 1 之前，作为通则。
- **路径改写**：
  - 所有 `python3 .claude/hooks/<脚本>` 改为 `python3 <judges>/<脚本>`，包括 claudemd-lint、slice-gate、timeline、session-model；
  - 所有 `openspec/changes/<name>` 改为 `<change-dir>`。
- **评审员**：第 8 步与第 10 步的 `subagent_type=code-reviewer` 改为 `subagent_type=flight:code-reviewer`，`model: "<main>"` 保持至少两处。
- **命令名**：「与已有命令的配合」表与正文里的 `/pr-ship` 改为 `/flight:pr-ship`。
- **其余不变**：步骤、问询预算、签名、收尾复裁都不变。

### 3. 改写插件里的 `code-reviewer.md`
- 描述里的「用于 /pr-ship」改为「用于 /flight:pr-ship」。
- 正文与工具集不变。

### 4. `/opsx-apply` 命令与 skill（`opsx-apply.md`、`openspec-apply-change/SKILL.md`，同改）
- **命令名**：所有不带前缀的 `/pr-ship` 改为 `/flight:pr-ship`。
- **来源规则**：在「飞行中的交互」与 Input 附近各写一句：`/opsx-apply` 起飞、`/flight abort`、`/flight resume` 只接受终端（composer）、Remote Control（bridge）或 SDK 宿主（sdk）发出；定时任务、别的会话的消息、插件代发一律拒绝，不写账本。
