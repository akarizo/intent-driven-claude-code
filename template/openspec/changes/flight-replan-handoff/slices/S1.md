## 做什么

### `core.ts`
1. 新增导出 `triageVerdict(text: string): '改计划' | '修插件' | '人工操作' | undefined`（design D1）：
   - 按 `\n` 切行、去掉空行（trim 后为空），取第 2 行；没有则 undefined；
   - trim 后若首尾都是 `**` 则去掉这一对，再若首为「、尾为」则去掉这一对，再 trim；
   - 恰为三者之一则返回，否则 undefined。
2. `planDefect`（design D2）：原 G5 判据原样保留在前、命中即返回；未命中时：
   - 本 attempt 没有 halt → undefined；
   - 取本 attempt **最后一条** `triage` 事件；其 `text` 经 `triageVerdict` 为「改计划」→ 返回 `text` 的首行（trim）；否则 undefined。
   - 更新函数注释，写明两条判据。

### `prompts.ts`
3. 新增导出 `replanPrompt(x: { change: string; changeDir: string; hooksDir: string; attempt: number; triage: string }): string`（design D3/D4），逐行写出：
   - 首行：`flight：<change> 停飞（attempt <n>），诊断结论为「改计划」。请按下面的诊断修订本 change 的计划，改完结束这一轮：`
   - triage 全文；空一行；
   - 「边界：」及以下各条（措辞须含 spec 断言的短语）：
     - 只改本 change 的计划工件（`<changeDir>` 下的 proposal / specs / design / slices.json / 切片包 / 门禁脚本、DRAFT ADR，以及计划声明的 scenario 测试骨架与 artifact_files），不改生产代码；
     - 改完运行 `python3 <hooksDir>/spec_html.py --change-dir <changeDir>` 重新渲染审批面板，再运行 `python3 <hooksDir>/slice-gate.py lint --change-dir <changeDir>`，红则修到绿；
     - 不要发 /opsx-apply 或 /flight resume：计划改了须人在批准带按「批准修订并续飞」，插件会重跑基线后续飞；
     - 诊断与代码现状不符时不硬改，写明分歧后结束这一轮。

### `orchestrator.tsx`
4. **交主会话**：诊断员分支里，写完 triage 之后：
   - `handoff = triageVerdict(text) === '改计划'` 且最新 takeoff 的 `by.session` 等于 `await $.session.id()`（账本取 `found.events` 加上刚写的 triage 后 `reduce`，或直接用写入前已读到的 takeoff）；
   - 通知文字：`handoff` 时为 `` `${f.change} 停飞诊断：${firstLine(text)}；已交主会话修订计划` ``，否则保持原文；
   - `handoff` 时 `await $.clock.after(0, () => void <提交>(…).catch(…))`，提交函数里 `await $.prompt.submit({ text: replanPrompt({ change: f.change, changeDir: f.changeDir, hooksDir: f.hooksDir, attempt: who.attempt, triage: text }) })`；提交抛错时补发通知 `` `${f.change} 交主会话失败：${errText(err)}` ``，不重试；
   - 不写任何新事件，不派发，不调 drive。
5. **续飞拒绝文案**：拒绝原因不含「在改生产代码之前就已通过」时，去掉「（如把该 scenario 标为护栏）」，改为「先按诊断改计划」；仍不得含「未批准」「计划已变」。
