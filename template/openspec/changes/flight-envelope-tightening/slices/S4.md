## 前置
S1 已合回 `envelope.ts` 的新函数与可选参数，S3 已合回 `io.ts` 的 `markPending` / `ownership`。先读 `slices/_interfaces.md`。

## 做什么
`template/plugins/flight/hooks/orchestrator.tsx`（`$` 只在这个文件里用）：

1. **`flyingWho`**：改用 `ownership`。
   - 登记中返回 `{ pending: true }`；
   - 正式归属的返回值里加上 `mainTree`（取 `flights.get(change).mainTree`）。
2. **`tool.call`**（Write / Edit / NotebookEdit / Bash）：
   - **登记中的 agent**：一律拒绝，理由「flight：派发登记中，稍后重试」。
   - **飞行 agent 的写入**：照旧 `writeVerdict`。
   - **飞行 agent 的 Bash**：
     - 先 `bashVerdict(role, command, worktree, mainTree)`，拒绝就返回 deny；
     - 通过后返回 `next({ ...e, command: inWorktree(command, worktree) })`，这是 D1。
3. **`tool.check`**：
   - 登记中 → 原样返回引擎判定；
   - `inEnvelope` 里 Read / Grep / Glob 改用 `readUpgradable(tool, input, worktree, mainTree)`；
   - Bash 改用 `bashUpgradable(role, command, commands, worktree, mainTree)`。
4. **`ctx.spawn`**：`$.agent.spawn` 拿到 agentId 后，立刻 `markPending(agentId, f.change)`，再返回。
5. **`takeoff`**：在起飞守卫之后、写账本之前，运行 `git --version`。解析出的主、次版本低于 2.38，或解析不出来 → 回复 `flight：需要 git ≥ 2.38（合回用 merge-tree --write-tree），当前 <输出首行>，不起飞`，不写账本。
6. **测试世界清理**：`orchestrator.test.tsx` 的世界里删掉失效的 `--is-ancestor` 分支和 `integrated` 注释里对它的描述；`integrated` 只靠 rev-parse 与 `log --merges` 模拟，现有用例必须保持绿。
7. **版本**：`template/plugins/flight/.claude-plugin/plugin.json` 的 version 改为 `0.3.1`。
