## 做什么（design D6 接线、D8、D9、D13）

### `template/plugins/flight/hooks/orchestrator.tsx`
- **飞行 agent 的 Bash 写入**：`envelopeVerdict` 对 Bash 先走 `bashVerdict`，通过后再走 S4 的 `bashWritesVerdict(who, command)`。
- **意图门禁接线**（design D6）：
  - 在 `tool.call`（Write / Edit / NotebookEdit / Bash）里：
    - 主会话：`mainSessionVerdict` 通过后再做意图判定；
    - 非飞行 agent：`flyingWho` 为 undefined 时做意图判定；
    - 飞行 agent：不做。
  - 判定：`toolTargets(tool, e, cwd)` → `intentVerdict(io, hooksDir, cwd, targets)`。cwd 取 `$.session.cwd()`。
  - hooksDir：由 `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` 的父目录交给 `judgesDir`；按会话缓存；求不出就放行。
  - 现有 `.catch` 的兜底语义不变：飞行 agent 拒，其余放行。
- **perform 查停飞**（design D8）：派发执行体 / 解冲突 agent 的 `ctx.spawn` 之前，以及三种合回之前，调用 S6 的 `stoppedNow(io, f)`；结果非 undefined 就直接返回，不追加事件。
- **SubagentStop diag**（design D9）：
  - 给 `on('classic.SubagentStop', …)` 加 `.catch(handler)`；
  - handler 用 `next.error` 的 kind / message / budget 与 `e.agent_id` 构造 `ev.diag`（S5），经 `appendEvent` 追加，attempt 取该 agent 的 attempt，取不到为 0；
  - 再 `return next(e)`；追加失败吞掉；找不到该 agent 的飞行时只 `return next(e)`。
- **面板刷新**：`driveNow` 执行完 halt 或 land 动作后，读最新账本并 `refreshPanel`。

### `template/plugins/flight/hooks/io.ts`
- `EVENTS` 增加 `diag: { attempt: ATTEMPT, where: NONEMPTY, error: STR }`；`EVENT_TYPES` 随之含 diag，共 14 种。

### 测试
- **`orchestrator.test.tsx` 与 `flight.test.tsx` 的世界**：
  - 主会话 / 非飞行 agent 的写入现在会运行 `git rev-parse --git-common-dir` 与 `intent-gate.py check`，世界要应答，默认 allow；
  - `ledger.py events` 的应答加上 `diag`。
- **`io.test.ts`**：`event-types-exported` 改为 14 种。
- **`versions.test.ts`**：凡硬编码事件全集的地方加上 diag。
- **SubagentStop 失败**：测试里让收口门禁的 `io.run` 抛错，观察 `.catch` 的效果。若 2.1.295 / 2.1.296 的测试引擎不运行 `.catch` 处理器，不要另造绕法：停下来，在收口回答里如实说明。
