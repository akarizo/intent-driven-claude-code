## 做什么

### `orchestrator.tsx`（design D6 / D8）
- **注册 ship 工具**：在 session.start（带 cwd matcher 的那个 hook）里注册 `{ ...SHIP_TOOL, isDeferred: false }`，失败时忽略并写一行注释说明后果（模型调不到 ship，PR 停在 draft）。
- **ship 工具的 `tool.call` hook**（`mcp__flight__ship`）：
  - 带 agentId → `{ deny: 'flight：ship 只接受主会话调用' }`，飞行 agent 也一样；
  - 输入不是 `{ change: 非空字符串, pr: 非空字符串 }` → deny；
  - 否则 `locate($, change)`：出错时 deny 并附原因；
  - 再 `readLedger`：出错时 deny；
  - 最后 `shipPr(ctxOf($), f, reduce(events), pr)`，原样返回其结果；
  - 异常兜底返回 `{ deny: 'flight：ship 处理失败' }`，写法同 measure 的 hook。
- **修复轮合回**（`perform` 里 `a.kind === 'merge'` 且 via 为 `fix` 的分支）：
  - slice 取 `a.slice`；
  - 修复体分支取 `lastDispatch(state, a.slice, 'fixer', A)` 的 branch；
  - 调 `mergeFix(io, f, note, branch, a.slice)`，merge 事件的 slice 用 `a.slice`。
  - note 照旧是 `blocking=<n>`。
- **per-task 指引**：
  - 模块级记一个布尔量：session.start 里 `opsx-apply` 注册成功时为 true；
  - `command.run`（opsx-apply）遇到 `--gate=per-task` 时：为 true 就直接回复，回复含「本项目没有 /opsx-apply 命令文件」与 `.claude/skills/legacy/openspec-subagent-apply-change/SKILL.md`，提示让模型读这份 skill 按 legacy 逐 task 守门执行；为 false 时照旧 `next(e)`。
  - `.catch` 分支的透传口径同步。
- **ship 工具的不变量注释**：在 HOST_ORIGINS 附近一句话写明三项：模型可调用的工具恰为三个；ship 只认主会话；ship 只写 ship 事件。
