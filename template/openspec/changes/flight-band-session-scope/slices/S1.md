# S1 · 批准带会话认领：写入与人发命令即认领，refresh 只评估已认领的 change

无依赖，与 S2 并行。改插件与它的测试，orchestrator 只加两个 `export`。

## 先读

  - `candidatesIn`（约第 96 行）、`refresh`（约第 229 行）、`refreshQuietly`（约第 392 行）；
  - `register`（约第 477 行）：`session.start`（只重置 `band`）、`turn.complete`（主循环、批准带启用时刷新）、账本守卫 `tool.call` hook（约第 595–597 行，带 `.catch`）；最后一行是 `registerOrchestrator(on)`。
- `template/plugins/flight/hooks/intent.ts`：`toolTargets(tool, e, cwd)` 是纯函数，给出 Write / Edit / NotebookEdit / Bash 的写入目标（绝对路径）。只读的 Bash（`cat`、`grep`）与 Monitor 给空数组。
- `template/plugins/flight/hooks/orchestrator.tsx`：`HOST_ORIGINS`（约第 55 行）与 `originOf`（约第 70 行），目前未导出。
- `template/plugins/flight/types/index.d.ts`：`PluginState.flight`。
- **hook 嵌套顺序**（引擎类型文档 `on` 的说明）：同一插件的注册按顺序嵌套，先注册的在外层。编排器对 `/opsx-apply`、`/flight` 自己作答、不调 `next`，所以新的 `command.run` hook 必须写在 `registerOrchestrator(on)` 之前。
- **`$` 不出文件**：register 只从 orchestrator import 值与闭包，不传 `$`。

## 省轮次（包络与工具的已知限制）
- 改文件一律用 Edit / Write，路径写字面绝对路径；不要用 `sed -i`、`python3 -c` 改文件，不要用 heredoc，不要把输出重定向到 worktree 之外。
- 命令里带 `$` 或反引号时，包络可能判为「无法判定」；查找用 `grep -n -e … <字面路径>`。没有 Grep 工具，用 Bash 的 grep。
- `claude plugin test template/plugins/flight` 跑全量约 4 秒，接 `2>&1 | grep -E "^\(fail\)| pass| fail"` 过滤。

## 测试世界的已知事实（`flight.test.tsx`）
- `useWorld` / `demoWorld`：主 worktree `/repo`，change 在 `/repo/template/openspec/changes/<name>`；`session.id` 为 `sess-1`，`session.cwd` 为 `/repo`；`TURN` 常量配 `$.turn.complete(TURN)` 模拟主会话一轮结束。
- `$.tool.call({ tool, ... })` 经过插件的全部 `tool.call` hook，再到测试在插件之下挂的应答。**账本守卫那组用例（约第 502–580 行、第 701、722 行）在用例内自己挂 Write / Edit / NotebookEdit / Bash 应答，并断言命令是否到达**。不要在 `useWorld` 里全局挂这几种工具的应答，否则可能截走它们（测试里 `on` 的嵌套是否也是先注册在外层，先实测）。认领 helper 只在需要它的用例里挂自己的应答。
- 主会话的 Write / Bash 写入会经编排器的意图门禁：先跑 `git -C /repo rev-parse --path-format=absolute --git-common-dir`。测试世界现在把它记进 `log.git`，再抛「unexpected git」。门禁出错后照样放行，但 `writes(log)` 会多出一项 `-C`。在 `process.run` 里对这条命令以失败作答（门禁找不到判定器即放行），且不记入 `log.git`。
- `$.command.run({ command: 'flight', args: 'status demo', origin: { kind: 'composer' } } as never)` 已在 `tools-and-commands-invariant` 一组里用过。插件来源写 `origin: { kind: 'plugin', name: 'other' }`。
- 起飞守卫缺省以 exit 3「未批准」作答；`log.fpDirs` 记 `plan_fp.py` 的 `--change-dir`。

## 做什么（design D1–D5）

### `template/plugins/flight/types/index.d.ts`
1. `PluginState.flight` 加 `claims: string[]`，写一行注释：本会话认领的 change 名（写入与人发的命令），只在本进程内有效。

### `template/plugins/flight/hooks/orchestrator.tsx`
2. 给 `HOST_ORIGINS` 与 `originOf` 加 `export`，别的不动。

### `template/plugins/flight/hooks/register.tsx`
3. **认领集合**（D1）：
   - `const claims = atom({ plugin: 'flight', key: 'claims' } as const, [] as string[])`；
   - 本文件内的 `claim($, names)`：过滤掉空串与 `archive`，只有出现新名字时才 `update`，返回集合是否变大；
   - `session.start` 不动 `claims`。
4. **写入认领**（D2）：
   - 在账本守卫 hook 的放行分支里，`next(e)` 之前 `await` 认领：
     - 目标 = `toolTargets(String(e.tool), e, await $.session.cwd())`；
     - 每个目标按 `/\/openspec\/changes\/([^/]+)(\/|$)/` 取名；
   - 不重绘；
   - hook 改为 async；`.catch` 保持现有语义：认领出错时 `next.called` 为假，不碰账本就照常 `next(e)`。
5. **命令认领**（D3）：
   - 新 hook `on('command.run', { command: /^(opsx-.+|flight)$/ }, …)`，放在 `registerOrchestrator(on)` 之前；
   - `HOST_ORIGINS.includes(originOf(e) ?? '')` 为假 → `return next(e)`；
   - 为真 → 参数按空白切词，不以 `-` 开头的都 `claim`；
   - `const r = await next(e)`；集合变大且 `!(await read($, band)).isDisabled` 时 `await refreshQuietly($)`；`return r`。
   - 认领自身出错不得吞掉命令：未调 `next` 时照常 `next(e)`。
6. **refresh 只评估已认领**（D4）：
   - `refresh` 读 `claims`，交给 `candidatesIn`；
   - `candidatesIn` 对不在集合里的目录名直接 `continue`，在 `fs.exists(spec.html)` 之前；
   - 其余（`dedupe`、`evaluate`、进行中叠加）不变。

### `template/plugins/flight/tests/flight.test.tsx`
7. **新用例**（4 个，见测量协议第 1 条）：
   - `write-claims-change` 与 `read-does-not-claim` 在用例内挂自己的 Write / Bash 应答；
   - `band-hides-unclaimed` 断言 `log.fpDirs` 里没有 demo 的目录；
   - `command-claims-change` 不调 `$.turn.complete`。
8. **现有用例补认领**（D5，只改 Given、不改断言）：
   - 加 helper：对给定的 change 名逐个用 Write 写 `<该 change 所在 worktree 的 changes 目录>/<name>/proposal.md`，自带 Write 应答；
   - 在 `$.session.start(START)` 之前调用。这时批准带未启用，认领不触发重绘，启动时那次刷新与改前一致，`plan_fp` 的调用序号不变；
   - 认领该用例 Given 里出现的全部 change 名（例如 `band-ignores-finished-and-foreign-copies` 认领 `old` 与 `demo`），保持原断言的含义。

### `template/plugins/flight/tests/orchestrator.test.tsx`
9. 它也加载整个插件：人发 `/opsx-apply` 时，命令认领会在返回后多刷新一次批准带。先跑全量；若有用例因此变红，只调它的 Given（例如先认领，或该用例不需要启动会话），不改断言。都没变红就不改这个文件。
