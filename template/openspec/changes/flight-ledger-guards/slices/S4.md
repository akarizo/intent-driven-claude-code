## 做什么（design D6）

### `template/plugins/flight/hooks/envelope.ts`
- **新增 `bashWriteTargets(command, cwd)`**：识别范围、排除项、unresolved 的口径见 design D6；签名见 `slices/_interfaces.md`。
  - **切分**：复用 `denySegments`、`words` 的分段与 cd / pushd 跟踪（`cdArg`、`resolveDir`）。
  - **重定向识别**：要用保留引号信息的原始词。`shellWord` 去引号之后，`'>'` 与 `>` 分不开，所以先在原始词上判断是不是重定向，再对目标词去引号。
  - **heredoc**：`<<` / `<<-` 之后的定界符不是写入目标，heredoc 的正文也不解析。同一命令里 `cat <<'EOF' > k.md` 的 `k.md` 仍是目标。
  - **空字符串参数**（如 `sed -i ''` 的 `''`）忽略。
  - **返回值**：经 `normalizePath` 规整成绝对路径，去重，保持出现顺序。
- **新增 `bashWritesVerdict(who, command)`**：
  - 对 `bashWriteTargets(command, who.worktree)` 的每个 target 调 `writeVerdict(who, target)`，第一处拒绝即返回；
  - unresolved 非空时返回 `{deny: 'flight：写入目标无法静态判定：<词>，请改用字面路径'}`。
- 现有导出的签名与行为一律不变。`bashVerdict` 不调用新函数，两者由 S8 在 `orchestrator.tsx` 串起来。

### 新文件 `template/plugins/flight/hooks/intent.ts`
- 导出 `toolTargets`、`intentVerdict`，签名与行为见 `slices/_interfaces.md` 与 design D6。
- **模块边界**：只经 `Io`，不 import claude-code 的运行时值，不调用 `$`。可 import `envelope.ts` 的 `bashWriteTargets`、`normalizePath`，以及 `core.ts` / `io.ts` 的类型。
- **check 的 argv**：恰为 `['python3', `${hooksDir}/intent-gate.py`, 'check', '--cwd', cwd, ...targets]`。不经 `judge()`，因为它要一个 `Flight`，而这里不在飞行里。
