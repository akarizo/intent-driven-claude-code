## 做什么

### `core.ts`（design D4）
1. `closing()` 预合并分支里，最新 premerge 有冲突时，把 S2 的直接停飞换成：
   - 该 premerge 之后没有 `slice: 'premerge'` 的 resolver 派发 → `{ kind: 'dispatch', role: 'resolver', slice: 'premerge', conflicts }`；
   - resolver 未结束 → `[]`；
   - 该 premerge 之后有 `slice: 'premerge'` 的 merge：ok → `[{ kind: 'final' }]`；失败 → `halt('premerge', '解冲突后快进失败：…；人工合并 <ref> 并提交后发 /flight resume <change>')`；
   - resolver 已结束、最后一条收口门禁绿 → `{ kind: 'merge', slice: 'premerge', via: 'resolve' }`；
   - 已结束但门禁红或没有结论 → `halt('premerge', '预合并冲突未解开：<冲突文件>；人工在 change worktree 合并 <ref> 并提交后发 /flight resume <change>')`。

### `land.ts` / `prompts.ts`
2. `prepareResolve(io, f, 'premerge', { branch: <ref>, attempt })` 已支持「合并任意分支」，确认可直接用；合并提交说明在 `slice === 'premerge'` 时写 `merge <ref> into <f.branch>`。
3. `afterMerge`：`slice === 'premerge'` 时不刷新接口摘要，直接返回 `{ ok: true, commit }`。
4. `prompts.ts` 新增 `premergeResolverPrompt({ change, changeDir, ref, conflicts })`：说明是把目标分支合进 change 分支时冲突，两边意图都保留，只解列出的文件，解完 `git add` 再 `git commit --no-edit`，不改其它文件；`prompts.test.ts` 补一条快照式断言。

### `orchestrator.tsx`
5. **派发**：`a.role === 'resolver' && a.slice === 'premerge'` 走单独分支：取最新 premerge 的 `ref`，`prepareResolve`，不调 `sliceBase`，用 `premergeResolverPrompt`，dispatch 事件照常记 worktree 与 branch。
6. **收口**：`classic.SubagentStop` 对 `role === 'resolver' && slice === 'premerge'` 不跑切片门禁，交给 `onLandingStop`（在 `landing.tsx` 里跑 `runFinal`，cwd 为解冲突 worktree），其后同 `stopVerdict`。
7. **合回**：merge via resolve 时 `owns('premerge')` 为空数组；land 的 `merged` 列表排除 `premerge`（`landing.tsx`）。
8. **`/flight recheck <change>`**（design D5）：只认 `HOST_ORIGINS`；`FLIGHT_USAGE` 补上；定位、读账本；最新 attempt 未落地 → 「flight：<change> 尚未落地：在飞或停飞时用 /flight resume」；已落地 → 跑 `judge(io, f, 'slice-gate', ['ship', '--change-dir', f.changeDir], f.changeTree)`，解析 JSON 的 `reasons`，没有以「final 过期」或「全量评审过期」开头的项 → 「flight：<change> 无需重验：final 与全量评审仍新鲜」；否则走普通起飞（非 resume）并返回起飞回复。
9. **计划缺陷拒绝续飞**（design D6）：`takeoff()` 里算出计划指纹之后、写 takeoff 之前，`opts.resume && planDefect(state) !== undefined && fp === state.takeoff?.fp` → 返回「flight：<change> 计划需修订：<原因首行>。计划不改，续飞仍会在同一处停飞；先改计划（如把该 scenario 标为护栏），再在批准带按「批准修订并续飞」」；不写任何事件。文字不得含「未批准」「计划已变」。
10. **改名行出路**（design D8 · D2）：第 705 行的拒绝信息里，`dirty.others` 全是含 ` -> ` 的改名行时，用改名专用的出路替换「列进 artifact_files」那条；混有其他路径时两条都给。首行保持「flight：工作区不干净，不起飞（工件之外的未提交改动）：」不变（起飞待命靠它归类）。
