## 做什么（design D11、D12）

### `template/plugins/flight/commands/pr-ship.md`
- 删掉 `timeline.py record pr-open`。原文写「两种模式都记」，改为：
  - 飞行模式的 PR 打开时间由 ship 事件记入账本；
  - 飞行外不再记录。
  - 随后的 `timeline.py report` 照旧。
- 飞行模式「ship 工具返回后另外提交 timeline」那一步删掉：记录在落地时已从账本生成并提交。
- 第 7 步飞行模式补 GitLab 分支：origin 为 GitLab 时用 `glab mr create --draft …` 建 MR，不调用 ship 工具，报告「只支持 GitHub，MR 保持 draft，交人决定」。
- Output Summary：「已自动修复」「评论中列出（未自动修）」两行标明「飞行外」才填写，飞行模式写「见 ship 评论」，与「review 轮数」一行的写法一致。
- 步骤编号保持 1–11 不变。

### `template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md`（同改，禁漂移）
- 删掉「首次起飞时插件以 `takeoff-gate.py` 的批准证据原文记 `timeline.py record approve` 并提交 `chore(flight): approve`」。改为：takeoff 事件写入账本；落地时由插件从账本生成 `timeline.md` 与 `gate-report.md`，与 `review-findings.json` 一起提交。须含「从账本生成」字样。
- 写明意图门禁：
  - 插件在场时，对主会话与非飞行 agent 的 Write、Edit、Bash 写法调用 `intent-gate.py check`；
  - 飞行 agent 按 owns 限写，Bash 同样适用；
  - 插件缺席时由 classic hook 兜底。
  - 须含「Bash」字样。
- 写明 apply 上下文只认目标所在 worktree 的 change（design D5）。
- 「起飞只接受人发出的命令」这半句改为「起飞的命令来源限制见下文「飞行中的交互」」（change 1 评审 LOW）。「**来源规则**」仍各只出现一次。

### `README.md` 与 `docs/WORKFLOW_zh.md`
- 记录文件的生成方式：飞行中判定器不写记录，落地时从账本生成。须含「从账本生成」。
- 意图门禁的范围：插件覆盖 Bash，classic 兜底。
- 已有讲 `slice-gate start` / `record`、`.openspec-slice` 的段落，按新行为改写。

### 仓库根 `CLAUDE.md`
- 只改铁律 11 中「`<main>` 由 `.claude/hooks/session-model.py` 判定」这半句，改为「`<main>` 飞行中由插件经 `$.session.model()` 判定、飞行外由 `.claude/hooks/session-model.py` 判定」。其余字一律不动。
