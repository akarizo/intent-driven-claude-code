## 契约

```
start S --change-dir DIR [--base REF] [--expect-branch BRANCH]
  给了 --expect-branch：在读标记 / 写标记之前
    tip = git rev-parse --verify BRANCH^{commit}          失败 → G0「G0 base: 分支 BRANCH 不存在」
    git merge-base --is-ancestor tip HEAD                  非 0 → G0「G0 base: HEAD <h10> 不是分支 BRANCH（<t10>）的后代——worktree 不是从 change 分支最新 commit 分叉」
  G0 → print(json.dumps({"slice": S, "ok": False, "commit": "", "failed": [msg], "warnings": [], "summary": "基点校验未通过"}, ensure_ascii=False))
       sys.exit(1)；不写标记、不记 timeline
  通过 → 后续逻辑一字不改
```

```
ship：final["commit"] != head[:10] 时
  BOOKKEEPING = ("timeline.md", "gate-report.md", "evidence.log", "review-findings.json", "tasks.md")
  fresh = merge-base --is-ancestor <final> HEAD 成功
          且 diff --name-only <final> HEAD 的每一项都等于 f"{change_rel}/{name}"（name ∈ BOOKKEEPING）
  任一 git 调用失败 → fresh = False
  not fresh → reasons 照旧追加「final 过期：记录 %s，HEAD %s」（文案不变，既有测试锚定它）
```

## 坑

- ⚠ G0 的祖先判定要放在同片 resume 分支之前（重试的 worktree 里标记可能已存在）。
- ⚠ `merge-base --is-ancestor` 用退出码表达结论，而 `git()` 会把非 0 变成异常：要区分「不是祖先」（exit 1）与真正的错误，或直接 `subprocess.run` 看 returncode。
- ⚠ 既有 `test_ship_draft_when_final_stale` 用 `"0000000000"` 当 final commit：它不存在，必须仍判过期（git 报错 → 不新鲜）。
- ⚠ 两条守卫测试（`test_ship_stale_after_code_change` / `test_ship_stale_after_plan_change`）现在就绿、不带 xfail，实现后也必须绿——它们锁住白名单的边界。
- ⚠ 不改 `cmd_gate` / `cmd_final` / `record` 的行为；G0 不写 gate-report 行。
