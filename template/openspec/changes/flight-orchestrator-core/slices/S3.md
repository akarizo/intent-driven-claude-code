# S3 · 随插件发布的 agent 类型与提示词纯函数

## 做什么
1. 新建 `template/plugins/flight/agents/{executor,reviewer,fixer}.md`。插件目录的 `agents/*.md` 会被声明为 `flight:<name>`（实测 X8）。
   - frontmatter 按 spec `flight-agent-types` 写：
     - **executor / fixer**：`tools: Read, Edit, Write, Bash, Grep, Glob`、`effort: high`、`maxTurns: 40`；executor 另有 `skills:` 列表含 `test-driven-development`；
     - **reviewer**：`tools: Read, Grep, Glob, Bash, mcp__flight__submit_findings`、`effort: high`；
     - 三份都**不写 `model`**（派发时显式指定；spawn 的 model 优先于类型的 model，实测 X1）。
   - 正文改写自仓库现有的 `template/.claude/agents/slice-executor.md` 与 `code-reviewer.md`（先读这两份），按新协议修改：
     - **executor**：cwd 是控制面为本切片建的 worktree；只做一个切片，按切片包 TDD，只写 owns 内文件，每切片一个 commit；**门禁由控制面在你收口时运行**，红了会把失败项告诉你、接着修；不要运行 `slice-gate.py` 的 start / gate / record（正文里不得出现这三个命令文本）；不 push / merge / 切分支 / 改 `openspec/` 工件；最后一行简述做了什么（不再返回门禁 JSON）。
     - **fixer**：两种任务，提示词会说明是哪种。①批量修复：逐条修 finding，每条先有失败测试，逐条 commit（`fix:` 前缀）；收口时控制面跑全量 final。②解合回冲突：当前 worktree 处于 `git merge` 冲突中，只解冲突文件，保持两边意图，`git add` 后 `git commit --no-edit`；收口时控制面跑该切片门禁。两种都写明门禁由控制面运行，并遵守同样的禁止项。
     - **reviewer**：只读评审一个切片的合回 commit；不重跑测试套件、至多 1 次定向抽查；**必须调用 `submit_findings` 提交**（severity / file / line / summary / fix），没有问题也要提交空列表；提交后一行结束。
2. 新建 `template/plugins/flight/hooks/prompts.ts`（纯函数，不 import `claude-code` 运行时值，不调用 `$`），签名写死（S7 / S8 调用）：
```ts
export function executorPrompt(x: { change: string; changeDir: string; slice: string; continuation?: { reason: string; failed: string[] } }): string
export function reviewerPrompt(x: { change: string; changeDir: string; slice: string; commit: string }): string
export function resolverPrompt(x: { change: string; changeDir: string; slice: string; conflicts: string[] }): string
export function fixerPrompt(x: { change: string; changeDir: string; findings: { severity: string; file: string; line: number; summary: string; fix: string }[] }): string
```
   - 切片包路径一律写成 `${changeDir}/slices/${slice}.md`（相对 worktree 根）。
   - executor 首次与续接都含「门禁由控制面在你收口时运行」与 owns 纪律；续接另含「未正常收口」或给定的 reason、以及 failed 每一项，并要求先 `git status` / `git log` 看清已完成的部分、在其上继续。
   - reviewer 含 commit、切片包路径与 `submit_findings`；resolver 含每个冲突文件与 `git commit --no-edit`；fixer 含每条 finding 的 summary。
