## 做什么（design D1、D3、D5；spec `flight-armed-takeoff` 的前三条要求）

新建 `template/plugins/flight/hooks/armed.ts`，按 `_interfaces.md` 导出全部类型、常量与函数：
- **`classifyRefusal(text)`**：按 spec 的字样表自上而下取第一条命中，认不出的归 `human`。字样取自 `orchestrator.tsx` 的 `takeoff()`（第 598 行起）与 slice-gate 的原文。例如：
  - `flight：slice-gate preflight 未通过：基线仍在跑（已 N 分钟，上次全量约 …）：等它结束再起飞`；
  - `flight：起飞守卫未通过：takeoff-gate: 未批准：…` / `…计划已变，需重新批准…`。
- **git status 本身失败**：回复为 `flight：工作区不干净，不起飞：` 紧跟换行；这与「未提交的只有本 change 的工件」「（工件之外的未提交改动）」两种不同，注意区分。
- **`nextStep`**：
  - 先判过期与 human / human-key；
  - 再在 `refused` 事件上判预算与 transientAgain；
  - 最后按 spec 的「各类待命在什么事件上推进」给出 retry / submit / wait；
  - 其余组合为 `{ do: 'wait' }`。
- **`modelPrompt`**：必须含 spec 列出的四段文字。可以多写一句「插件会在这一轮结束后自动重试」。
- **`armedLine`**：示例 `flight · 起飞待命 demo · slice-gate preflight 未通过：基线仍在跑（重试 0/3，剩 30 分钟）`，剩余分钟向上取整。
- **`humanText`**：跨会话的拒绝里有 `--takeover` 字样，原文首行照抄即可，不用另写做法。

全部为纯函数：不 import `claude-code` 的运行时值，不读时钟（`now` 由调用方传入）。
