## 做什么

### 1. `template/plugins/flight/hooks/core.ts`（design D8）
`next()` 里的 `firstDispatch`，门禁结论 `g` 现在是：

```ts
last(evs.filter(e => e.ev === 'gate' && e.slice === s && e.seq > prev.seq))
```

再加一个条件：`(e.agent === prev.agent || e.agent === REGATE)`。续接说明的 `failed` 与 `base` 都来自这个 `g`，随之收窄。`beforeExecutor` 不改。

### 2. `template/plugins/flight/hooks/prompts.ts`（design D4）
`executorPrompt` 里「写好测试后、改生产代码前，调用 `measure` …」这一行之后，加一行：

> 某个目标在改生产代码前测量就已通过（且不是护栏）时，不得改坏生产代码来造红：照实收口，写明是哪个 scenario。

### 3. `template/plugins/flight/hooks/measure.ts`（design D3）
- `MeasureJson` 增加 `guards: string[]`。解析时用 `strs(j.guards)`，缺省为 `[]`；S1 会让 `slice-gate measure` 输出这个字段。
- `report()`：对每个满足以下三个条件的目标，追加一行。
  - 条件：状态为 PASSED；不在 `m.guards` 里；本次 `m.source` 为空。
  - 文字：`注意：<t> 在改生产代码之前就已通过：若它描述的行为在 base 上本已成立，这是计划错误（应标为护栏）；不要改坏生产代码造红，照实收口说明`。
  - 护栏目标不追加。

### 4. 版本
`template/plugins/flight/.claude-plugin/plugin.json` 的 `version` 改为 `0.4.2`。
