# S1 · slice-gate：baseline 预检 + preflight + G2 基线差分 + start 幂等

**目标**：把环境事实的判定移到起飞前（baseline / preflight），让 G2 只为本 change 新引入的问题判红，让重试不丢区间与红计数。设计：design D1–D3，及 D4 里 `start --base` / `gate.base` 两处契约。

**deps: 无**（wave 1，与 S2、S4 并行）

## 契约

```python
BASELINE = "gate-baseline.json"
VERIFY_TOOL_RE = re.compile(r"\b(tsc|typecheck|eslint|rustfmt|clippy|ruff|mypy|flake8|golangci)\b")
ANSI_RE = re.compile(r"\x1b\[[0-9;]*[A-Za-z]")

def normalize_lines(text) -> list[str]        # 去 ANSI → \d+ → "#" → strip → 丢空行，保序去重
def plan_sha(data) -> str                      # sha1(json.dumps([gate.test, gate.lint, gate.typecheck, [[id, verify]...]], ensure_ascii=False, sort_keys=True))
def load_baseline(change_dir) -> dict | None
def gate_cmd_verdict(kind, cmd, root, baseline) -> (failed_item | None, warning_item | None)
def cmd_preflight(args)                        # lint_plan → 基线四项校验 → 打印 waves
```

- **baseline**：跑 `gate.test`（计时，写回 `full_suite_sec`）→ `gate.lint` / `gate.typecheck`（记 `{"exit", "lines": normalize_lines(out)}`，未配置记 `null`）→ 每片 `verify`（记 `{"exit"}`）→ `reasons`（`全量测试在基线上红（exit N）` / `<S> verify 在基线上红（exit N）：命令不可运行或含既有错误`）→ 写 `gate-baseline.json`（`commit`=HEAD 全长、`at`、`plan_sha`（在写回 slices.json 之后算）、`ok`、`reasons`、`test`、`lint`、`typecheck`、`verify`）→ timeline `baseline exit N, Ns` 备注追加 `ok/red` → stdout JSON 带 `ok` 与 `reasons` → 退出 0/1 按 `ok`。
- **preflight**：`lint_plan` 错 → die；缺文件 → die(`缺基线：先运行 slice-gate.py baseline`)；`ok` 假 → die 列 `reasons`；`plan_sha` 不等 → die(`基线过期：gate / verify 改动后需重跑 baseline`)；`merge-base --is-ancestor` 不成立 → die(`基线 commit 不在当前分支历史`)；通过 → `print(json.dumps(waves))`。`main()` 注册 `preflight`，参数只有 `--change-dir`。
- **lint 新规则**：`VERIFY_TOOL_RE.search(verify)` → `verify: <S> 含 typecheck/lint 工具，verify 只跑测试；typecheck 放 gate.typecheck、lint 放 gate.lint（门禁按基线差分）`。
- **G2 差分**（`gate` 与 `final` 共用 `gate_cmd_verdict`）：`rc == 0` → 无；无基线或基线里该 kind 为 `null` → `failed` `G2 <kind>: exit N\n<尾 6 行>`（现文本不变）；有基线 → `new = [l for l in normalize_lines(out) if l not in set(baseline[kind]["lines"])]`；`new` 空 → `warnings` `G2 <kind>: exit N，输出与基线一致（既有 K 行已按基线排除）`；非空 → `failed` `G2 <kind>: exit N（新增 M 行）\n` + 前 6 条。
- **start**：加 `--base`；读标记，若 `marker["slice"] == args.slice` → 不改标记，timeline `slice-start`, 备注 `"%s (resume)"`，打印既有标记，退出 0；否则 `base = args.base or HEAD`。
- **gate**：`result["base"] = base`。

## 坑

1. ⚠ `git merge-base --is-ancestor` 非 0 会让 `git()` 抛 `RuntimeError`，用 `subprocess.run` 直接判 returncode。
2. ⚠ 自举：本仓库自己的 `gate.lint` 是 `compileall`，输出为空；测试要用假命令（如 `sh -c 'printf "a.ts(186,41): error TS2339 x\n"; exit 1'`）构造输出。
3. ⚠ `test_baseline_*` 的 `gate.test` 用 `true` / `false`，不要真跑 pytest（子进程里再起 pytest 慢且脆）。
4. ⚠ 既有 24 个测试一条不得回归；`plan()` helper 的默认 `gate` 含 `"lint": None`，保持。
