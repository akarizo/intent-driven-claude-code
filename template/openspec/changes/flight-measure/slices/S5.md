# S5 · io.ts：在飞账本读失败判不出、measure 事件写入校验、导出事件类型表

## 做什么（只改 `template/plugins/flight/hooks/io.ts`）

### 1. measure 事件写入前校验
`EVENTS` 加入 `measure`，与 `ledger.py`（S1 同时实现）用同一张字段表：
- `attempt`：`ATTEMPT`；
- `slice`、`agent`、`base`：`NONEMPTY`；
- `commit`：`STR`；
- `outcomes`：数组，每项恰两项字符串，第二项属于 `PASSED / FAILED / ERROR / SKIPPED / XFAIL / XPASS / MISSING`；
- `changed`、`source`：`STRS`。

描述沿用现有格式，`eventProblem` 返回 `measure 的 <字段> <描述>`。

### 2. 导出事件类型表
`export const EVENT_TYPES: readonly string[]`，即 `EVENTS` 的全部键。S7 起飞核对判定器时会用到。

### 3. 归属判不出（fail-closed）
- **新返回值**：`ownership` 的返回类型增加 `{ unknown: true; change: string; error: string }`。
- **何时返回它**：扫描本进程登记的在飞飞行（`flights` 里、且 `active.has(change)`）的账本时，`readLedger` 返回 `{ error }`，并且其余地方也没找到该 agent → 返回「判不出」，`change` 为读失败的那个 change，`error` 为原因。
- **不缓存**：「判不出」不写进 `misses`，也不写进 `owners`；下一次查询重新读账本。
- **其余 change 照旧跳过**：`refs/flight/*` 里不在 `flights` 中的 change 读失败，仍按「没找到」处理。一条损坏的旧账本不得让所有非飞行 agent 判不出。
- **`flightOfAgent` 对外签名与行为不变**：读失败仍返回 undefined。需要的话，抽一个内部函数，由 `ownership` 与 `flightOfAgent` 共用。
- **`ownerOf`**：对「判不出」返回 undefined，与登记中一样。
