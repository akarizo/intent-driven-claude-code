## 做什么

### `io.ts`（design D1）
1. `EVENTS` 加 `shelve: { fp: FP }`，注释「人在批准带按「搁置」（DRAFT-approval-revocable-by-shelve）」。`EVENT_TYPES` 随之含 `shelve`。

### `types/index.d.ts`
2. `FlightItem` 新增 `ledgerDir: string`（读账本用的判定器目录：主检出的，没有时同 `hooksDir`），带注释。

### `register.tsx`
3. **读账本的判定器**（design D2）：
   - `refresh` 里先对主 worktree 求一次 `hooksDirOf($, main)`；
   - `evaluate` 收到它，`ledgerDir = mainDir !== '' ? mainDir : hooksDir`，写进 item；
   - 所有 `ledger.py` 调用（`approved`、`isAlreadyApproved` 的 `show`、`flightOf` 交给 `readLedger` / `stoppedNow` / `lastHaltKind` 的 hooksDir、搁置前的 `events`）改用 `ledgerDir`；
   - `fingerprint`（`plan_fp.py`）与 `depsOf` 里的 `slice-gate.py baseline` 仍用 `item.hooksDir`。
4. **evaluate 识别搁置**（design D3）：账本可读之后、停飞判定之前，读一次事件（`readLedger`），取最后一条 approve / shelve；是 shelve 且 fp == 当前指纹 → `return undefined`。
5. **isAlreadyApproved**：`ev.ev === 'shelve'` 与 takeoff 一样清空 `last`。
6. **写事件**：把 `appendApprove` 改成按事件类型参数化（如 `appendDecision($, item, ev: 'approve' | 'shelve', surface)`），commit 说明写 `flight: <ev> <change> <fp 前 8 位>`；原调用处改为传 `'approve'`。
7. **绘制**（顶部那一项可操作 = `problem === ''` 且无 `busy`）：
   - 主按钮之后：`<Button key={'shelve:' + change + ':' + fp} label="搁置" variant="secondary" dimColor onPress={() => undefined} />`（真正的处理在 `ui.press` hook）；
   - 再加一行 `<Text dimColor>搁置：这份计划不再显示、不能起飞；改动计划后重新出现</Text>`。
8. **按键**：
   - `ui.press` 的 matcher 正则加 `shelve`；`PRESS_KEY` 的模式组加 `shelve`；
   - `mode === 'shelve'` 走单独分支，顺序照 design D3 第 1–6 步：`inFlight` → 找项（不比较 `item.mode`）→ 重算指纹 → `ledger.py events` 核对 → `serial` 内追加 shelve → toast 并刷新；
   - toast 文字：
     - 判定器不认识：`flight：判定器（<ledgerDir>）不认识 shelve，未搁置：先把主检出更新到与插件同一版本`；
     - 写失败：`flight：<change> 账本写入失败（重试 3 次），未搁置`；
     - 成功：`flight：已搁置 <change>（指纹 <前 8 位>）：不再显示、不能起飞；改动计划后会重新出现`。
9. **逐行列出工件**（design D4）：
   - `artifactCount` 改为返回路径列表，模块级 `artifacts` 存列表；
   - 说明行「按下会提交本 change 的 N 个工件并直接起飞」与「批准修订并续飞」的说明保持原文；
   - 其下逐行 `<Text dimColor>` 列出至多 5 个路径，超过 5 个时第 6 行为「…另 K 个」。
