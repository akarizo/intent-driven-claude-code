# S8 · 铁律 3、新 ADR、执行体定义与提示词、评审参考材料写明测量协议

## 做什么

### 1. 铁律 3（两处同改）
根 `CLAUDE.md` 与 `template/CLAUDE.md.snippet` 的铁律 3 改为：
> TDD 与留痕：生产代码前必有先失败的测试；测试由可信方运行并留痕（飞行中 = 控制面测量写入账本；回退路径 = hook 写 evidence.log），不接受自述。

snippet 的措辞可以按它原有的简写风格压缩，但必须同时含「可信方」「账本」「不接受自述」，并且不再出现「测试运行由 hook 留痕」。snippet 仍须 ≤ 8KB。

### 2. 新 ADR `template/openspec/adr/DRAFT-flight-measure-protocol.md`
- **格式**：参照同目录的 `DRAFT-flight-envelope-tightening.md`。
- **头部**：`Status: accepted`、Date 2026-10-10。关联写明：
  - 细化 `DRAFT-gate-evidence-not-self-reported` 第 1 条，真值源加入账本的 measure 事件；
  - 在飞行路径取代 `DRAFT-apply-as-flight` 第 4 条中「测试运行由 hook 留痕」一句；
  - 两份旧 ADR 原文不动。
- **Decision 写明**：
  - 测量工具由执行体请求、控制面执行；
  - 起点测量与豁免；
  - G5 账本判据的四条（不满足即判红）；
  - 门禁的 base 与证据模式由控制面给出；
  - Workflow 回退路径仍用 evidence.log，3c 删除。
- **Consequences 写明**：
  - 判红的摩擦；
  - 非 pytest 目标无法测量；
  - 跨版本续飞需作废重飞。

### 3. 执行体：`template/plugins/flight/agents/executor.md`
- **工具白名单**：frontmatter 的 `tools` 加上 `mcp__flight__measure`。
- **TDD 条**改写为测量协议：
  1. 先解锁骨架、把断言写实；
  2. **调用 `measure` 工具看它红**；
  3. 再写最小实现。
  - 补充：自己跑的 verify 只用来快速反馈，不算证据。
  - 补充：测量结果说「这次红不能作为先红证据」时，说明已经先改了生产代码。
- **删掉**「不加 `cd && ` 前缀（cwd 已是仓库根）」整句，以及「测试运行由 hook 自动留痕，不要贴 RED / GREEN 日志」中的「由 hook 自动留痕」。「不要贴日志」的意思保留。

### 4. 执行体提示词：`template/plugins/flight/hooks/prompts.ts`
`executorPrompt` 在 TDD 那一行之后加一行，写明：
- 写好测试后、改生产代码前，调用 `measure` 工具让控制面测一次并看它红；
- 自己跑的测试不算证据。

`prompts.test.ts` 新增 TS 测试 `executor-prompt-states-measure-protocol`，断言提示词含「measure」与「不算证据」。现有提示词用例保持绿，写死了旧文本的按新文本更新。
