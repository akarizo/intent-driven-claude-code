## 契约

```text
plan_fp.py
  PLAN_FILES = proposal.md · design.md · slices.json · specs/**/spec.md · slices/*.md（除 slices/_interfaces.md）
  plan_fingerprint(change_dir) -> str            64 位小写十六进制
    · 目录不存在 / 一个计划文件都没有 → raise PlanError(原因)
    · 文本按 UTF-8 解码，CRLF → LF
    · slices.json：json.loads → 删 gate.full_suite_sec（缺则忽略）→ json.dumps(sort_keys=True, ensure_ascii=False, separators=(",", ":"))
    · 行 = "<相对路径(用 /)>\t<sha256(规范化内容)>"，按路径排序，"\n".join 后取 sha256
  CLI：plan_fp.py --change-dir DIR [--short]
    exit 0：stdout 一行指纹（--short 为前 8 位）
    exit 2：PlanError → stderr 一行原因
spec_html.py
  compute_meta_chips 末尾追加 '<span class="chip" data-state="done">计划指纹 <前8位></span>'；PlanError 时不加，不影响渲染
```

## 坑

- ⚠ 「执行记录」以**白名单**判定：只读 PLAN_FILES，其余文件一律不碰（测试会往 change 目录写 8 类记录文件）。
- ⚠ `slices/_interfaces.md` 由 integrator 在飞行中写，必须排除，否则每个 wave 合回都会让批准失效。
- ⚠ 不要复用 `slice-gate.py` 的 `plan_sha`：它只覆盖 gate 命令与 verify，是基线过期判据（design D1）。
- ⚠ 每条测试解锁时去掉对应 `@XF` / `xfail(strict=True)` 标记；`tests/test_spec_html.py` 已有 6 条用例必须继续通过。
