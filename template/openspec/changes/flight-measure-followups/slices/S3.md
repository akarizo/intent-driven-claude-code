## 做什么

### 1. `template/plugins/flight/hooks/io.ts`
新增导出：
```ts
export async function freshWorktree(io: Io, f: Flight, name: string, attempt: number): Promise<{ path: string; branch: string } | { error: string }>
```
- `worktreePath(f, name)` 不存在 → `git worktree add -b flight/<change>/<name> <path> <f.branch>`（cwd 为 `f.mainTree`，与 `ensureWorktree` 相同）；
- 已存在 → 改用 `name = <name>-a<attempt>` 做同样的事；
- 两者都已存在 → `{ error: 'worktree 已存在：<path>' }`，不执行 `worktree add`。

`ensureWorktree` 保留不动，供续接复用旧现场时使用。

### 2. `template/plugins/flight/hooks/land.ts`
- `mergeSlice(io, f, slice, gate, owns, branch?)`：`branch` 缺省为 `flight/<change>/<slice>`。`integrated`、`directCommits`、`emptyMerge` 与 `mergeNoFf` 一律用这个 `branch`，函数内不再出现写死的拼法。
- `prepareResolve(io, f, slice, x?: { branch?: string; attempt?: number })`：
  - 解冲突 worktree 用 `freshWorktree` 的同一规则命名，名字是 `<slice>-resolve`，已存在就另起 `<slice>-resolve-a<attempt>`；
  - 在其中合并 `x.branch`，缺省为 `flight/<change>/<slice>`；
  - 返回值增加 `branch`（解冲突分支）。
  - 可以直接调用 io 的 `freshWorktree`，注意 `freshWorktree` 基于 `f.branch` 切出，与原来的做法一致。
- `finishResolve(io, f, slice, gate, owns, resolve?: { path: string; branch: string })`：用传入的解冲突 worktree 与分支；缺省为旧的 `resolvePath` / `resolveBranch`。
- `mergeFix(io, f, note, branch?)`：`branch` 缺省为 `flight/<change>/fix`。
