## 做什么（design D6）

### 1. `template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md`（同改，禁漂移）
- **删除**：
  - `--engine=workflow`（命令约 :7、:27；skill 约 :14、:36）；
  - 流程摘要里「启动切片工作流（…回退并行 Agent 派发）」一类说法（命令约 :22；skill 约 :29）；
  - 路由表里 slice-executor 与 integrator 两行（命令约 :30-36；skill 约 :39-45）；
  - 旧引擎的 step 0–7（命令约 :38-102；skill 约 :47-101），含 `.flight`、session-decompose、`--expect-models`、Workflow args 与回退段。
- **保留并整理**：描述插件接管后的行为。
  - 起飞检查：批准指纹（takeoff-gate）、工作区与「授权提交」、lint / preflight、版本核对、跨会话与 `--takeover`。
  - 派发与收口门禁、续飞另起 worktree、落地交 `/pr-ship`。
  - 现有段落里已有的这些内容原样保留，只删旧引擎部分。
- **新增一段（标题「模型读到本命令即停飞」）**：
  - 插件接管时本命令不会到达模型；模型读到这里，说明 flight 插件缺席、未加载或版本不符。
  - 必须停下报告，不得改用其他方式实现本 change。
  - 给出指引：`claude plugin marketplace add akarizo/intent-driven-claude-code --scope project`、`claude plugin install flight@intent-driven -s project`、`/reload-plugins`。
- **`--gate=per-task`**：说明保留（插件原样交给模型，转读 legacy skill）。
- **路由表**：只留插件角色：
  - `flight:executor` / `flight:reviewer` / `flight:fixer` = 会话主模型；
  - 机械动作由插件执行，零 token。

### 2. `template/.claude/skills/openspec-git-discipline/SKILL.md`
飞行 carve-out（约 :41-47）改写为插件的做法：
- 每个切片的 worktree 在 `.claude/worktrees/flight-<change>-<S>`，分支 `flight/<change>/<S>`，基于 change 分支尖端；
- 续飞时同名已存在就另起 `<S>-a<attempt>`，旧的保留；
- 由控制面（flight 插件）合回 change 分支、提交飞行记录；
- 执行体只在自己的 worktree 里提交。

不再出现 Workflow、Agent 回退、`opsx-apply.js`、integrator。

### 3. `template/.claude/commands/pr-ship.md` 与 `template/.claude/agents/code-reviewer.md`
- **改写 evidence.log 的定位**：「Workflow 回退路径：…evidence.log」改为「飞行外（主会话修复等）：evidence.log」。涉及 pr-ship 约 :138、:216-217，code-reviewer 约 :18、:31。
- **code-reviewer 的描述**（约 :3）：不再说「用于飞行模式的每切片评审」（那由插件的 `flight:reviewer` 负责），改为「`/pr-ship` 的 PR 评审与复核」。
- 两处都保留 `evidence.log` 字样。
