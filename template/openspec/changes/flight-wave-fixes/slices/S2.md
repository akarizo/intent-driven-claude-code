## 契约

```js
// 头注释：args 列表里 expectHead → branch；说明 branch = change 分支名（起飞时 git branch --show-current），start 据此做基点祖先校验
const branch = args.branch || null
const startCmd = (s, base) => `python3 ${hooksDir}/slice-gate.py start ${s} --change-dir ${changeDir}`
  + (base ? ` --base ${base}` : '') + (branch ? ` --expect-branch ${branch}` : '')
// executorPrompt(s, retryOf)：
//   retryOf && retryOf.commit → 第零步 cherry-pick（原文不变）
//   否则 → 没有第零步（删去 expectHead 比对）
//   start 那一行之后补一句：start 非 0 退出（G0 基点校验未通过）→ 不做任何改动，把它打印的 JSON 原样作为最终输出
const MERGE = {
  type: 'object',
  required: ['ok', 'failed'],
  properties: {
    ok: { type: 'boolean' },
    merged: { type: 'array', items: { type: 'string' } },
    failed: { type: 'array', items: { type: 'string' } },
    warnings: { type: 'array', items: { type: 'string' } },
  },
}
// 合回派发：schema: MERGE；prompt 末尾加「本次只合回，不要运行第 3 项（全量门禁 final）——后续 wave 的 scenario 还没解锁，
//   现在跑必然红。返回 JSON {ok, merged, failed, warnings}」
// integ.ok 判定与 blocked.push 的形状不变
```

- `slice-executor.md` 开工第 2 条补：prompt 给的 start 可能带 `--expect-branch <branch>`（基点校验）；start 非 0 退出 → 不做任何改动，把 start 打印的 JSON 原样作为最终输出（此时没有标记，stop-gate 不会拦收口）。
- `integrator.md` 第 3 项首句：仅当 prompt 点名第 3 项时运行（Finalize 会点名；wave 合回不点名，也不要自己跑——后续 wave 的 scenario 还没解锁，跑了必然红）。命令本身不变。

## 坑

- ⚠ `run_workflow` helper 把脚本正文包进 async 函数、mock 掉 `agent / parallel / phase / log` 后执行：脚本必须保持「顶层 `export const meta` + 正文 + 末尾 `return`」的形状，不要改成 import / 模块导出。
- ⚠ 不改 GATE schema 的字段（执行体与 Finalize 仍用它）；MERGE 只给合回派发用。
- ⚠ Fix 阶段 prompt 里的 `slice-gate.py start fix` 是字面量，不走 `startCmd`，保持原样（fix 在 change worktree 里跑）。
