# S1 · 插件起飞：授权提交时只提交本 change 的工件；插件补丁版本 +1

先读 `design.md` 的 D1–D5。

## 做什么
1. **`template/plugins/flight/hooks/land.ts`**：
   - 新增并导出纯函数 `classifyDirty(paths: readonly string[], x: { changeDir: string; scenarioFiles: readonly string[] }): { records: string[]; artifacts: string[]; others: string[] }`，规则见 D2；
   - 新增并导出 `commitArtifacts(io: Io, f: Flight, paths: readonly string[]): Promise<string | undefined>`：`git add -- <绝对路径…>`，再 `git commit -m "docs(openspec): <change> 工件（起飞时经「授权提交」提交）" -- <绝对路径…>`；失败返回原因，成功返回 undefined。写法参照同文件的 `commitRecords`。
2. **`template/plugins/flight/hooks/orchestrator.tsx` 的 `takeoff()`**：
   - **参数**（D1）：`authorized` = 有一个词恰为「授权提交」，或者 change 名候选以「授权提交」结尾且去掉后缀后非空（此时用去掉后缀的名字）；「授权提交」本身不能当成 change 名；
   - **工作区**（D2–D4）：替换现有的 `dirty` 处理。读 `${tree.path}/${changeDir}/slices.json` 的 `scenario_tests`，取 `::` 之前的部分作为 `scenarioFiles`，然后 `classifyDirty`：
     - `others` 非空 → 返回 D4 的「工件之外」拒绝信息，只列 `others`；
     - `artifacts` 非空且未授权 → 返回 D4 的提示信息（含 `/opsx-apply <change> 授权提交`）；
     - 否则：`records` 非空 → 沿用 `commitRecords`；`artifacts` 非空 → `commitArtifacts`；任一失败 → 拒绝并写明原因；
   - 提交必须在起飞守卫（`takeoff-gate`）通过之后，现有顺序已经保证，不要挪动守卫；
   - 起飞成功的回复里，有工件提交时追加一行「已提交工件 N 个文件」。
3. **`template/plugins/flight/.claude-plugin/plugin.json`**：version 在你的 worktree 当前值上升一个补丁号。
