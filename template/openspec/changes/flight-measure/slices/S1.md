# S1 · 判定器：measure 子命令、measure 事件与 events 子命令、严格 XPASS

## 做什么

### 1. `template/.claude/hooks/ledger.py`
- **新增事件类型 `measure`**：在 `EVENTS` 里加入，除公共字段外必需：
  - `attempt`：正整数；
  - `slice`、`agent`、`base`：非空字符串；
  - `commit`：字符串；
  - `outcomes`：数组，每项是恰好两项的字符串数组，第二项属于 `PASSED / FAILED / ERROR / SKIPPED / XFAIL / XPASS / MISSING`；
  - `changed`、`source`：字符串数组。
  - 允许表外的额外字段，例如 `unmeasurable`。
  - 错误描述沿用现有格式：`measure 的 <字段> <描述>`。
- **新增子命令 `events`**：`ledger.py events` 按字母序每行打印一个 `EVENTS` 的键，退出 0。不需要 `--change-dir`。注意现有 argparse 把 `--change-dir` 设为 required，要改成只对 show / approved / verify 必需。

### 2. `template/.claude/hooks/slice-gate.py`
- **G7 的 pytest 插件（`G7_PLUGIN` 字符串）**：在 `report.when == "call"` 分支里，`report.failed` 且 `report.longrepr` 是以 `[XPASS(strict)]` 开头的字符串 → 记为 `XPASS`。
  - 依据：pytest 8.4.2 `_pytest/skipping.py` 对严格 xfail 意外通过设 `outcome = "failed"`、`longrepr = "[XPASS(strict)] " + reason`，且不设 `wasxfail`。
  - G7 只认 PASSED，因此 G7 行为不变。
- **新增子命令 `measure <S> --change-dir D [--base B]`**：
  - **base**：取 `--base`，否则取切片标记里的 base；两者都没有 → `die`。
  - **目标**：本片 `scenarios` 经 `scenario_tests` 映射出的目标。以 `.py` 文件开头的（`rel.endswith(".py")`）是可测目标，其余放进 `unmeasurable`。
  - **运行**：对可测目标调用一次现有的 `_pytest_outcomes(root, targets, gate)`，复用 G7 的运行方式与超时。
  - **状态合并**：每个目标取 nodeid 等于它、或以 `目标[` 开头的全部结果，按 ERROR > FAILED > XPASS > XFAIL > SKIPPED > PASSED 取最差者；没有结果记 `MISSING`。
  - **`outcomes` 的顺序**：按本片 `scenarios` 的顺序排列，骨架断言依赖这个顺序。
  - **改动清单**：`changed` 是 `changed_files(root, base)` 的已提交与未提交之并，排序后输出。`source` 是其中「非测试、非文档 / 配置、不在 change 目录内、不是切片标记」的文件，与 `cmd_gate` 里 `source` 的分类完全相同；抽成一个小函数让两处共用。
  - **输出**：打印 JSON `{"slice", "base", "commit", "outcomes", "unmeasurable", "changed", "source", "tail"}`。`commit` 为 `git rev-parse HEAD`；`tail` 为 pytest 输出的最后 40 行，用现有的 `_tail` 或同义实现。
  - **退出码**：跑完退出 0，不论红绿。超时或 pytest 起不来时，打印 `{"slice", "error": "<原因>"}` 并退出 1。
  - **只读**：不写 timeline、不写 gate-report、不碰标记。
