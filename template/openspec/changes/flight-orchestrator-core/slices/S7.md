# S7 · 编排接线：接管 /opsx-apply、收口现跑门禁、结束兜底、合回与解冲突、状态行、类型隐藏

## 做什么
把 S5 留下的空壳 `template/plugins/flight/hooks/orchestrator.tsx` 换成实现，导出不变：`registerOrchestrator(on: On): void`。它注册下面这些 hook，并实现 `drive`。

### 1. 类型隐藏
`agent.offer`：`e.agent` 为 `flight:executor` / `flight:reviewer` / `flight:fixer` → `{ isOffered: false }`；其他 → `next(e)`。

### 2. 接管 `/opsx-apply`（`command.run`，matcher `{ command: 'opsx-apply' }`）
1. **解析参数**：`<name> [--model=<alias>] [--engine=workflow] [--gate=per-task]`。含 `--engine=workflow` 或 `--gate=per-task` → `return next(e)`（交给命令文档），不写账本。
2. **版本下限**：`$.session.version()` 低于 2.1.295 或读取失败 → 回复原因，不起飞（下限常量与批准带一致）。
3. **定位**：
   - `trees(io, await $.session.cwd())`，第一项为主 worktree；
   - change worktree 是分支为 `worktree-<name>` 的那一项（没有参数时，取会话 cwd 所在 worktree 的分支名去掉 `worktree-` 前缀）；
   - changeDir 取 `template/openspec/changes/<name>` 与 `openspec/changes/<name>` 中存在的那个；
   - hooksDir 取 `judgesDir(io, 主 worktree)`。
   
   任一找不到 → 回复原因。
4. **起飞检查**，依次执行，任一不过即回复原因，不写账本、不派发：
   - `judge takeoff-gate --change-dir <change 目录绝对路径>`：非 0 → 回复 stderr 原文与 `<change 目录>/spec.html` 的绝对路径。
   - `git -C <changeTree> status --porcelain` 非空 → 回复「工作区不干净」与输出。
   - `judge slice-gate lint` 与 `judge slice-gate preflight --change-dir <changeDir>`：cwd 均为 changeTree；非 0 → 回复 stderr；waves 取 preflight 的 stdout（JSON）。
   - **主模型**：有 `--model=` 用它；否则 `io.run(['python3', <hooksDir>/session-model.py], { env: { CLAUDE_CODE_SESSION_ID: await $.session.id() } })`。非 0 → 回复「判不出主模型，用 --model= 指定」。
5. **正在飞**：读账本。最新 takeoff 的 attempt 未 land / halt，且 `$.agent.list()` 里有该 attempt 派发的 agent 状态为 pending / running / waiting → 回复「正在飞」，不重复起飞。
6. **起飞**：
   1. 组装 `Flight`（session 取 `$.session.id()`），登记到 `flights`；
   2. attempt = 已有 takeoff 数 + 1；
   3. attempt 为 1 时：`judge timeline record approve --change-dir <changeDir> --note "<takeoff-gate 的 stdout>"`，再只 add timeline.md、提交 `chore(flight): approve`；
   4. 追加 takeoff 事件，fp 取 `judge plan_fp --change-dir <change 目录绝对路径>` 的 stdout；
   5. `await drive($, f)`；
   6. 回复一行：`✈ 起飞 <change>：<切片数> 片 / <wave 数> 个 wave · 主模型 <model> · attempt <n>`。

### 3. drive（模块内 Promise 队列串行；每轮重读账本）
1. `readLedger` 出错 → 停飞（交给 `runLandingAction` 的 halt）。
2. 否则：
   - `state = reduce(events)`；
   - `plan = { waves: takeoff.waves, deps: slices.json 里每片的 deps }`；
   - `fpNow` 来自 plan_fp；
   - `actions = next(state, plan, fpNow)`。
3. 逐个执行这批动作，再进入下一轮；某一轮没有动作即停（再加一个 50 轮的保险上限）。各动作的执行方式：

| 动作 | 执行 |
|---|---|
| dispatch executor | `ensureWorktree(f, S)`。新建的：在其中 `judge slice-gate start S --change-dir <changeDir> --expect-branch <f.branch>`；续接（已存在）：start 不带 `--expect-branch`，因为 change 分支可能已前移。start 非 0 → 记 blocked（infra，含 stdout）。成功 → `spawnAgent(role executor, executorPrompt(...))`，记 dispatch；被拒 → 记 blocked（infra）。 |
| dispatch resolver | `prepareResolve(io, f, S)`；在解冲突 worktree 里 `judge slice-gate start S --change-dir`；`spawnAgent(role resolver, resolverPrompt({ conflicts }))`，记 dispatch（worktree 为解冲突 worktree）。 |
| gate | 在该 agent 的 worktree 里 `judge slice-gate gate S --change-dir <changeDir>`（timeout 600000），解析 JSON 后记 gate 事件（含 agent）。stdout 不是 JSON → 按红记，failed 为 `G? 门禁输出无法解析：<stderr 首行>`。 |
| merge via branch | 门禁 JSON 取本 attempt 该切片最后一条 ok 的 gate 事件；owns 取 slices.json；`mergeSlice`。ok → 记 merge（ok）；否则记 merge（ok:false，failed 原样，含 `conflict: <文件>` 项）。 |
| merge via resolve | `finishResolve` 后同上。 |
| merge via fix | `mergeFix(io, f, 'blocking=<n>')` 后记 merge（slice 为 fix）。 |
| blocked | 记 blocked 事件。 |
| dispatch reviewer / fixer、final、land、halt | `await runLandingAction($, f, action)`（S8 实现；本切片的工作区里它是空壳）。 |

4. 每轮结束更新状态行：`$.ui.status('✈ <change> · W<当前 wave 序号>/<wave 数> · 运行 <已派发未结束的 agent 数> · 阻断 <本 attempt 阻断数>')`。

### 4. 收口门禁（`classic.SubagentStop`）
1. `flightOfAgent(io, e.agent_id)`：找不到，或 role 不是 executor / resolver → `next(e)`。
2. 在 dispatch 记录的 worktree 里跑 `slice-gate gate S`（同上解析），记 gate 事件。
3. `stopVerdict(reduce(events), agent, gate)`：
   - block → `return { ...(await next(e)), block: text }`；
   - accept → `next(e)`。

### 5. 结束（`turn.complete`）
- `e.agentId` 为空 → `next(e)`。
- `flightOfAgent` 找到时（任何 role）：`const r = await next(e)`；记 ended（reason 为 `e.reason`，model 为 `e.usage?.model ?? null`）；`await drive($, f)`；`return r`。

### 测试世界（参考 `tests/flight.test.tsx` 的写法，实测 X6 的配方）
- **process.run**（`e = { argv, init }`）按 argv 分派，答复包 `{ value: { exitCode, stdout, stderr, isStdoutTruncated: false, isStderrTruncated: false } }`：
  - `git worktree list --porcelain` → 主 /repo + /repo/.worktrees/demo（分支 worktree-demo）；
  - `takeoff-gate.py` / `slice-gate.py lint|preflight|start|gate` / `plan_fp.py` / `session-model.py` / `timeline.py` → 预设；
  - **账本**：`git hash-object -w --stdin` 的 stdin 就是事件 JSON，世界把它存进数组；`ledger.py show` 按顺序逐行返回；`update-ref` 返回 0。
- **派发**：底层收到的是 Agent 工具参数（`subagent_type`、`model`、`cwd`、`prompt`），答复 `{ model, agentId, result: { status: 'async_launched', agentId, description, prompt, outputFile: '/dev/null' } }`。
- **其他**：
  - `classic.SubagentStop` 底层答 `{}`；`turn.complete` 底层答 `{ text: '' }`；
  - `$.classic.SubagentStop({...})` 与 `$.turn.complete({...})` 由测试直接触发；
  - `fs.*`、`session.*`、`ui.status`、`agent.list` 按需要 mock。
