## 做什么（design D1、D2、D6）
1. **opsx-apply 命令与 skill**：在「起飞待命」一节末尾加一条（两份同字），要求含「唤醒轮」与「只回复「收到」」：
   > - **唤醒轮**：插件只能在处理外部事件的 hook 里派发 agent，否则 agent 的工具调用会绕过包络与 measure。所以定时到点的重试（基线仍在跑的 60 秒检查、偶发失败的 10 秒重试）与看门狗停飞后的诊断员，都不直接派发：条件满足时，插件以自己的名义发一轮只回复「收到」的对话，这一轮结束时再起飞或派发。等待类先零 token 检查条件，没满足就不发。
2. **README.md 与 docs/WORKFLOW_zh.md**：在「起飞待命」那一条末尾补一句，含「唤醒轮」，例如：「定时到点的重试与看门狗诊断经唤醒轮：插件发一轮只回复「收到」的对话，这一轮结束时再起飞或派发」。
3. **opsx-propose 命令**：description 改为「一次成稿：一步生成完整 change 的全部工件（含切片计划），收尾把 spec.html 交给人类审批，人在批准带按「批准起飞」即按下即起飞」。或者任何含「按下即起飞」、不含「自己发 /opsx-apply」的等价写法。
4. **`template/plugins/flight/.claude-plugin/plugin.json`**：version 改为 `0.10.2`。description 保留起飞待命、按下即起飞、自愈、看门狗、续飞，可以补「唤醒轮」。
5. **`tests/test_armed_followups_docs.py`**（加强，不是 scenario）：`test_plugin_version_0_10_1` 改为断言版本「不低于 0.10.1」，逐段数字比较；函数名与 Given / When / Then 注释同步改。照上一个 change 改 `test_armed_docs.py` 的先例。
