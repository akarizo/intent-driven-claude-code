## 做什么

### 1. `orchestrator.tsx` · 派发执行体（`perform` 里 `dispatch` 且 role 为 executor）
- **续接**（`a.continuation` 存在）：取本片上一个执行体 dispatch（`agentOf` 得到 worktree 与 branch）。那棵 worktree 存在 → 复用（与现在一样），`start` 带原 base；不存在 → 按新派发处理。
- **新派发**：`freshWorktree(io, f, a.slice, A)`。
  - 如果本片先前有过执行体 dispatch，而且新 worktree 与它不同，就把 `previous: { branch, attempt }` 传给 `executorPrompt`。
  - `start` 带 `--expect-branch f.branch`，与现在新建时一样。
- **dispatch 事件**：带 `branch`。
- **合回**：`merge` 动作（via branch）用本片最后一次门禁绿的那个 agent 的 `agentOf(...).branch` 调 `mergeSlice`。
- **解冲突**：
  - 派发解冲突 agent 时，`prepareResolve(io, f, slice, { branch: <同上的切片分支>, attempt: A })`，dispatch 事件带解冲突分支；
  - `merge`（via resolve）用解冲突 dispatch 的 worktree 与分支调 `finishResolve`。

### 2. `landing.tsx` · 修复体与修复合回
- 派发修复体改用 `freshWorktree(io, f, 'fix', attempt)`，dispatch 事件带 `branch`。
- 修复合回（orchestrator 里 `merge` via fix）用本 attempt 最后一个修复体 dispatch 的分支调 `mergeFix`。

### 3. `orchestrator.tsx` · 起飞（design D5，用户定）
- 读到账本之后、写任何事件或记录之前判断：最新 takeoff 的 `by.session` 不是本会话（`$.session.id()`），且该 attempt 没有 land / halt。
  - 参数里没有 `--takeover` → 回复：
    > flight：<change> 的 attempt <N> 由另一个会话（<id 前 8 位>）起飞，尚未落地或停飞；到那个会话里继续，或确认它已结束后用 /opsx-apply <change> --takeover 接管
  - 有 `--takeover` → 照常起飞，takeoff 事件多记 `takeover: <原会话 id>`。
- `--takeover` 不能被当成 change 名：找 change 名时跳过所有 `--` 开头的参数，现有逻辑已经如此，确认即可。它也不在 `PASS_THROUGH` 里。
- 同会话的「agent 仍在运行」检查不变。

### 4. `orchestrator.tsx` · 测量判不出（design D7）
`mcp__flight__measure` 的 tool.call：先查 `ownership(io, agentId)`。结果为 `unknown` 时，返回 `{ deny: 'flight：暂时无法判定你的归属（账本读取失败），稍后重试测量' }`，不调用 `onMeasure`。
