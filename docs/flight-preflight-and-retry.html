0 · 结论先行

四个问题全部属实，根因都在 template 脚本
  • 切片 lint 全 change 计算 → slice-gate.py 对 gate.lint 原样执行，没有基线也没有区间
  • 重试基准校验拒绝上一轮 commit → opsx-apply.js 重试仍用起飞时的 expectHead
  • evidence 写错目录 → test-evidence.py 无标记时按字母序猜第一个未完成 change
  • S3 verify 没排除既有错误 → typecheck 无基线、verify 手搓 grep、规划 lint 不拦
复盘另发现两处
  • 重试重跑 start 把 base 重置到上一轮 commit、red_count 归零 → 门禁区间变空、stop-gate 之后连拦 6 次
  • 基线全量测试 exit 101（红）照常批准起飞 → 环境坏的判定推迟到飞行中
追问①：停飞能避免吗

能，而且该避免。这个 change 派发 3 次才飞完，4 个停飞原因全部可在起飞前用脚本判出（详见 §3）。修法 F2「起飞前预检」。

追问②：给了 PR 地址后没问就修

属实。行为与 pr-ship.md step 10「CRITICAL/HIGH 自动修复，不问询」一致，不是模型越权；但你的全局 CLAUDE.md 列举的授权范围里没有「自动修并 push 修复 commit」。两份文档打架，需要你定（D5）。

2 · 六处缺陷：现象 → 证据 → 根因 → 修法

缺陷 1 · 切片 lint 按整个 change 算文件 F1

现象S0 只 owns .claude/hooks/slice-gate.py，G2 lint 却对 backend/tests/requests/*.rs 报 rustfmt 差异。 证据gate-report 09:06:31 S0 red「G2 lint: exit 1 … gap < 60 …」；09:07:30 S0 red「G6 ownership: backend/tests/requests/manual_scale.rs 不在 owns 内」（执行体为了过 lint 去改了别人的文件）。 根因template/.claude/hooks/slice-gate.py:577-582：cmd_gate 对 gate.lint 原样 run_cmd；作者把 lint 写成 git diff main...HEAD -- "*.rs"，覆盖整条分支。基线阶段没有记录 lint 输出，门禁也没有区间概念。 修法F1 基线差分：baseline 时记录 lint / typecheck 的规范化输出行；切片门禁与 final 只对「基线没有的行」判红，与基线一致则降级为 warning「既有 N 行已按基线排除」。作者无需配合，零 token。

缺陷 2 · 重试时基准校验拒绝上一轮的 commit F3

现象单切片 wave（不隔离）重试立即失败；多切片 wave（隔离）重试从零重做。 证据run 1 转录 09:06:55 执行体返回 {"failed":["G0 base: worktree HEAD 不是 c5134a6b31"],"summary":"当前 HEAD 是 99f8e1a（上一轮已提交的 S0 commit …"}。run 2 临时 worktree wf-1 与 wf-3 各有一个同题不同 sha 的 S1 commit（3f1e84c / e92af59）。 根因template/.claude/workflows/opsx-apply.js:87-98 executorPrompt(s, retryOf) 重试时仍用起飞时的 expectHead 做第零步校验；隔离模式下每次 agent() 都是新 worktree（已核实 Workflow API 无复用入口），上一轮 commit 只在 worktree-wf_*-1 分支上，「只修这些门禁项」无从下手。 修法F3 重试接续：门禁 JSON 带上 base；重试第零步改为「HEAD ≠ 上一轮 commit 则 git cherry-pick <retryOf.commit>（worktree 共享对象库，两种模式都可达；冲突则 abort 返回 G0）」，再 start <S> --base <retryOf.base>。

缺陷 3 · evidence hook 写错 change 目录 F4

现象S1 门禁报 openspec/changes/fix-kafka-ingest-loss/evidence.log 不在 owns 内 + 工作树脏；执行体只好 git checkout -- 复原。 证据主会话 09:28:33 命令 sed -i '' 's#cargo test --test mod …#…#' openspec/changes/…/slices.json：文本含「cargo test」命中 TEST_RE；start S1 在 09:28:40 才写标记（09:10:48 S0 门禁绿时已删旧标记）。gateway 仓库有 11 个 tasks.md 未勾完的 change，按字母序第一个正是 fix-kafka-ingest-loss。 根因template/.claude/hooks/test-evidence.py:51-62 无标记时的回退 = 遍历 openspec/changes/* 取第一个有未勾选项的 change，这是猜测；多活跃 change 的仓库里几乎必错。 修法F4 禁猜：定位顺序改为 标记 → 当前分支名 worktree-<name> 且 openspec/changes/<name> 存在 → 恰好只有一个未完成 change → 否则不写。（TEST_RE 会被 sed / grep 文本误触发是另一个小问题，本次只记不修。）

缺陷 4 · S3 verify 没排除既有错误 F1 + F2

现象S3 verify = pnpm test && ! (pnpm -s typecheck | grep -E "src/(views/system/jobs|api/system|…)")，改动文件 0 处类型错误仍红。 证据gate-report 09:34:33 / 09:35:15；review-findings.json blocked：「命中 src/api/system.ts:174-189 与 hook.tsx:189 共 18 处既有错误（自 7e6b525 Initial commit 起即存在）… 规划缺陷：verify 未按基线排除既有错误」。已用 git show main: 复核这些行在 main 上原样存在。 根因三层都缺：typecheck 没有基线（F1）；verify 手搓 typecheck grep，lint_plan（slice-gate.py:133-163）不拦；cmd_baseline（:686-700）从不试跑各切片 verify，命令写错要到飞行中才知道。 修法F1 基线差分覆盖 gate.typecheck；规划 lint 新规则：verify 禁含 typecheck / lint 工具名（tsc|typecheck|eslint|rustfmt|clippy|ruff|mypy|flake8|golangci），提示放到 gate.typecheck / gate.lint；F2 预检：baseline 逐片试跑 verify，骨架都是 strict-xfail 所以基线上必须绿，红即停下报告。

缺陷 5 · 重试重跑 start：base 重置 + red_count 归零 复盘发现 F3

证据worktree 根的 .openspec-slice 现为 {"slice":"S3","base":"5c452e3…","red_count":1}：base 就是 S3 自己的 commit，两次红只记了 1 次。第一轮 09:34:33 有「G3 pairing: 改了源码 … 但区间内没有测试文件改动」，第二轮 09:35:15 该项消失（区间为空）。09:39 起主会话每次收口都被 stop-gate 拦：「S3 已 start 但门禁未绿」，共 6 次。 根因slice-gate.py:531-541 cmd_start 无条件覆盖标记。 修法start 对同一切片幂等：已有标记则保留 base 与 red_count，只记 slice-start S3 (resume)；新增 --base 供隔离模式重试钉住原始基准。红两次后 stop-gate 按既有规则放行。

缺陷 6 · 基线红照常起飞 复盘发现 F2

证据timeline 08:53:58 baseline exit 101；09:05:34 approve。S1 最终以 infra 记 blocked，原因「loco-openapi … 基线 flight_batch 同样复现」。 根因cmd_baseline 退出码只是提示；opsx-propose.md step 4 不因红停下；lint（apply step 3）与 takeoff-gate.py 都不看基线。四种暂停例外里的「测试环境本身坏（verify 在改动前就不可运行）」本可在起飞前判定。 修法F2：baseline 产出 gate-baseline.json；slice-gate.py lint 缺它 / 不 ok / 过期 → 非 0 停飞。人类收窄 gate.test 或修环境后重跑 baseline；改了计划文件即触发 takeoff-gate 的新鲜度重批。

3 · 追问①：起飞后停下来，需要避免吗、能避免吗

需要，且大部分能。这次 4 个停飞原因没有一个是「设计想错了」，全是环境与命令层面的事实，在批准之前就能用脚本判定：

停飞原因类型起飞前预检能拦？靠什么
S0：lint 对不属于本片的骨架文件报差异基线本就有的问题能baseline 记 lint 基线，门禁只看新增
S1：verify 命令语法错，cargo 直接拒绝命令不可运行能baseline 逐片试跑 verify，非 0 即报
S1：loco-openapi 路由累积随机 panic环境坏能baseline 已经 exit 101，只是没人拦
S3：typecheck 命中 18 处既有错误基线本就有的问题能同上两条
S2：临时 worktree 没有 node_modules基础设施部分不是停飞原因；可在预检里提示「verify 依赖未纳入 git 的目录」，本次不做

不能靠预检避免的：切片对接口 / 数据模型的理解偏差。那是 spec、design、切片评审的职责，不属于本次。

代价：预检 = 全量测试一次 + 各片 verify 各一次，本例约 62 s + 3 × 30 s ≈ 3 分钟；对比三次派发与 33 分钟的飞行，划算。预检跑在 propose 阶段的 baseline 步骤，也就是人类批准之前，红会直接出现在审批面板里。

5 · 修复设计

F2 · 起飞前预检（覆盖缺陷 4、6，回答追问①）

propose step 3写 slices.json → lint 绿
→
propose step 4 · baseline跑 gate.test · gate.lint · gate.typecheck · 每片 verify
→
gate-baseline.json{commit, plan_sha, ok, reasons, test{exit,sec}, lint{exit,lines}, typecheck{exit,lines}, verify{S1:{exit},…}}
→
spec.html红 → 面板显示原因，人类先修再批
→
apply step 3 · lint缺文件 / ok=false / plan_sha 过期 → 非 0 停飞
  • ok 判据：test exit 0 ∧ 每片 verify exit 0（骨架是 strict-xfail，基线上应绿）。lint / typecheck 红不阻断，只记基线行。
  • plan_sha：gate 三条命令 + 各片 verify 的 sha1。改了任何一条就过期，必须重跑 baseline。不用 mtime，跨 worktree 不可靠。
  • 不设「已知红，放行」字段：那等于让模型自证。红就改 gate.test 或修环境，改计划文件会触发 takeoff-gate 重批，链条闭合。

F1 · 门禁基线差分（覆盖缺陷 1、4）

门禁跑 gate.lint / gate.typecheck，取完整输出
→
规范化：去 ANSI · 数字串→# · 去首尾空白 · 丢空行
→
新增行 = 本次行集 − 基线行集
→
有新增 → 红，只贴新增行（≤ 6 行）
无新增但 exit ≠ 0 → warning「既有 N 行已按基线排除」

数字串折叠是为了让「同文件同报错、行号漂移」仍算既有。无 gate-baseline.json 时退回现行为（exit ≠ 0 即红），回退语义一致。

F3 · 重试接续（覆盖缺陷 2、5）

现在
第 1 轮 commit C1 → 门禁红
→
重试仍校验 HEAD == expectHead X
不隔离：HEAD=C1 ≠ X → G0 拒绝
隔离：新 worktree@X，C1 不可达 → 从头重做
→
重跑 start → base=C1，red_count=0
改后
门禁 JSON 多带 base
→
重试第零步：HEAD ≠ C1 → git cherry-pick C1（冲突 abort → G0）
→
start S --base X：同片已有标记则保留 base / red_count
→
只修 failed → gate：区间 X..HEAD 完整，red_count 累加到 2 后 stop-gate 放行

已核实 Workflow agent() 只有 isolation: 'worktree'，无复用上一轮 worktree 的选项，所以用 cherry-pick 而不是改派发方式。opsx-apply.md / openspec-apply-change/SKILL.md 的回退路径同句同改。

F4 · evidence 定位禁猜（覆盖缺陷 3）

.openspec-slice 标记
→
分支名 worktree-<name> ∧ openspec/changes/<name> 存在
→
恰好一个 tasks.md 未勾完的 change
→
多于一个 → 不写（宁缺毋错）

F5 · pr-ship 自动修复前问一次（可选，取决于 D5）

把唯一一次问询预算从 step 11「要不要人工再看」挪到 step 10「N 条 CRITICAL/HIGH：自动修并 push / 只贴评论交人」；无人应答默认只贴评论。只改 pr-ship.md 一处与对应测试。
