## 做什么

### `prompts.ts`（design D1）
新增两个纯函数（`Finding` 用文件里已有的本地类型）：
```ts
export function wholeReviewPrompt(x: { change: string; changeDir: string; hooksDir: string; base: string; commit: string; prior: Finding[] }): string
export function followupReviewPrompt(x: { change: string; changeDir: string; round: number; base: string; commit: string; prior: Finding[] }): string
```
- **共同要求**：
  - 写明审查范围 `git diff ${base} ${commit}`；
  - prior 逐条写成 `[级别] file:line — 摘要`，空时写「切片评审没有 CRITICAL/HIGH」（复核为「上一轮没有 CRITICAL/HIGH」）；
  - 取不到 diff 或 diff 为空时，提交一条 summary 为「取 diff 失败」的 HIGH，不得提交空列表；
  - 只读，不重跑测试套件，至多 1 次定向抽查；
  - 必须调用 `submit_findings` 提交，没有问题也提交空列表，提交后一行结束。
- **全量评审另写**：
  - 验收依据为 `${changeDir}` 下的 proposal.md、design.md、specs/、slices.json；
  - 门禁与测量统计以 `python3 ${hooksDir}/timeline.py report --change-dir ${changeDir}` 为准，在 worktree 里运行；
  - prior 是切片评审提过、修复体已修的 CRITICAL/HIGH：逐条核对，没闭环或修得不对的照原级别再提交。
- **复核另写**：
  - 「第 ${round} 轮修复」，只审这一轮修复带来的改动；
  - prior 是上一轮的 CRITICAL/HIGH：未闭环或修得不对的照原级别再提交；
  - 修复补丁新引入的问题照常分级提交；与本次修复无关的代码不报。

### `landing.tsx`
- **派发评审员**：动作带 `mode`（见 `slices/_interfaces.md`）时走新分支；不带 `mode` 的切片评审照旧。
  - **mode `whole`**：
    1. `git -C <mainTree> rev-parse HEAD` 得到 m；
    2. `git -C <changeTree> merge-base <commit> <m>` 得到 base；
    3. 任一步失败、输出为空或 base 等于 commit → 不派发，记 `ev.blocked({ slice: 'review:' + action.slice, kind: 'infra', reason: '算不出全量评审的起点：<原因>' })`；
    4. 否则用 `wholeReviewPrompt` 派发（cwd 为 change worktree，description 为「全量评审」），dispatch 事件额外带 `commit` 与 `base`。
  - **mode `followup`**：用动作的 base / commit 与 `followupReviewPrompt` 派发，`round` 从 slice `whole-r<k>` 取 k，description 为「复核 第 k 轮」，dispatch 事件同样带 `commit` 与 `base`。
  - 派发被拒：照旧记 blocked `review:<slice>`。
- **派发修复体**：slice 取 `action.slice ?? 'fix'`。提交记录失败时的 blocked、`freshWorktree(io, f, slice, attempt)`、dispatch 事件的 slice 与 branch，一律用这个 slice；description 为「修复 <slice>」。
- **修复体收口**（`onLandingStop`）：gate 事件的 slice 用 `agentOf` 得到的 slice（旧事件没有 slice 时为 `fix`），不再写死 `FIX`。
- **落地**：
  - 改调 `closeout(io, f, merged)`，不再 import、不再调用 `closeoutLists`；
  - merged 排除 slice 为 `fix` 与匹配 `^fix-r\d+$` 的合回。

### `land.ts`
- **`mergeFix`**：签名改为 `mergeFix(io, f, note, branch?, slice = 'fix')`；分支缺省为 `flight/${f.change}/${slice}`，合并提交信息为 `integrate: ${slice}`，其余不变。
- **`closeout(io, f, merged)`**（design D4）：
  1. 先跑 `slice-gate.py ship --change-dir <changeDir>`（cwd 为 change worktree），解析 stdout 的 JSON（退出码 0 / 1 都解析）；
  2. 解析失败，或缺 `ready` 与几个数组字段 → 返回 `{ verdict: 'draft', reasons: 'ship 输出无法解析：<首行>' }`，不写 `review-findings.json`，不勾选、不记 apply-done、不提交；
  3. 否则写 `review-findings.json`，内容为 `{blocked, blocking, deferred, fix}`，取自 JSON，格式照旧（2 空格缩进加换行）；
  4. 勾选 `tasks.md`；
  5. `timeline.py record apply-done`，note 为 `blocked=<n> blocking=<m>`；
  6. 以 `chore(flight): 收口` 提交记录；
  7. 返回 `{ verdict: ready ? 'ready' : 'draft', reasons: reasons.join('; ') }`。
  - 原先最后跑的那次 ship 删掉（ship 已经在第一步跑过）。

### `agents/reviewer.md`
- `description` 与正文改为「只审提示词给定的范围」，范围有三种：
  - 切片合回 commit：`git diff <commit>^1 <commit>`，对第一父取 diff；
  - 全量评审：change 分支相对分叉点的全部改动；
  - 复核：一轮修复带来的改动。
- 保留「取 diff 失败」须报 HIGH、不得提交空列表；保留 `^1`；不出现 `git show`。
- 流程第 1 步改为：读提示词给的验收依据（切片包，或 change 目录的 proposal / design / specs）。
