## 做什么（design D2 的跟踪部分、D4 的提示词、D6 的定义；签名见 `slices/_interfaces.md`）

### `template/plugins/flight/hooks/prompts.ts`

**`integFixerPrompt`**：
- 开头：「任务三 · 整合修复」，change 名与 changeDir；
- 逐条列出 failed（多行项原样缩进）；
- 写明规则：
  - 每处修复先有失败测试（final 的失败就是红）；
  - 只写全部切片 owns 的并集；
  - 不改本 change 的 proposal / design / tasks / slices.json / 切片包 / specs 与 openspec/adr；
  - 不碰 slices.json 里 scenario 映射的测试函数；
  - 测试只增不减：不删 assert、不删测试函数、不加 xfail / skip；
- 「门禁由控制面在你收口时运行（全量 final + G9 整合护栏，起点 `<base>`）：不要自己运行 slice-gate」；
- 修不了的在最后一行写明原因。

**`integReviewPrompt`**：
- 「专审整合修复」；
- 审查范围 `git diff <base> <commit>`；
- 点名「重点核对是否以改弱测试换绿（删断言、放宽阈值、改期望值去迁就实现）」；
- 沿用 `REVIEW_TAIL`。

**`triagePrompt`**：
- 「停飞诊断」：change、停飞原因、kind；
- 只读：不改任何文件、不提交、不重跑全量测试；
- 查看命令：
  - `python3 <hooksDir>/ledger.py show --change-dir <changeDir>`
  - `python3 <hooksDir>/timeline.py report --change-dir <changeDir>`
  - `git log` / `git diff`
- 最终回答格式：
  - 首行：一句话根因；
  - 第二行：恰为「改计划」「修插件」「人工操作」之一；
  - 其后：需要改计划时，写出 slices.json / spec / 切片包的具体改法草案（只写在回答里，不落盘）。
