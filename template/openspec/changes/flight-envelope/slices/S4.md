# S4 · 续飞零 token 补跑门禁、保留原 base；起飞前提交遗留记录；终态短路

## 做什么

### `template/plugins/flight/hooks/core.ts`
1. `Action` 加一种：`{ kind: 'regate'; slice: string; base: string; worktree: string }`。执行体的 dispatch 动作加可选字段 `base?: string`。
2. `next()` 的 `sliceActions(s)`：本 attempt 还没有 S 的执行体派发（`execs` 为空）时，按下面的顺序判：
   - **本 attempt 已有 S 的补跑结论**（gate 事件，`agent === 'regate'`，取最后一条）：ok 就 `[{ kind: 'merge', slice: s, via: 'branch' }]`；红就续派执行体，`continuation` 照旧带失败项，再加上 `base`。
   - **否则用 `firstDispatch(s)`**：
     - 上一 attempt 派过 S 的执行体且没被记阻断、S 的最后一条 gate 事件（任意 attempt）ok、且带 `base` → 返回 `{ kind: 'regate', slice: s, base, worktree: <上次 dispatch 的 worktree> }`；
     - 其余情况维持原逻辑；能从最后一条 gate 事件取到 `base` 时，续接派发带上它。

### `template/plugins/flight/hooks/orchestrator.tsx`
3. **`runGate`** 加可选参数 `base`，有值时给 `slice-gate gate` 加 `--base <base>`。
4. **`perform` 处理 `regate`**：
   - worktree 存在（`io.exists`）时，`runGate(io, f, a.slice, a.worktree, a.base)`，记 gate 事件：`attempt` 为本 attempt，`agent` 为 `'regate'`，其余为门禁 JSON。
   - worktree 不存在时，按全新派发处理：走 dispatch executor 的同一段逻辑，不带 base、不带 continuation。
5. **`perform` 的 dispatch executor**：`a.base` 有值时，`slice-gate start` 的参数加 `--base <a.base>`。
6. **`takeoff` 的「工作区不干净」检查（约 294 行）**：用 `git status --porcelain --untracked-files=all` 列出脏路径。如果每个路径都是 `${changeDir}/${r}`（`r` 属于 `land.ts` 导出的 `RECORD_FILES`），就先 `commitRecords(io, f, 'chore(flight): 记录')`，失败则拒绝起飞并给出原因；否则照旧回复「工作区不干净」。注意 porcelain 的 XY 列可能以空格开头，取路径时不能先 trim。
7. **`driveNow` 的终态短路（PR #40 评审 MEDIUM）**：在 `if (state.takeoff === undefined) return` 之后、调 `plan_fp` 之前，加 `if (state.events.some(e => (e.ev === 'land' || e.ev === 'halt') && Number(e.attempt) === state.attempt)) return`。
