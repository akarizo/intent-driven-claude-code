**目标**：仓库根成为 marketplace；`install.sh` 在目标仓库按项目作用域装 `flight@intent-driven`（design D9）。

**deps: S3**（marketplace 的 `source` 指向 S3 建的 `template/plugins/flight/`）

## 事实基线（main 5545f68）

- `install.sh`：`REPO_URL="${IDT_REPO_URL:-https://github.com/akarizo/intent-driven-claude-code}"` 31 行；`merge_settings` 274 行起（settings.json 是用户数据，只合并不覆盖）；收尾摘要 heredoc 约 430–455 行，其中 447 行描述 takeoff-gate「校验会话转录里的人类消息证据与新鲜度」。

- 本机 `claude` 在 `~/.local/bin/claude`；测试里的 `path_without_real_claude` 会把含 `claude` 的 PATH 目录剔除。

## 契约

```text
.claude-plugin/marketplace.json
  {"name":"intent-driven","owner":{"name":"akarizo"},
   "plugins":[{"name":"flight","source":"./template/plugins/flight","description":"…"}]}
install.sh（install 与 --upgrade 都跑，放在 merge_settings 之后）
  owner_repo = REPO_URL 去掉 https://github.com/ 前缀与 .git 后缀
  若 $TARGET/.claude/settings.json 的 enabledPlugins["flight@intent-driven"] 为 true → log「flight@intent-driven 已启用，跳过」
  否则若 command -v claude：
      (cd "$TARGET" && claude plugin marketplace add "$owner_repo" --scope project)
      (cd "$TARGET" && claude plugin install flight@intent-driven -s project)
      任一非 0 → 告警并打印手动命令，不改变退出码
  否则：打印「起飞批准需要 flight 插件，请在 <TARGET> 内执行：」+ 两条完整命令（以 claude 开头）
  摘要 447 行改写：takeoff-gate 以账本指纹为判据（批准带按钮），需 flight@intent-driven 插件
```

## 坑

- ⚠ **先改 `run_install`**：本片实现后 install.sh 会调用 PATH 上的 `claude`；上方旧助手 `run_install` 必须同样用 `path_without_real_claude` + 桩，否则跑测试会真实改动开发者本机的 `~/.claude/plugins/installed_plugins.json` 与 `known_marketplaces.json`（2026-10-09 实测会写）。
- ⚠ 判断 `enabledPlugins` 需要解析 JSON：有 python3 用 python3（与 `merge_settings` 同法，不引入新依赖）；无 python3 时退化为 `grep -q '"flight@intent-driven": *true'`。
- ⚠ 插件步骤不得让 install.sh 以非 0 退出（`set -e` 环境下用 `|| …` 吞掉并告警）。
- ⚠ 手动命令的文字必须与测试常量逐字一致（含 `--scope project`、`-s project`）。
- ⚠ 每条骨架解锁时去掉 `@PX` 标记；已有 2 条用例必须继续通过。
