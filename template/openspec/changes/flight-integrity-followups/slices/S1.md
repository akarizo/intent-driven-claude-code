## 契约

```text
_g7_runner(gate) -> (argv_prefix, warning | None)
  gate.get("pytest") 非空      → shlex.split(gate["pytest"]), None
  否则 toks = shlex.split(gate.get("test") or "")；找第一个 i：
      os.path.basename(toks[i]) in ("pytest", "py.test")，或 toks[i] == "pytest" 且 toks[i-1] == "-m"
    找到且 toks[:i+1] 里没有 && || ; | 与 cd、也没有形如 NAME=值 的 token → toks[:i+1], None
  其余                          → [sys.executable, "-m", "pytest"],
                                   "G7：无法从 gate.test 推导 pytest 运行方式，已退回 <sys.executable> -m pytest；可在 slices.json 的 gate.pytest 指定"
_g7_timeout(gate) -> 秒数
  环境变量 FLIGHT_G7_TIMEOUT 可解析为数字 → 取它
  gate.full_suite_sec 为数字 → max(120, 3 * full_suite_sec)；否则 600
_pytest_outcomes(root, targets, gate) → (outcomes, rc, out_text, timed_out)
  argv = prefix + ["-p", "flight_g7_outcomes", "-p", "no:cacheprovider", "--rootdir", root, *targets]
  超时：杀掉整个进程组（start_new_session=True + os.killpg），以免孙进程占住管道
scenario_status(...) → (violations, total, passed, warnings)
  timed_out → 每个 .py 目标：「G7 scenario: <sid> → <target> 运行超时（<N> 秒）」
  目标无结果 → 「… 未被收集运行（pytest rc=<rc>：<诊断行>）」
               诊断行 = out_text 中第一条含 "Error" 的行，没有则末行，strip 后截断到 200 字符
  warning 非空且确有 .py 目标 → warnings 追加它
cmd_gate / cmd_final：接四元组，把 G7 的 warnings 并入输出的 warnings
schema.yaml tasks 指令：在 gate 说明处补一句「`gate.pytest`（可选）：G7 实跑 scenario 测试用的 pytest 命令前缀（如 `uv run pytest`）；缺省从 `gate.test` 推导」
```

## 坑

- ⚠ **超时测试的包装脚本先 `sleep 5` 再 exec**：只杀直接子进程的话，`sleep` 会继续占住输出管道，`communicate()` 要等它结束。用进程组整组杀掉。
- ⚠ **推导与退回只影响 G7 的实跑**；G2 全量测试仍按原样用 `gate.test` 走 shell。
- ⚠ **本文件里已有 `_set_gate(change, key, cmd)` 助手**（约 575 行，被 lint 相关用例使用）。新段用的是 `_update_gate`，不要合并或改名。
- ⚠ 改完跑 `cd template && openspec schema validate intent-driven`，保持绿。
- ⚠ 逐条去掉 5 条 G7 骨架的 `@pytest.mark.xfail`；守卫测试不动。
