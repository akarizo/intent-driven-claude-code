## 事实基线（main 5a110aa）

- `plan_fp.py`：27 行 `plan_files`。33 行与 36 行两处 `glob.glob(os.path.join(change_dir, ...))`，change_dir 未转义。
- `ledger.py`：
  - 34 行 `_git(change_dir, *args, check=True)` 用 `text=True`。非 UTF-8 输出在 subprocess 内部抛 `UnicodeDecodeError`，最终走到 CLI 的 `except Exception` → exit 5。
  - 60 行 `read_events`：先 `rev-parse -q --verify ref`（1 = 无引用；其他非 0 → `LedgerUnreadable`），72 行再用 `cat-file -t tip` 判类型。悬空 ref 时 `cat-file` 失败 → `LedgerUnreadable` → exit 5。
  - 99 行 `latest_approval` 在 `read_events` 之后**再次** `rev-parse` 取 tip，读写交错时与读到的事件不一致。
- `takeoff-gate.py` 的 `is_takeoff_dispatch` 已识别 Workflow：`args` 可以是 JSON 字符串、含 `changeDir`。
- `tests/test_approval_gate.py` 已有 `NO_SID`、`current_fp(d)`；conftest 有 `make_change`、`ledger_append`、`approve_event`。

## 契约

```text
plan_fp.plan_files：两处 glob 的前缀改为 glob.escape(change_dir)（os.path.join(glob.escape(change_dir), "specs", "**", "spec.md")）
ledger：
  _git 仍是唯一的 git 调用入口（签名保持 _git(change_dir, *args, check=True, ...)，测试经它注入并发写入），改为按字节取输出；
    调用方需要文本时显式 .decode("utf-8")
  读事件 blob：decode 失败 → LedgerInvalid(<提交 sha>, "event.json 不是 UTF-8")
  cat-file -t <tip> 非 0 → LedgerInvalid(tip, "引用指向不存在的对象")
  拆出 _read(change_dir) -> (events, tip)：只 rev-parse 一次，后续 cat-file / rev-list 都用这个 tip
  read_events 返回 _read(...)[0]；latest_approval 用 _read 的 tip，不再二次 rev-parse
  CLI 退出码语义不变：LedgerInvalid → 4，其余 → 5
```

## 坑

- ⚠ `test_ledger_tip_matches_read_chain` 用 monkeypatch 替换模块级 `_git`，在第一次 `rev-list` 之后追加 F2。所以：
  - 链遍历必须仍用 `rev-list`；
  - 所有 git 调用必须经模块级 `_git` 名字查找（不要在函数里缓存成局部别名）。
- ⚠ 既有 `LedgerUnreadable` 语义保留：git 能执行但返回非 0（不在仓库内等）→ `LedgerUnreadable`，起飞门禁据此 deny；git 不可执行（`FileNotFoundError`）原样上抛。
- ⚠ `test_takeoff_hook_guards_workflow_dispatch` 是既有行为守卫，本片不需要改实现，它必须始终通过。
- ⚠ 逐条去掉 4 条骨架的 `@pytest.mark.xfail`。
