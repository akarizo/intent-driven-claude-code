## 做什么（design D1、D2、D6）

### `template/plugins/flight/hooks/armed.ts`
1. `Arm` 加 `awaitingWake: boolean`：`armOf` 置 false，`beforeRetry` 置回 false。`ArmStep` 加 `{ do: 'wake'; text: string }`。
2. `nextStep`：
   - 在 TTL / human / 预算三项检查之后、`switch` 之前，加一条：`main-turn` 且 `arm.awaitingWake` 时，返回 `retry`；
   - `switch` 里原来对 `tick` / `timer` 返回 `retry` 的三处（wait-baseline 的 tick、wait-agents 的 tick、transient 的 timer），改为 `arm.awaitingWake ? { do: 'wait' } : { do: 'wake', text: wakePrompt(arm) }`；
   - wait-agents 遇 `agent-ended` 仍返回 `retry`。
3. **`wakePrompt(arm)`**，两行：
   - `flight：<change> 起飞待命到点（<原因首行>），插件将在这一轮结束后重试起飞。`
   - `这一轮只回复「收到」，不要做别的，也不要发 /opsx-apply。`

### `template/plugins/flight/hooks/orchestrator.tsx`
4. **`runStep` 处理 `wake`**：
   - 先 `armReady($, arm)`，false 就直接返回，什么都不做；
   - true 时：`T0 = await $.clock.now()`，`putArm({ ...arm, awaitingWake: true, submittedAt: T0 })`，状态行照旧，然后 `$.clock.after(0, () => void submitWake($, change, step.text, arm.since))`。
5. **`armReady($, arm)`**，零 token，任何异常按 true 处理：
   - **wait-baseline**：`locate` 后用 `judge` 跑一次 `slice-gate preflight --change-dir <changeDir>`。退出码非 0 且 stderr 含「基线仍在跑」时返回 false，其余返回 true；
   - **wait-agents**：读账本，取当前 attempt 派出的 agent，在 `$.agent.list()` 里任一处于运行态（`LIVE`）就返回 false；
   - **其他类**：返回 true。
6. **`submitWake($, change, text, since)`**：
   - `$.prompt.submit({ text })`；
   - 失败时，当前待命 `since === since` 才 `dropArm` + 通知 `giveUpText(arm, '提交唤醒失败（<原因>）')` + `restoreStatus`。
7. **`submitFix` 绑定待命**（design D6）：
   - 加 `since` 参数，`runStep` 的 submit 分支传 `arm.since`；
   - 成功时，当前待命 `since` 相同才标记 `awaitingModel` 与 `submittedAt`；
   - 失败时，`since` 相同才放弃并通知。
8. **主会话 `turn.complete` hook**：
   - 挑选条件改为 `(arm.awaitingModel || arm.awaitingWake) && after(arm)`；
   - 之后处理 `pendingTriage`：开始时刻 ≥ 该项 T0 的，先删除，再 `await triage(ctxOf($), f, haltKind, reason)`。
9. **看门狗诊断**：
   - `watchOne` 末尾的 `triage(...)` 改为 `deferTriage($, f, 'watchdog', reason)`：`NO_TRIAGE` 含该 kind 就返回；否则 `T0 = now`，`pendingTriage.set(f.change, { f, haltKind, reason, at: T0 })`，然后 `$.clock.after(0, …)` 提交唤醒文本；
   - 唤醒文本两行：`flight：<change> 已被看门狗停飞，插件将在这一轮结束后派只读诊断员。`、`这一轮只回复「收到」，不要做别的，也不要发 /opsx-apply。`；
   - 提交失败：删掉该项，通知 `flight：<change> 看门狗停飞后未能派诊断员（唤醒失败：<原因>）`；
   - `pendingTriage` 是模块级 `Map<string, { f: Flight; haltKind: HaltKind; reason: string; at: number }>`；
   - `driveNow` 里的 `triage` 不动，它本来就在活的 hook 里。

### `template/plugins/flight/types/index.d.ts`
10. `FlightArmedItem` 加 `awaitingWake: boolean`（注释：已提交唤醒、尚未重试）。
