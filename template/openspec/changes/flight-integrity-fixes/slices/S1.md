# S1 · 门禁结论留存到 git ref，重派起跑时找回

**目标**：门禁通过时把结论 JSON 写进 `refs/flight/<change>/gate-<S>`；`start --resume-checkpoint` 先找它，找到且基点吻合就以 3 退出、原样打印；`record` 与首轮 `start` 负责清理（design D1）。

## 契约

```text
_gate_ref(change_dir, S) = "refs/flight/%s/gate-%s" % (basename(change_dir), S)

cmd_gate：result.ok 为真 →
  blob = hash-object -w --stdin  ← json.dumps(result, ensure_ascii=False)
  tree = mktree                  ← "100644 blob <blob>\tgate.json\n"
  commit = commit-tree <tree> -p <result.commit> -m "flight: gate <S> ok <commit8>"
  update-ref <gate_ref> <commit>
  任一步非 0 → warnings 追加「门禁结论未能留存：<stderr 首行>」，ok 不变（写入要在 append_report 之前，warnings 才能进报告与输出）

cmd_start（--resume-checkpoint 且基点校验已过）→ 先查 gate_ref：
  读 <gate_ref>:gate.json；满足 rec.ok 为真、rec.slice == S、HEAD ∈ {rec.base, rec.commit}
    → print(json.dumps(dict(rec, recovered=True)))；timeline 记 slice-start "<S> (recovered gate)"；sys.exit(3)
    → 不写 .openspec-slice，不恢复快照
  否则 → 不动 gate_ref，走原有快照恢复
cmd_start（首轮，无 --resume-checkpoint）→ 与 _ckpt_delete 一起删 gate_ref
cmd_record → 写回或「已记录」两条路径都删 gate_ref（不存在时静默）
```

## 坑

- ⚠ **退出码 3 是新的语义**：执行体契约「start 非 0 → 原样返回 JSON」由 S3 在文档里补说明，本片只管脚本。
- ⚠ `commit-tree` 需要提交者身份。测试仓库有 `user.email`；真实临时 worktree 继承用户配置。写入失败只告警，不得让门禁变红。
- ⚠ 旧值不需 CAS：同一切片同一时刻只有一个执行体；`update-ref` 直接覆盖。
- ⚠ 既有用例 `test_gate_ok_deletes_checkpoint` 仍须通过：快照 ref 照删，门禁结论 ref 是另一条。
- ⚠ 逐条去掉 S1 四条骨架的 `@pytest.mark.xfail`；S2 的三条留给 S2。
