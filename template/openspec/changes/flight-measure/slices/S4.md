# S4 · 包络补漏：解释器 -c 与 eval、换目录写法、GIT_* 环境变量、共享 config 与 fetch、Glob pattern

## 做什么（只改 `template/plugins/flight/hooks/envelope.ts`，纯函数）

### 1. 解释器 `-c` 与 `eval`
`bashVerdict` 逐段判定时：
- **触发条件**：段的程序名（basename）为 `bash`、`sh` 或 `zsh`，且其选项中有 `-c`（单独的 `-c`，或含 `c` 的短选项簇如 `-lc`）；或者程序名为 `eval`。
- **取内层命令**：取其后的命令文本（`-c` 之后的其余词，或 `eval` 之后的其余词），用空格拼回，去掉一层引号。
- **递归判定**：以本段当前的目录（前面 `cd` 设定的）为起点，按同一套规则递归判定内层命令；内层被拒，整条命令就被拒。
  - 需要把当前目录作为内部参数传下去：抽一个带起始目录参数的内部函数，`bashVerdict` 对外签名不变。
- **取不出来**（引号不配对，包括被分段切开的情形）→ 拒绝，理由含「无法判定」与「-c / eval」。

### 2. 换目录的各种写法（改 `words` 与 cd 识别）
- **剥前缀**：剥掉段首的 `builtin`、`command`、`exec`，以及 `env` 和紧随的选项（`-` 开头）与 `VAR=`。被剥掉的 `VAR=` 键名一并返回，见第 3 条。
- **`pushd <p>`**：与 `cd <p>` 一样设定目录。
- **`popd`**：之后目录记为无法判定（null），后续改动类 git 会因作用目录无法判定被拒。

### 3. `GIT_*` 环境变量
- `words` 改为同时返回段首被剥掉的赋值键名，含经 `env` 给出的。
- **改动类 git 段**（不在 `READONLY_SUBS`，且不在拒绝表以外的放行范围）：键名里有以 `GIT_` 开头的 → 拒绝，理由含「GIT_」与这些键名。
- **`export` 段**：后面出现 `GIT_` 开头的名字（无论带不带 `=`）→ 拒绝。
- **只含赋值的段**：所有词都是 `VAR=val`，且有以 `GIT_` 开头的键 → 拒绝。
- **只读子命令带 `GIT_*`**：不拒绝。它本来就因 `hasEnv` 不免询问，这一点不变。

### 4. 共享 config 与 fetch
- `DENY_SUBS` 加入 `fetch`。
- **`git remote`**：参数为空，或第一个参数是 `-v`、`--verbose`、`show`、`get-url` 时放行，其余拒绝，理由含「git remote」。
- **`git branch`**：拒绝选项加上短选项 `u`，以及长选项 `--set-upstream-to`、`--unset-upstream`、`--edit-description`。

### 5. Glob 不越界免询问
`readUpgradable` 对 Glob：`pattern` 以 `/` 开头，或按 `/` 切开后有 `..` 段 → 返回 false。其余规则不变。
