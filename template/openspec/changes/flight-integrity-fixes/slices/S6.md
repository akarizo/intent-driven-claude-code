# S6 · install.sh：插件两步互不阻断、升级补缺失的 settings 顶层键

**目标**（design D7）：
- `marketplace add` 失败不再挡住 `install`；两步都失败时仍以 0 退出并打印手动命令。
- `merge_settings` 把模板 settings.json 里用户缺失的顶层键补上，已有键不动。
- 文件头的「用户数据」清单列入 settings.json。

## owns

- `install.sh`
- `tests/test_install.py`（末尾 3 条骨架与助手 `run_install_claude_failing`）

## 事实基线（main 5a110aa）

- `install.sh`：
  - 文件头 13–16 行列出「用户数据」（不含 settings.json）；
  - 273 行 `merge_settings`：python 段只合并 hooks，按 command 去重，非法 JSON 时中止，绝不覆盖；
  - 358 行 `install_flight_plugin`：369–370 行 `marketplace add … && install …` 串联，前者失败后者不执行，失败分支打印「请在 $TARGET 内手动执行」与两条命令；
  - 391 行 `copy_tree "$TEMPLATE_SRC/.claude" "$TARGET/.claude" "$UPGRADE" "preferences.md settings.json"`：升级不再覆盖 settings.json；
  - 412 行调 `merge_settings`，417 行调 `install_flight_plugin`。
- 模板 `template/.claude/settings.json` 的顶层键：`env`（`CLAUDE_CODE_SUBAGENT_MODEL: sonnet`）、`worktree`（`{"baseRef": "head"}`）。
- 测试助手：
  - `run_install_stubbed(tmp_path, target, *flags, claude=True)`，其 claude 桩恒返回 0；
  - 新增的 `run_install_claude_failing(tmp_path, target, failing, *flags)` 让指定 plugin 子命令返回 1；
  - 常量 `MARKET_ADD`、`PLUGIN_INSTALL`。

## 契约

```text
install_flight_plugin（有 claude 时）：
  (cd TARGET && claude plugin marketplace add <owner_repo> --scope project) || log_info "marketplace add 失败（可能已声明），继续安装"
  if (cd TARGET && claude plugin install flight@intent-driven -s project) → log_add …
  else → log_err「flight 插件安装失败（起飞批准需要它），请在 $TARGET 内手动执行：」+ 两条完整命令
  退出码不变
merge_settings：python 段多接收 "$TEMPLATE_SRC/.claude/settings.json"（不存在则跳过补键）
  对模板中除 hooks 外的每个顶层键 k：k 不在用户 data 中 → data[k] = 模板值（深拷贝）；已存在 → 不动（不深合并）
  有补键或有 hooks 合并即写回；状态输出沿用 created / merged / unchanged / error_malformed
文件头「用户数据」清单加入 settings.json（说明：升级只补缺失的顶层键）
```

## 坑

- ⚠ 既有 4 条插件分发用例与 `.flight` 忽略用例都要继续通过。尤其：
  - `test_install_registers_plugin_at_project_scope` 断言两条调用的顺序是 marketplace → install；
  - `test_install_skips_enabled_plugin` 断言已启用时零调用。
- ⚠ 补键只补**顶层**缺失键：用户 `env` 存在时，不得往里加 `CLAUDE_CODE_SUBAGENT_MODEL`（骨架断言 env 恰为 `{"MY_KEY": "1"}`）。
- ⚠ 测试绝不能碰真实 `claude`：两个助手都用 `path_without_real_claude`。
- ⚠ install.sh 里内嵌 python 的写法沿用现有 `python3 - "$settings" "$fragment" <<'PY'` 模式（产品代码，不受本会话的 heredoc 约束）。
- ⚠ 逐条去掉 3 条骨架的 `@pytest.mark.xfail`。
