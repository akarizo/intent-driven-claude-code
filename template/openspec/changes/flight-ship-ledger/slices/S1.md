## 做什么

### `slice-gate.py ship`（design D3）
`cmd_ship` 改为只读账本、`slices.json` 与 git：
- **不读文件**：不读 `gate-report.md` / `review-findings.json`；**删掉** `timeline_record(..., "ship", ...)`。
- **账本**：用同目录 `ledger.read_events(change_dir)` 读事件（`cmd_gate` 已有这种 import 写法）。读失败 → reason `账本读取失败：<异常>`。
- **判据**：按 design D3 的表依次累积 reasons；reason 文案照表一字不差（测试按子串断言）。
  - attempt `A` 取最后一条 takeoff 的 attempt。
  - 「本 attempt」指事件的 attempt 等于 `A`。
  - 修复轮 slice 用正则 `^fix-r\d+$`；全量评审轮 slice 为 `whole` 或匹配 `^whole-r\d+$`，轮次序号：`whole` 为 0、`whole-r<k>` 为 k。
  - **最新一轮**：本 attempt 里有 review 事件的全量评审轮中，序号最大的那一轮。
  - **最新一轮评审的 commit**：该 review 的 agent 对应的 dispatch 事件里的 `commit` 字段；缺失则视为过期。
  - `_final_fresh` 照旧复用，判断「commit 之后只有记账改动」。
- **路由对账**：照搬 `template/plugins/flight/hooks/core.ts` 的 `routingFindings`：
  - 每条 ended 事件，期望模型取同 attempt 的 takeoff 的 `model`（找不到就取最后一条 takeoff）；
  - 实际模型须包含期望模型（都转小写比较），否则生成 `{"severity": "HIGH", "file": "routing", "line": 0, "summary": "路由不符：<角色>（agent <id>）期望 <期望>，实际 <实际或「缺失」>", "fix": "按角色路由用 <期望> 重跑该角色，或人工核对该 agent 的实际模型"}`；
  - 角色取该 agent 最后一条 dispatch 的 role，没有则写 `unknown`。
- **输出**：JSON 字段与 `slices/_interfaces.md` 一致，`commit` 为 HEAD 全长。退出码 0 为 ready、1 为 draft。`--markdown` 的输出格式不变。
- **没有 `slices.json`**：直接判 draft，reason 为 `没有 slices.json：不是飞行 change`，不再读 `review-findings.json`。

### 其余判定器
- **`FEATURES`**：增加 `ship-ledger`，放在末尾。
- **`_reusable_fix_gate`**：取「slice 为 `fix` 或匹配 `^fix-r\d+$` 的 gate 事件」里的最后一条，其余判法不变。函数注释同步。
- **`ledger.py`**：`EVENTS` 增加 `"ship": {"attempt": ATTEMPT, "pr": NONEMPTY, "verdict": _one_of("ready", "draft"), "commit": STR}`。
- **`timeline.py report`**：
  - 「批准 → PR 打开」优先取账本里第一条 ship 事件的 `at`（ISO 时间，解析方式与 timeline 行一致，按 UTC）；
  - 没有 ship 事件（或账本读不出）时，照旧取最后一条 pr-open 行；
  - 文件头注释同步。
