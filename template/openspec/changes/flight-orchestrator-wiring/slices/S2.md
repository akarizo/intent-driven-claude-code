# S2 · 评审员看第一父 diff

## 做什么
控制面交给评审员的 commit 是 `--no-ff` 合并提交。对没有冲突的合并提交，`git show <commit>` 不输出 diff（3a 评审实测 `git show 712f5d9` 只有提交头），评审员会以为「无变更」而放行。

1. `template/plugins/flight/hooks/prompts.ts` 的 `reviewerPrompt`：取改动的指令改为 `` `git diff ${x.commit}^1 ${x.commit}` ``；提示词里不再出现 `git show`。同时写明：取不到 diff 或 diff 为空，就提交一条 severity 为 HIGH 的 finding，summary 写「取 diff 失败」，不得提交空列表。
2. `template/plugins/flight/agents/reviewer.md`：第 13、22 行（「只看给定 commit」与流程第 2 步）同样改用 `git diff <commit>^1 <commit>`，并把「取不到 → 提交一条说明『取 diff 失败』的 finding」明确为 **HIGH**。正文里不得再出现 `git show`。frontmatter 不动（3a 的 `agent-files-declare-flight-types` 仍须通过）。
