## 现状（主会话已核实）
- `progName` 只去掉首尾一层引号。
- `parseGit` 的 `head` 同样只去首尾引号；`sub`、`globals` 原样保留。
- `segmentsVerdict` 用 `toks[0] === 'cd'` / `'pushd'` / `'popd'` / `'export'` 做字面比较。

因此下面这些命令都能绕过拒绝表或 worktree 限制：
- `\git push`、`git "push"`、`g''it push`、`git p\ush`；
- `\cd /repo && git commit`、`\bash -c 'git push'`、`git commit "--amend"`。

## 做什么（`template/plugins/flight/hooks/envelope.ts`，design D7）

### 1. 新增 `shellWord(t: string): string | null`
对单个词做 shell 去引号：
- 单引号内原样保留；
- 双引号内，`\` 只转义 `$`、反引号、`"`、`\`；
- 引号外，`\x` 变成 `x`；
- 不配对的引号按字面去掉，不报错。被分段切开的 `"$(cat msg)"` 会留下单独一个 `"`，这种情况要能正常处理。
- 单引号外出现 `$` 或反引号时，返回 `null`。

### 2. 在这些位置先做 shellWord 再判断
- **`progName`**：取 `shellWord` 结果的 basename，结果为 null 时返回空串。这一处覆盖前缀命令表、`eval` / `bash -c` 识别、读标准输入的解释器。
- **`segmentsVerdict`**：`cd` / `pushd` / `popd` / `export` 的识别用 `shellWord(toks[0])`。
- **`parseGit`**：
  - 程序名（`head`）用 `shellWord` 的 basename 判是否为 `git`；
  - 全局选项按 `shellWord` 后的值判断（`-C`、`--git-dir` 等）。选项的参数照旧交给 `resolveDir`，它已经会把 `$` 判为无法判定；
  - 子命令取 `shellWord` 后的值；
  - `args` 逐个去引号，结果为 null 的保持原样。这样 `hasOpt` 能认出 `"--amend"`。
- **`bashUpgradable`**：判 `cd` 的地方也用去引号后的命令名。

### 3. 无法判定 → 拒绝（理由含「无法判定」）
- 命令名（`words(seg).toks[0]`）不为空且 `shellWord` 为 null，例如 `$G`、`${GIT:-git}`，或 `$(which git) push` 切出来的 `$` 段。
- git 调用的子命令或某个全局选项的 `shellWord` 为 null，例如 `git $SUB origin`。
- **反引号命令替换出现在命令名位置**：在原始命令里，从某个起始反引号往前，到上一个分隔符（开头、`&&`、`||`、`;`、`|`、`&`、换行、`(`）为止，中间除了 `VAR=val` 与前缀命令（`PREFIX_OPTS`）以外没有别的词。这一步在 `bashVerdict` 切段之前做；切段后反引号已丢失。
- 拒绝理由示例：`<角色>的命令名无法判定（含 $ 或反引号等 shell 展开）：写成脚本文件再运行`。

### 4. ceiling 写进注释
- 参数里的展开不判，`git commit -m "$(cat msg)"` 仍放行；
- 双引号里的反引号不判；
- 引号内的分隔符照旧切段。
