## 先读：#53 的教训
- 判定全在 `armed.ts`，本片只做接线：读写会话状态、在各事件上调用 `nextStep`、执行结果。不要在本文件里再写一套分类或预算。
- **`$.prompt.submit` 不能在 `command.run` 的处理中调用**，引擎会拒绝，不 await 也一样。实测原文：「called from a command.run hook, it would wait on the turn this hook is holding」。必须在 `$.clock.after(0, () => …)` 的回调里调用。
- **主会话一轮结束**：注册 `on('turn.complete', { turnId: /./ }, …)`，只处理 `e.agentId` 为空的轮次。实测：这是本插件在 `turn.complete` 上的第三个 hook，可以与 `register.tsx` 不带 matcher 的那个、本文件 `{ agentId: /./ }` 的那个共存。
- 本地命令本身不产生 `turn.complete`。

## 做什么（design D2–D6；spec `flight-armed-takeoff` 的后四条要求）

### `template/plugins/flight/hooks/orchestrator.tsx`
1. **会话状态**：`const armedAtom = atom({ plugin: 'flight', key: 'armed' } as const, { items: {} } as FlightArmed)`，用 `read` / `update`（与 `panel` 同法）。`Arm` 与 `FlightArmedItem` 字段一一对应，直接存取。
2. **起飞 + 被拒即待命**：写一个本文件内的 `takeoffArmed($, args, opts)`，供以下三处调用：
   - `/opsx-apply` 的 `command.run`（第 894 行）；
   - `/flight resume`（`flightCommand`，第 868 行）；
   - `takeoffNow` 的 `entry`。

   它的流程：
   1. 调 `takeoff` 拿回复；
   2. 回复以「✈ 起飞」或「续飞 attempt」开头即成功：清除该 change 的待命，原样返回；
   3. 被拒时 `cls = classifyRefusal(text)`：
      - human / human-key：经 `ctx.notify` 发 `humanText`，原样返回，不写待命；
      - 其余：`armOf(...)` 写入会话状态，立刻以 `refused` 求一次 `nextStep` 并执行（见第 3 条），状态行显示 `armedLine`，通知一次，回复为原文加一行「已进入起飞待命：<原因首行>」。
   4. 人再发同一 change 的起飞，用新待命覆盖旧的。
3. **执行 `ArmStep`**（`$` 都来自触发它的那个 hook）：
   - `retry`：`beforeRetry` 后再调 `takeoff`。成功 → 清除待命，通知「<change> 已起飞」。又被拒 → `refusedAgain` 后以 `refused` 再求一次 `nextStep` 并执行。
   - `submit`：`$.clock.after(0, () => void $.prompt.submit({ text }))`，并把 `awaitingModel` 置真。
   - `wait`：有 `ms` 时 `$.clock.after(ms, …)`，到点以 `timer` 求下一步。
   - `give-up`：清除待命，`ctx.notify(giveUpText(arm, reason))`，清掉状态行。
4. **推进事件**：
   - 看门狗计时器的 `watchTick` 末尾对全部待命以 `tick` 推进；
   - `{ agentId: /./ }` 的 `turn.complete` 里，agent 所属 change 有待命时以 `agent-ended` 推进；
   - 新增 `{ turnId: /./ }` 的 `turn.complete`，只处理 agentId 为空的轮次，对 `awaitingModel` 的待命以 `main-turn` 推进。
5. **偶发失败留证据**：transient 类被拒时，change 账本可读就追加 `ev.diag(b, { attempt, where: 'takeoff', error: <原因首行> })`。attempt 取账本当前 attempt，没有起飞过时为 0。
6. **取消**：`flightCommand` 的 `abort` 分支（第 880 行附近）先看该 change 是否待命中：
   - 是 → 清除，回复「flight：已取消 <change> 的起飞待命」（须含「已取消起飞待命」）；
   - 不必有在飞飞行；`locate` 失败且有同名待命时也要能取消。
7. **`takeoffNow` 的 `entry` 换成 `takeoffArmed`**，签名不变。

## 现有用例要改（本片 owns）
- **断言 `/opsx-apply` 拒绝原文的用例**：human 类的回复不变；wait / transient / model 类的回复多了一行「已进入起飞待命」。逐个看现有用例（例如 preflight 红、指纹失败、lint 红相关的），把精确匹配改为断言首行或 `toContain`，不删断言。
- **被拒后起的 `clock.after` / `prompt.submit`**：现有世界若推进时钟，可能触发重试或提交。没应答 `prompt.submit` 的世界会报 no implementation。在这类世界里补应答，或断言它的出现。
