# S3 · 批准带在按键处理之内起飞与续飞

依赖 S1：`orchestrator.tsx` 由 S1 先改，本片只在其中加两处导出。S2 在本片之后开启凭证强制，所以本片必须把凭证从按键一路传到 `takeoffNow`。接口见 `slices/_interfaces.md`。

## 先读
- **`template/plugins/flight/hooks/register.tsx`**：
  - `ui.press` hook（约第 520 行起）；
  - `startTakeoff` / `startResume`（约第 428–455 行）；
  - `depsOf`（约第 330 行）；
  - `finished`、`refreshQuietly`、`baselineTick`、`leaveBaseline`（约第 388–425 行）。
- **`orchestrator.tsx`**：
  - `takeoffNow` 与 `entry`（约第 750 行）；
  - 带 `cwd` matcher 的 session.start hook，`entry` 在这里造（约第 1192 行）；
  - `restoreStatus`（约第 807 行）。
- **为什么**：现在按键处理用 `clock.after(0)` 把起飞挪到回调里，派出的执行体因此绕过了包络与 measure（flight-armed-followups 首轮实况）。在按键 hook 里 await 起飞就不会。交互实测：按键 hook 挂起 120 秒，人照常输入；期间别的按键也会并发处理。
- **`$` 不出文件**：register 只 import `takeoffNow`、`restoreStatusNow`、`scenarioFiles` 与 `lease.ts`，不把 `$` 传给别的文件。

## 测试世界的已知事实（`flight.test.tsx`）
- **起飞守卫**：takeoff-gate.py 默认以 exit 3「未批准」作答，起飞停在守卫，`log.gates` 记下以哪个 change 起飞过。
  - `gatePasses` 放行；
  - `gateWait` 让守卫等一个 promise。
  - 本片的用例看 `log.gates` 判断「起飞已尝试」，不看账本 takeoff：测试世界的 lint 固定为红。
- **基线**：`world.baseline` 给基线结果（`{ exitCode, stdout }`），`world.baselineWait` 让基线等待，`log.baselines` 记录调用。
- **其他记录**：`log.toasts`、`log.statuses`、`log.notifies`。
- **重绘**：`ui.mount` 之后重新 `find` / `findAll` 即可看到最新的批准带。
- **按键返回之前的断言**：先不 await，`const p = ui.press(...)`；用 `until(() => …)` 等守卫被调用；断言完再放行，最后 `await p`。
- **「本片之后按键不再需要推进时钟」**：现有用例里 `await ui.press(...)` 之后的 `background(log)` / `advance(0)` 可以保留，只要断言仍成立。

## 做什么（design D3、D4、D6）

### 新建 `template/plugins/flight/hooks/lease.ts`
1. 按 `_interfaces.md` 写出 `Lease`、`LEASE_DENY`、`withLease`、`leaseDeny`：
   - `withLease` 先造 `{ alive: true }`，在 `finally` 里置 false，把 body 的结果或异常原样交回；
   - `leaseDeny`：缺失或 `alive` 为假时返回 `LEASE_DENY`。
   - 纯模块，文件头注释写明规则：派发只在处理外部事件、尚未返回的 hook 里，定时器回调拿不到活凭证。
   - `guardedSpawn` 由 S2 加，本片不写。

### `template/plugins/flight/hooks/orchestrator.tsx`（只加两处）
2. `takeoffNow(args, opts?: { resume?: boolean; lease?: Lease })` 与 `entry` 的 opts 类型加上 `lease`，原样传给 `takeoffArmed` 的 opts（`takeoffArmed` 的 opts 类型也加 `lease?: Lease`）。本片不使用它。
3. **`restoreStatusNow()`**：
   - 在造 `entry` 的同一个 session.start hook 里，再造 `statusEntry = () => restoreStatus($)`；
   - `export function restoreStatusNow(): Promise<void> { return statusEntry === undefined ? Promise.resolve() : statusEntry() }`。

### `template/plugins/flight/hooks/register.tsx`
4. **按键整体包在 `withLease` 里**：`ui.press` hook 的 body 改为 `return withLease(async lease => { …原有处理… })`，把 `lease` 传给 `startTakeoff` / `startResume`。
5. **进行中再按被拒**：解析出 change 之后，若 `inFlight.has(change)`，就 `toastQuietly($, 'flight：<change> 正在起飞，稍候')` 并返回 `{ element }`。这一条放在指纹核对与写 approve 之前。
6. **`startTakeoff($, item, lease)`**：
   - `inFlight.set(...)`，然后 `await refreshQuietly($)`；
   - `try`：`const text = await takeoffNow([change, AUTHORIZE], { lease })`，toast 与通知首行；
   - `catch`：通知「起飞失败」；
   - `finally`：`await finished($, change)`。
   - 不再用 `clock.after(0)`。
7. **`startResume($, item, replan, lease)`**：
   - 登记进行中；replan 时照旧先 `baselineTick`（它用 `clock.after` 刷新进度，只写状态行，可以留着），否则 `refreshQuietly`；
   - `try`：`await resumeFlight(depsOf($, item, lease), change, { replan })`；
   - `catch`：通知「续飞失败」；
   - `finally`：`await finished($, change)`，再 `await restoreStatusNow().catch(() => undefined)`。
8. **`depsOf($, item, lease)`**：`takeoff: (args, opts) => takeoffNow(args, { ...opts, lease })`。
9. **按键路径一律吞错**：凡是在按键处理里调用的重绘，都改用 `refreshQuietly`；进行中记录只在 `finally` 里删除。

## 现有用例要改（本片 owns，不改用例名，不删断言）
- `band-shows-busy-while-taking-off`、`band-shows-baseline-progress`：现在按键处理要等守卫或基线放行才返回。改成先 `const p = ui.press(...)`，`until` 等到守卫或基线被调用，读出批准带，放行之后再 `await p`。断言不变。
