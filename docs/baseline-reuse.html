基线增量复用：改一点计划不再重跑全量

案例：afa · change b737-post-hooks-merge-split-params · 2026-10-14 · 实测数据来自会话转录 f59f474c 与 gate-baseline.json

结论
  1. 这次的第二遍基线本来就不用跑：现在在 afa 里跑 slice-gate.py preflight 直接通过（rc=0）。只改了一个测试文件、spec 和切片包，没动 gate 命令和 verify，plan_sha 没变。打算重跑是模型自己判断的，没有任何机械判据要求重跑。
  2. 但不能只靠「先跑 preflight」：plan_sha 只认命令字符串。测试文件、verify 脚本的内容变了，它看不出来，有漏洞，宽进了。
  3. 推荐：基线按「依赖什么」拆成三层，各算各的指纹，只重跑指纹变了的那层。全量层只在代码树变了时重跑；只改了测试文件时，只补跑这些文件。本例约 10 分钟 → 只剩 S1/S2 verify 加 1 个文件（耗时还没实测）。判据比现在更严。

2 · 第一性原理：基线到底测的是什么

层产出本例耗时真正依赖（指纹应包含）现在的 plan_sha 认不认
全量层预存红集（168 条），final 按它做差分447s代码树（HEAD + 工作区里非测试文件的改动）· gate.test 命令 · 它引用的脚本内容只认命令字符串 ⚠ 脚本内容改了认不出
增量测试层新增或改动的 test_*.py 在基线上的结果秒级这些测试文件的内容完全不认
verify 层每片 verify 在基线上必须绿≈2 分钟（3 片合计）每片 verify 命令 · 它覆盖的测试文件内容只认命令 ⚠ 测试内容改了认不出
lint / typecheck既有输出行，按行做差分秒级owns 文件内容 · 命令只认命令

要点：全量层的预存红集是代码树的函数，跟计划工件（spec / slices / 切片包）没关系；往新测试文件里加 strict-xfail 用例也不会改变其他文件的结果。所以「改计划 → 重跑全量」是把两件不相干的事绑在了一起。

3 · 方案分档

档 1 · 只改文档零代码

propose 的命令文档与 skill 写明：改完计划后不凭判断重跑，先跑 preflight，绿了就不跑。

＋ 本例立刻省 10 分钟

－ 继承 plan_sha 的漏洞：新测试本身坏了（例如护栏在 base 上就红）也会放行，起飞后 G5 才炸（参考 shelve S3 三次停飞）

档 2 · 分层指纹 + 增量基线推荐

改 slice-gate.py 的 baseline / preflight；插件的「批准修订并续飞」走的也是 baseline，自动受益，不用改 TS。

＋ 省时，而且补上了现有漏洞（判得更严，不是放宽）

＋ 零 token：脚本判定，模型只管调用

－ 跨文件副作用（conftest、全局状态）要保守处理：凡是动了非 test_*.py 的文件就回到全量

档 3 · 跨 change 复用全量已定：做

全量结果存进 git common dir 下的基线池，同一仓库的各 worktree 共享。命令指纹 = 命令文本（本 change 路径换成占位符）+ 命令里直接引用的脚本内容；被 source 的 _env.sh 不计入。仓外（raw-dlib、解释器环境）不检测；仓内任何非测试改动都回全量。

－ 实测命中率有限：afa 历次基线的 commit 之间，executor/ 里都有 6–56 个源码改动。主要在「同一 main commit 上连续开 change」「之间只改了测试文件」时命中

4 · 档 2 判定流程（baseline 自己判断，模型不判）

slice-gate.py baseline --change-dir D            （--full 强制全量）
 │
 ├─ 无旧基线 / 旧基线红 / commit 变了 / gate.test 命令或脚本内容变了 ──► 全量（同现在）
 │
 ├─ 自旧基线以来工作区变动 Δ（排除本 change 的计划工件：spec/slices/切片包/tasks/html）
 │    ├─ Δ 含任何非 test_*.py 文件（conftest / helpers / 源码 / 配置）──► 全量
 │    └─ Δ 只有 test_*.py ──► 增量：gate.pytest 只跑 Δ 这些文件
 │                            补跑不红、且旧预存红不涉 Δ 文件 → 预存红集沿用旧集；否则全量
 │
 ├─ verify：只重跑「命令变了」或「覆盖到 Δ 文件」的片；其余沿用旧 exit
 ├─ lint / typecheck：每次都重跑（便宜）
 └─ 写 gate-baseline.json：layers{full_key, files_sha{path:sha}, verify_key{S:sha}} + mode: full|incremental
                          stdout 一行：「复用全量（commit 同，Δ=1 个测试文件，增量 N 秒）」

preflight：用同一套分层指纹判过期（commit、命令、脚本内容、测试文件 sha、verify 覆盖文件 sha）
           任何一层对不上 ──► 「基线过期：<哪一层> 变了」

本例落到「只有 test_*.py」那一支：Δ = test_dlib_post_hooks_merge_split_rules.py → 增量跑 1 个文件；verify 只重跑 S1、S2（它们覆盖这个文件），S3 沿用旧结果。
