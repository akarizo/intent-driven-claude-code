Why · 01为何而做

阶段 3 的最后一块是交互（路线图 D8 / D9）。飞行现在只有一行状态行可看，还有三个缺口：

- 人无法中途停下一次飞行：控制面自动停飞时也不终止已派出的 agent（#39 遗留）。 - 续飞没有独立入口：要靠「再发一次 /opsx-apply」，续飞和新起飞在命令上分不开。 - 看不到各片进度：wave、门禁、测量、评审、修复、final 都没有地方集中显示。

flight-retire-workflow-engine（#49）合入时还暴露了两个问题：

- 主检出没快进，插件照样起飞：#48、#49 两次飞行都由 #46 版的旧判定器判，guards 与逐目标先红实际没有被执行过。起飞时没有任何机械检查能发现判定器过旧。 - #49 评审留下三条 MEDIUM： - /opsx-apply 命令的 Guardrails 仍写「PreToolUse hook」，与同名 skill 不一致； - 安装器只列出退役文件，没说明它们仍可被调用、且不再受起飞批准拦截； - apply skill 的「读到即停飞」一段，在用户用自然语言触发 skill 时会误判为插件缺席。

2026-10-12 实测（CLI 2.1.296，无头模式，default 与 bypass 两种权限模式都试过）：插件可以经 $.tool.call({ tool: 'TaskStop', task_id: <agentId> }) 停掉自己派出的 agent，不弹权限询问。停下后 turn.complete 立即到达（reason 为 aborted），classic.SubagentStop 不触发。

What · 02变更范围

  • /flight 命令（插件注册），四个子命令：
  • /flight status [<change>]：按账本打印本次 attempt 的进度：各 wave、各片所处阶段、门禁红次数、测量见红、评审、修复、final 与落地或停飞。
  • /flight panel [<change>]：打开飞行面板。
  • /flight abort [<change>]（用户定：只有人工中止才停 agent）：
  • 只处理本会话起飞的在飞 attempt；
  • 先在账本记停飞（人工中止（/flight abort）），再用 TaskStop 停掉本 attempt 在飞的 agent，回复里逐个列出停下或没停下的；
  • 被停的 agent 留在 worktree 里的未提交改动，续飞时照旧续接。
  • /flight resume <change> [--takeover] [授权提交]（用户定）：只续未落地的 attempt，按同一份计划走起飞路径；从未起飞或已落地时拒绝并说明。
  • 飞行面板（用户定：起飞时自动打开）：内容与 /flight status 相同，随控制面推进实时刷新。
  • 起飞核对判定器能力（用户定）：
  • slice-gate.py features 列出判定器支持的能力；
  • 插件起飞前核对自己需要的能力（evidence-ledger-only、g5-per-target、guards），缺一项就拒飞，并提示先把主检出更新到与插件同一版本。
  • #49 的三条 MEDIUM：
  • /opsx-apply 的 Guardrails 改成与 skill 一致；
  • 安装器写明退役文件仍可被调用、且不再受起飞批准拦截，请尽快删除；
  • 命令与 skill 的「读到即停飞」一段区分「本轮是否发过 /opsx-apply」。
  • 文档与版本：/opsx-apply 命令、skill 与 README 写明 /flight 的用法；插件版本 0.6.0。
判定器：template/.claude/hooks/slice-gate.py，新增 features 子命令。插件：template/plugins/flight/hooks/ 下的 versions.ts、core.ts、orchestrator.tsx，新增 abort.ts；types/index.d.ts 新增面板状态；版本 0.6.0。文档：template/.claude/commands/opsx-apply.md、template/.claude/skills/openspec-apply-change/SKILL.md、install.sh、README.md。本 change 自己的飞行：插件 0.5.0 不核对判定器能力。起飞前主检出须在 f42ebcb（已核对）。

Specs · 04行为规范 (Gherkin)

flight-abort ADDED

Requirement: 人工中止先记停飞再停 agent

abortFlight 对本会话起飞的在飞 attempt SHALL 先记停飞（原因「人工中止（/flight abort）」），停飞写入成功后 SHALL 对本 attempt 每个在飞的 agent 调用停止，回复逐个列出已停与未停（附原因），并提示可用 /flight resume <change> 续飞；停飞写入失败时 SHALL 不停任何 agent 并如实回复。 Feature: 用户定：只有 /flight abort 停 agent；实测 TaskStop 停下后 turn.complete 到达，先记停飞才能让控制面不再推进

Scenario: abort-halts-then-stops-live-agents

  • GIVEN本会话起飞的 demo attempt 1 在飞，在飞的 agent 为 a2、a3，停 a3 会失败（原因「not found」）
  • WHEN调用 abortFlight
  • THEN先调用一次 halt（原因含「人工中止」），之后才依次停 a2、a3
  • AND回复含 a2「已停」、a3「未停」与「not found」，并含 /flight resume demo

Requirement: 没有本会话的在飞 attempt 时不动作

没有 takeoff、本 attempt 已落地或停飞时，abortFlight SHALL 回复「没有在飞的 attempt」；最新 takeoff 来自另一个会话时 SHALL 回复「另一个会话」并指明到那个会话里中止；两种情况都 SHALL NOT 记停飞、SHALL NOT 停任何 agent。 Feature: TaskStop 只认本会话的任务

Scenario: abort-refuses-without-own-flight

  • GIVEN三份账本：
  • WHEN分别调用 abortFlight（本会话 sess-1）
  • THEN第一、三份回复含「没有在飞的 attempt」，第二份含「另一个会话」与 other-se
  • AND三次都没有调用 halt 或 stop

Design · 05技术设计

Context

- 状态的唯一来源：飞行状态全部在账本 refs/flight/<change>/ledger 里，由 core.reduce 归约成 State。现有的状态行（orchestrator.tsx 的 showStatus）只显示 wave、运行数与阻断数。 - 停飞路径：landing.tsx 的 runLandingAction(ctx, f, { kind: 'halt', reason }) 记停飞事件并提交记录。之后 driveNow 看到这个 attempt 已停飞，就不再推进。已派出的 agent 不会被终止。 - 起飞路径：orchestrator.tsx 的 takeoff($, args) 依次做这些核对： 1. 版本下限； 2. 定位 worktree 与 change 目录； 3. takeoff-gate； 4. git 版本； 5. checkPluginCopy、checkJudges（ledger.py events）； 6. 跨会话； 7. 工作区与授权提交； 8. lint / preflight； 9. 指纹。

核对完写 takeoff 事件，再 drive。再发 /opsx-apply 时，就从账本续飞。 - 插件 API 实测（2026-10-12，CLI 2.1.296，无头模式，default 与 bypass 两种权限模式都试过，scratchpad/mods/abort-spike）： - 停止：$.tool.call({ tool: 'TaskStop', task_id }) 能停掉插件自己派出的 agent，不弹询问，返回 { result: { message: 'Successfully stopped task: …' } }； - 列表状态：$.agent.list 里该 agent 的状态由 running 变为 killed； - 结束事件：turn.complete 立即到达（reason: 'aborted'、isAborted: true），classic.SubagentStop 不触发。 - 测试世界可模拟：command.register、agent.list、tool.call、ui.open 都是可挂 hook 的事件（flight.test.tsx 与 orchestrator.test.tsx 已在用前三个）。

Goals / Non-Goals

Goals - 人能随时看到飞行进度（/flight status、面板），能中止本会话起飞的飞行并停下在飞的 agent，能显式续飞未落地的 attempt。 - 判定器能力不足（主检出未快进）时，在起飞前机械地拒飞。 - 收掉 #49 的三条 MEDIUM。

Non-Goals - 自动停飞不停 agent（用户定）：指纹变化、账本读失败等仍只记停飞。 - 不中止另一个会话的飞行：TaskStop 只认本会话的任务。 - 「SubagentStop hook skipped: python3 aborted」成因：仍未查明。实测排除了「重复触发」和「hook 预算」两种解释，需要在真实飞行里开 claude --debug 定位，不在本 change 处理。 - 包络兜底与 /pr-ship 进插件：各自另立 change。

Decisions

slice-gate.py features

每行打印一项能力，退出 0。本次声明三项：

evidence-ledger-only

G5 只按账本判；

g5-per-target

逐目标先红；

guards

切片护栏。

versions.ts 的 checkJudges

在核对 ledger.py events 之后，再跑 slice-gate.py features。

子命令不存在（退出码非 0）

拒飞，原因写「判定器过旧（slice-gate.py 没有 features 子命令）」，后接 UPDATE_MAIN；

缺少 REQUIRED_FEATURES（导出常量，就是上面三项）中的任一项

拒飞，原因写「判定器缺少能力 <列表>」，后接 UPDATE_MAIN。

调用方不改

checkJudges 的调用签名不变，所需能力用模块常量，orchestrator 不需要改动。

首行

✈ <change> · attempt <n> · W<i>/<n> · <end>；

每片一行

<id> W<wave> <phase> · 门禁红 <reds> · 测量 <measured> · 评审 <review>；

末行

修复 <fix> · final <final>。

注册

在 session.start（带 cwd matcher 的那个 hook）里调用 $.command.register({ name: 'flight', description: '飞行：status | panel | abort | resume' })，由 command.run { command: 'flight' } 分派。

抽出 locate($, name)

把 takeoff 里「定位 worktree、change 目录、判定器目录、构造 Flight」的部分抽成这个函数，供 takeoff / status / resume 共用，起飞行为不变。

省略 <change>

本进程只有一个在飞的 flight（flights 与 active）时取它；否则回复用法，要求给出 change 名。

四个子命令
status

读账本，summaryLines(summarize(state)).join('\n')。

panel

先刷新面板状态，再 $.ui.open({ id: 'flight', title: '✈ <change>' })。

abort

调用 abortFlight，传入的三个函数如下。之后刷新状态行与面板。

halt

调用 runLandingAction(ctx, f, { kind: 'halt', reason })，再读账本确认停飞事件已写入；

live

本 attempt 的 dispatch 去掉已有 ended 的，再与 $.agent.list() 中状态属于 LIVE 的取交集；

stop

$.tool.call({ tool: 'TaskStop', task_id })，抛错返回原因。

resume

调用 takeoff($, args, { resume: true })。takeoff 读到账本后（跨会话判断那里）：

账本没有 takeoff

返回「<change> 从未起飞：用 /opsx-apply <change>」；

最新 attempt 已落地

返回「<change> 已落地（attempt <n>），没有可续飞的」；

其余照常起飞。回复前加一行「续飞 attempt <n>

已合回 <k> 片跳过」。

Risks / Trade-offs

TaskStop 的兼容性

TaskStop 是内置工具，其输入 task_id 接受 agentId 是实测结论（2.1.296），引擎升级可能改变。abort 停不下时会在回复里列出原因，停飞事件照样已写入，控制面不会再推进。

能力核对会拦住老判定器

只要主检出没快进就拒飞。这正是本 change 要的行为，提示里写明怎么处理。

面板挤占终端宽度

窄终端由引擎挂起（不显示），状态行仍在。
