## 做什么

### 1. `template/.claude/hooks/spec_html.py`（design D6）
`render_flight` 的 Scenario 状态表：
- 读取每个切片的 `guards`；
- 护栏 scenario 那一行，在状态格的状态标签前加 `<span class="chip" data-state="guard">护栏</span>`；
- 非护栏行不变；
- 样式表给 `data-state="guard"` 一个与现有状态标签同风格的配色，亮色、暗色两套都要有。

### 2. 规划文档（design D5，命令与同名 skill 同改，禁漂移）
- **`template/openspec/schemas/intent-driven/schema.yaml`**，tasks instruction：
  - `slices.json` 结构说明里加切片字段 `guards`：scenario id 列表，须是本片 `scenarios` 的子集，缺省为空；
  - 描述 strict-xfail 骨架的段落后补一段**护栏 scenario**：
    - 行为在 base 上已成立的 scenario（保持原行为、不回归）列进所属切片的 `guards`；
    - 它的测试在规划时写完整、不带 xfail，base 上须通过；
    - G5 只豁免 `guards` 里、且起点测量已通过的目标；
    - 其余 scenario 照旧用 strict-xfail 骨架。
- **`template/.claude/commands/opsx-propose.md` 与 `template/.claude/skills/openspec-propose/SKILL.md`**：在「tasks 阶段额外产出」那条之后补同样的护栏说明（一两句即可，详见 schema）。「verify 在基线上必须绿（骨架是 strict-xfail）」处补上「护栏测试不带 xfail、须已通过」。
- **`template/.claude/commands/opsx-continue.md` 与 `template/.claude/skills/openspec-continue-change/SKILL.md`**：tasks.md 那条里同样补上护栏说明。

### 3. `template/plugins/flight/agents/executor.md`
「TDD（测量协议）」那一条补充三点：
- G5 逐个目标判：先把本片全部 scenario 测试写好、测一次红，再写实现；**改源码后的红不算**；
- `guards` 里的护栏 scenario 测试已经写好、起点即通过，不需要先红；
- 某个非护栏目标在改生产代码前就已通过时，不得改坏生产代码来造红：照实收口，写明是哪个 scenario。

### 4. `template/openspec/adr/DRAFT-flight-measure-protocol.md`（仍是草案，直接改）
- 第 2 条「起点测量与豁免」的豁免规则改为：只有切片 `guards` 列出的护栏 scenario 的目标免于先红，且须在起点测量里已通过（人批准 + 控制面测到）。
- 写明 G5 逐目标判、改源码后的红不算。
