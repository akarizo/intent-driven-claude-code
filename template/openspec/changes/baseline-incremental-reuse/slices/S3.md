### `opsx-propose.md` 与 `openspec-propose/SKILL.md` 第 5 步（两份同改）
在现有说明之后补这几条，措辞须满足测试断言：
- 脚本自己判断跑全量还是**增量**：
  - 自上次基线以来，代码树只有 `test_*.py` 变了（计划工件不计）、且补跑这些文件不红 → 复用上次的全量结论，只补跑这些测试文件；
  - verify 只重跑受影响的片；
  - lint / typecheck 照跑。
- **跨 change** 复用：同一仓库其他 change 跑过的全量，命令指纹相同、代码树之差只有测试文件时，同样复用。基线池在 git common dir 下。
- 写成单独一行：**改完计划后重跑 `slice-gate.py baseline`**，由脚本判全量或增量；模型不自行判断要不要重跑。preflight 会按内容判基线是否过期。
- `--full` 强制全量：仓外环境（数据仓、解释器）变了，或被 source 的门禁脚本改了时用。
- 一行报告加一种格式：「基线绿（增量：复用 <change> 的全量，补跑 n 个测试文件 t 秒；预存红 k 条）」。

### `README.md`
飞行说明里加一条：基线按内容指纹增量复用。只改了测试文件时不重跑全量；同一仓库跨 change 复用；`--full` 强制全量。
