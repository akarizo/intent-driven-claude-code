# S1 · envelope.ts 收紧：Bash 改写函数、git 作用目标、拒绝表补齐、白名单收紧、读取免询问限于仓库内

## 做什么
`template/plugins/flight/hooks/envelope.ts`（纯函数）：
- 不碰 `$`，没有 Node：路径处理用文件里已有的 `normalizePath`。
- **新增参数一律可选**：`orchestrator.tsx` 现在按旧签名调用，接线由 S4 做。本片不能让现有调用变红。

规则以 design.md 的 D1–D5 为准：

1. **D1** · 新增 `export function inWorktree(command: string, worktree: string): string`：
   - 返回 `cd '<worktree>' && <command>`；worktree 里的 `'` 写成 `'\''`；
   - command 已经以同一前缀开头时，原样返回。
2. **D2** · `bashVerdict(role, command, worktree?: string, mainTree?: string)`：
   - 给了 `worktree` 时，按 D2 求每个 git 段的作用目录。依次看：`-C`（可多次，逐级拼接；相对路径而前面又没有绝对基准时，判为「无法判定」）、`--git-dir=` / `--git-dir <p>`、`--work-tree`、同一命令前面某段 `cd <绝对路径>`。都没有时，作用目录就是 worktree。
   - 子命令不在 `READONLY_SUBS` 里，且作用目录不在 worktree 内（规范化后带 `/` 边界的前缀判断）→ 拒绝，理由含「自己的 worktree」并给出该路径。
   - 只读子命令的作用目录在 `mainTree` 内即放行。
3. **D3** · 拒绝表：
   - 子命令 `pull`；`config` 除 `--get`、`--get-all`、`--get-regexp`、`--get-urlmatch`、`--list`、`-l` 之外一律拒绝。
   - 全局 `-c` 的值、`--config-env` 的值，键名（`=` 之前）小写后等于 `core.hookspath` → 拒绝。
   - `hasOpt` 的长选项门槛改为 `--` 之后至少 1 个字符：`--am`、`--d` 都要能命中。
   - **读标准输入的解释器**：段的程序名（跳过前导 `VAR=`；取 basename）属于 `python`、`python3`、`python3.x`、`node`、`bash`、`sh`、`zsh`、`ruby`、`perl`，且参数中有单独的 `-` 或 `-s` → 拒绝。整条命令含 `/dev/stdin` 也拒绝。理由含「写成脚本文件再运行」。
   - **heredoc**：整条命令含 `<<`（`<<<` 也算）→ 拒绝，理由含「Write」。
4. **D4** · `bashUpgradable(role, command, commands, worktree?: string, mainTree?: string)`：
   - 任何一段带前导 `VAR=` → false。
   - 给了 worktree 时：开头一段是 `cd '<worktree>'` 或 `cd <worktree>`、且目标正是自己的 worktree → 视为白名单段。
   - git 段的作用目录：只读子命令要在 `mainTree` 内，`add` / `commit` 要在 worktree 内，否则 false。
   - 其余沿用现有逻辑。
5. **D5** · 新增 `export function readUpgradable(tool: string, input: unknown, worktree: string, mainTree: string): boolean`：
   - Read 取 `file_path`，Grep / Glob 取 `path`，缺省时为 worktree；
   - 规范化后在 `mainTree` 内（含 `mainTree` 本身）→ true；
   - 其他工具 → false。
