## 做什么（`template/plugins/flight/hooks/orchestrator.tsx`，design D4、D5、D8）

### 1. 抽出 `locate`
把 `takeoff` 里「解析 change 名 → 找 worktree → 找 change 目录 → 找判定器目录 → 构造 Flight」的部分，抽成 `locate($, name)`：
- 成功返回 `{ f, tree, main }`，失败返回 `{ error }`；
- `takeoff` 改为调用它，起飞行为与回复文本都不变。

### 2. 注册 `/flight`
在带 `{ cwd: /^/ }` matcher 的 `session.start` hook 里，加上 `await $.command.register({ name: 'flight', description: '飞行：status | panel | abort | resume' })`，失败时忽略。

### 3. `command.run { command: 'flight' }` 分派
- **change 的取法**：给出 change 名就用它；省略时，本进程 `flights` 里只有一个 change 且它在 `active` 中，就取它；否则回复用法并要求给出 change 名。
- **来源守卫（design D8）**：
  - `abort` 与 `resume` 在做任何事之前先查 `e.origin?.kind`，只认 `composer` 与 `bridge`；
  - 其余来源（含 `undefined`）回复 `flight：/flight <子命令> 会写账本，只接受人在终端发出（本次来源：<kind，未标明时写「未标明」>）`，不读写账本、不停 agent；
  - `status` 与 `panel` 不查来源。
- **四个子命令**：
  - **`status [<change>]`**：`locate` 后读账本，回复 `summaryLines(summarize(reduce(events))).join('\n')`。账本里没有 takeoff 时，回复「<change> 尚未起飞」。
  - **`panel [<change>]`**：用账本刷新面板 atom，再 `$.ui.open({ id: 'flight', title: '✈ <change>' })`，回复「已打开飞行面板」。
  - **`abort [<change>]`**：调用 `abortFlight`，三个回调如下，之后调用 `showStatus` 刷新：
    - `halt`：`runLandingAction(ctx, f, { kind: 'halt', reason })`，之后重读账本，确认本 attempt 有 halt 事件，有则返回 true；
    - `live`：本 attempt 的 dispatch 里，去掉已有 `ended` 的 agent，再与 `$.agent.list()` 中状态属于 `LIVE` 的 agent 取交集；
    - `stop`：`await $.tool.call({ tool: 'TaskStop', task_id: id } as never)`，抛错时返回错误首行。
  - **`resume <change> [--takeover] [授权提交]`**：调用 `takeoff($, args, { resume: true })`。`takeoff` 读到账本（跨会话判断处）后：
    - 没有 takeoff：返回 `flight：<change> 从未起飞：用 /opsx-apply <change>`；
    - 最新 attempt 已落地：返回 `flight：<change> 已落地（attempt <n>），没有可续飞的`；
    - 其余照常；成功回复前加一行 `续飞 attempt <n>：已合回 <k> 片跳过`。
- **其他参数**：回复用法：`/flight status|panel|abort [<change>] · /flight resume <change> [--takeover]`。
- **异常**：`command.run` 的 hook 加 `.catch`，异常时回复 `flight：/flight 出错（<首行>）`，与 `/opsx-apply` 的写法一致。

### 4. 面板
- **atom**：`types/index.d.ts` 的 `PluginState.flight` 增加 `panel: FlightPanel`，即 `{ change: string; lines: string[] }`，并导出 `FlightPanel` 类型。用法与 `register.tsx` 的批准带 atom 相同：`atom({ plugin: 'flight', key: 'panel' }, { change: '', lines: [] })`。
- **刷新**：`showStatus` 在设置状态行的同时，`void update($, panel, () => ({ change: f.change, lines: summaryLines(summarize(state)) }))`。
- **绘制**：新增 `ui.render { component: 'Pane', requestId: 'flight' }`，每行一个 `Text`；`lines` 为空时显示「尚无飞行」。
- **自动打开**：`takeoff` 成功（写入 takeoff 事件并 drive 之后、返回起飞文本之前）调用 `void $.ui.open({ id: 'flight', title: '✈ <change>' })`。

### 5. 守卫测试（`flight.test.tsx` 与 `tests/test_flight_plugin.py`）
- **`no-model-callable-approval-path`**：`expect(log.commands).toEqual(['flight'])`。
- **`only-findings-tool-registered`**：
  - 登记的命令同样期望 `['flight']`；
  - 在六次工具调用之后，再以 `origin: { kind: 'composer' }` 依次发出 `/flight status demo`、`/flight abort demo`、`/flight resume demo`；
