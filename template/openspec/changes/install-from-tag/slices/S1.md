## 契约

```text
install.sh 的 pipe 模式（脚本旁边没有 template/）
  ref = IDT_BRANCH，缺省 main，可以是分支或 tag
  依次尝试 $REPO_URL/archive/refs/heads/$ref.tar.gz → $REPO_URL/archive/refs/tags/$ref.tar.gz
    成功 → 解压到 $TMP（--strip-components=1）
    都失败 → [err] 行列出两个地址；exit 4；不创建目标目录
  $TMP/install.sh 不存在 → [err]，exit 4
  交接：UPGRADE=1 → bash "$TMP/install.sh" --upgrade "$TARGET" </dev/null
        否则      → bash "$TMP/install.sh" "$TARGET" </dev/null
        退出码原样作为整体退出码；EXIT trap 删 $TMP
本地模式（脚本旁边有 template/）：一字不改
--help：IDT_BRANCH 一行写明「分支或 tag」；文件头管道用法注释同步提一句 IDT_BRANCH
```

README：在 `### 一键更新（已装项目）` 之前新增 `### 安装指定版本`，内容包括：
- pipe 写法：`curl -fsSL https://raw.githubusercontent.com/akarizo/intent-driven-claude-code/main/install.sh | IDT_BRANCH=stable-v2.0 bash -s -- ~/path/to/your-project`
- clone 写法：`git clone --depth 1 --branch stable-v2.0 https://github.com/akarizo/intent-driven-claude-code.git /tmp/idt` + `/tmp/idt/install.sh ~/path/to/your-project`
- 去哪查可用 tag：GitHub Tags 页，或 `git ls-remote --tags https://github.com/akarizo/intent-driven-claude-code`
- 警示 1：不要从 tag 路径（`raw…/<tag>/install.sh`）取脚本走管道，老脚本缺省装的是 main
- 警示 2：不支持用 `--upgrade` 把已装新版的项目降级（新版多出的文件不会删，settings 里已合入的 hooks 会保留）

## 坑

- ⚠ macOS 自带 bash 3.2：`set -u` 下展开空数组（`"${arr[@]}"`）会报 unbound variable。不要用数组透传参数，按契约分两种调用写。
- ⚠ 交接不能用 `exec`：进程被替换后 EXIT trap 不再执行，`$TMP` 会泄漏（`pipe-propagates-exit-and-cleans-temp` 会抓到）。
- ⚠ 交接必须 `</dev/null`：`curl | bash` 时父 bash 正从 stdin 读脚本，子进程继承 stdin 会吞掉剩余脚本。
- ⚠ `set -e` 下拿子进程退出码要写成 `rc=0; bash … || rc=$?; exit "$rc"`。
- ⚠ 第一个地址 404 时不要留下半截解压：建议先 `curl -fsSL -o "$TMP/src.tar.gz" <地址>`，成功后再 `tar -xzf … -C "$TMP/src" --strip-components=1`；两次失败的地址都记下来，用于 `[err]` 行。
- ⚠ 测试按 `[err]` 前缀找错误行（非 tty 时没有颜色码）：两个地址都要出现在 `log_err` 的输出里，不能只靠 curl 自己的报错。
- ⚠ 既有 `run_install` / `run_install_stubbed` 系列测试走本地模式，必须继续通过；不要动 `merge_settings` / `install_flight_plugin` / `copy_tree`。
- ⚠ README 新节内不要再出现 `## ` / `### ` 子标题（测试截到下一个二级或三级标题为止）；代码块里的 `# 注释` 不受影响。
- ⚠ 每条测试解锁时去掉 `@pytest.mark.xfail(strict=True, ...)` 那一行；不要改骨架的断言。
