## 做什么（`slice-gate.py`）

### 1. 计划工件与不计入 Δ 的路径（design D2）
- `PLAN_FILES = ("proposal.md", "design.md", "tasks.md", "slices.json", "spec.html", BASELINE, ".openspec.yaml") + BOOKKEEPING`，`PLAN_DIRS = ("specs/", "slices/")`。注意 BOOKKEEPING 里有 `slices/_interfaces.md`，它在 `slices/` 之下，本来就会被排除。
- `_plan_file(rel, change_rel)`：判断 rel 是不是本 change 的计划工件。
- `_ignored(rel)`：字节码（`is_bytecode`），或路径分段里有 `.pytest_cache`。

### 2. 快照（design D1、D6）
- `_snapshot(root, change_rel) -> dict`：
  - 用 `git status --porcelain -z --untracked-files=all` 解析出未提交路径。改名、复制项要两边都记：原路径记为 null，新路径照常；
  - 去掉 `_ignored` 与 `_plan_file`；
  - 现存文件用一次 `git hash-object --stdin-paths` 批量取 blob id；已删除的记 null。
- `_blobs_at(root, commit, paths) -> dict`：一次 `git ls-tree -r -z <commit> -- <paths…>`，路径很多时分批，每批 ≤ 500。commit 里没有的路径记 null。

### 3. 命令指纹（design D4）
- `cmd_key(root, change_rel, cmd) -> str | None`：
  - shlex 切词，抛错返回 None；
  - 每个词做归一：把 `change_rel` 换成 `<change>`；
  - 词指向仓库内已存在的文件时（相对 root，或在 root 之下的绝对路径），记 `[归一后的词, blob id]`；
  - 返回 `sha1(json.dumps([归一后的整条命令, 文件列表], ensure_ascii=False, sort_keys=True))`。

### 4. Δ（design D1、D2）
`_delta(root, cand, cur_snap, head, change_rel, same_change) -> list | None`：
- 候选 commit 不是 HEAD 的祖先 → 返回 None。可以复用 `_is_ancestor`（第 800 行）。
- 候选路径 = `git diff --name-only <cand.commit> HEAD` ∪ `cand.snapshot` 的键 ∪ `cur_snap` 的键。
- 去掉 `_ignored`、本 change 的 `_plan_file`。
- 去掉 `<changes 根>/**`（`changes 根 = dirname(change_rel)`）。例外：`same_change` 为真时，本 change 目录下非计划工件的文件保留。
- 逐个比旧值与新值：
  - 旧值 = `cand.snapshot` 有就取它，否则取 `_blobs_at(cand.commit)`；
  - 新值 = `cur_snap` 有就取它，否则取 `_blobs_at(HEAD)`；
  - 不同即进 Δ。返回排好序的列表。

### 5. 复用判定（design D3）
`_try_reuse(root, change_dir, data, cand, cur_snap, key) -> (dict | None, why)`，下面任一条不满足就返回 None：
- `cand.ok is True`；
- `cand.test.exit == 0`，或 `cand.test.failed` 是列表；
- `cand.cmd_key == key` 且 key 非空；
- Δ 不是 None；
- Δ 里每个路径的文件名都匹配 `test_*.py`；
- `cand.test.failed` 里没有哪条的 classname（`::` 之前）按 `.` 切开后含 Δ 中某个测试文件的主干（文件名去掉 `.py`）；
- Δ 里现存的文件交给 `_pytest_outcomes(root, files, data["gate"])` 补跑，不超时、没有 FAILED / ERROR、rc ∈ {0, 5}。Δ 为空、或没有现存文件时不补跑，sec 记 0。

通过时返回 `{"from": {"change", "commit", "at"}, "files": Δ, "sec": 补跑耗时}`。

### 6. `cmd_baseline` 改写（保留原有行为，按顺序）
1. 开跑**之前**：读旧基线 `old = load_baseline(change_dir)`（运行标记不算），取 `s0 = _snapshot(...)`、`key = cmd_key(...)`。
2. 照旧写运行标记。
3. 候选：没有 `--full` 时为 `[old]`，前提是 old 带 `snapshot`。候选的 change 取 `old.get("change")` 或本 change 目录名。S2 会在这里接上池。
4. 逐个 `_try_reuse`，命中 → `mode = "incremental"`：
   - `bl["test"]` = 候选的 `{exit, sec, failed?}`；
   - 不跑 `run_test_gate`；
   - 不改已有的 `full_suite_sec`，为 None 时写候选的 `test.sec`。
   未命中 → 原有全量路径，`mode = "full"`。
5. lint / typecheck 照原样跑。
6. verify：
   - 全量 → 全跑；
   - 增量 → 只重跑以下几类片：old 里没有该片、`cmd` 不同、命令路径覆盖到 Δ、或命令里认不出路径（design D7：切词，去掉 `::` 之后的部分，仓库内已存在的路径或等于 Δ 里的路径才算路径）。
   - 其余写 `{"exit": old 的 exit, "cmd": cmd, "reused": True}`；重跑的写 `{"exit", "cmd"}`。
7. 运行期间的改动（design D6）：取 `s1 = _snapshot(...)`，对比 s0 与 s1 不同的路径：
   - 开始时就存在（s0 有它，或 `_blobs_at(HEAD)` 非 null），或 `is_test_path` → `reasons` 加「基线运行期间 <路径> 被修改，重跑 baseline」；
   - 否则 `warnings` 加「基线运行期间新出现 <路径>（视为运行副产物）」。
8. `bl` 新增字段：`change`（目录名）、`mode`、`snapshot`（= s1）、`cmd_key`；增量时还有 `incremental`。stdout JSON 照原样带上这些。

### 7. `cmd_preflight`（design D8）
在原有四项校验通过之后、打印 waves 之前，下面几条都满足时做内容检查：
- 基线有 `snapshot`；
- 本 change 的账本里没有 `ev == "takeoff"`（`ledger.read_events`；抛错按没有处理）。

检查：以基线本身为候选，`_delta(..., same_change=True)`。Δ 为 None 或非空 → `die("基线过期：自基线以来有改动：<前 8 个路径>；重跑 baseline（只改了测试文件时走增量）")`。

### 8. argparse
`baseline` 子命令加 `--full`（store_true）；同步更新文件头注释的子命令说明。
